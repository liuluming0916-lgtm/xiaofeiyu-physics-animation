# 宿主 ⇄ 模板页 控制协议（§13.2 定稿 · 第 3 期）

> **状态：第 3 期定稿**（方案 §13.2 原文为"字段冻结，§22 待细化"；§22 第 11 条要求随第 3 期定稿）。
> 依据：`docs/history/物理解题动画软件v1.0自研方案.md` §13.1 / §13.2 / §13.3。
> 从端实现：`template/animation-template.html` 的 `bindHost()` / `postToHost()`。
> 宿主实现：`web/src/lib/host-protocol.ts`。
> **两侧的字段必须与本文件一致**；改协议要先改本文件（§21.1 第 1 条）。

---

## 0. 为什么需要协议（§13.1）

> **播放器就是模板页本身。** 宿主（前端）通过 `postMessage` 控制它；导出 = 保存正在播放的那个文件。
> **导出 = 另存为。屏幕上看到的 = 导出的，逐像素一致，天然保证。**

代价就是这套协议。因此协议的第一原则是：**宿主能做的控制，模板页内也必须能自己做**——
否则"导出另存"出来的文件会因为缺少宿主而失去那些能力。

## 2. ★ 第 3 期定稿：`source` 字段（原文未规定）

§13.2 草案**没有规定来源标识**，但从端实现里已经用了它，且需要一个可靠的方向判据
（否则模板页会响应自己发出去的消息，或响应页面上任意第三方 iframe 的消息）。

**本协议正式规定：**

```
宿主 → 模板：{ source: 'od-host',     type: '<消息名>', ...载荷 }
模板 → 宿主：{ source: 'od-template', type: '<消息名>', ...载荷 }
```

**接收方规则（两侧对称）：**

| 收到的情况 | 怎么处理 |
|---|---|
| `data.source === 'od-host'`（模板侧）/ `'od-template'`（宿主侧） | **接受** |
| `data.source` 存在但**不是**上述期望值 | **忽略**（不是发给我的） |
| `data.source` **不存在** | **接受**（向后兼容 §13.2 草案；草案里没有这个字段） |

> 这条"缺省即接受"是**刻意的**：协议升级期间，老宿主/老模板不应因为多了或少了一个字段就失效。
> 但**新写的代码一律带 `source`**。

## 3. ★ 第 3 期定稿：`program` 注入与两条装载路径

模板页有两种装载方式，**都必须支持**：

| 路径 | 何时用 | `PROGRAM_DATA` 从哪来 |
|---|---|---|
| **A. 构建期内联**（主路径） | 导出的单文件成品页、`template/build/*.html` | 构架时由 `template/build-template.mjs` 写进 HTML |
| **B. 宿主运行时注入** | 宿主 iframe 装载**空壳模板**（`template/animation-template.html`） | 宿主发一条 `program` 消息 |

**为什么两条都要**：

- **A 是导出保真的根基**（§13.1）：单文件、离线、双击即播、逐像素等于屏幕上看到的；
- **B 是开发与动态生成的必需**：用户刚生成的一道题还没有对应的构建产物，
  但要求立刻能在动画页里看到（否则"出可播放动画"要等一次构建）。

**`program` 消息（宿主 → 模板）：**

```jsonc
{
  "source": "od-host",
  "type": "program",
  "slots": { "PROBLEM": "…", "STEPS": "…", "ANSWERS": "…", "VIEW": "…",
             "setup": "…", "stateAt": "…", "drawFrame": "…", "readouts": "…" },
  "mode": "NUMERIC",          // 或 "SYMBOLIC"
  "texSvg": { "renderer": "…", "formulas": { "tex": "<svg…>" } }   // 可选
}
```

**模板侧处理规则（已实现）：**

1. **若 `PROGRAM_DATA.slots` 已经内联存在（路径 A）→ 忽略 `program` 消息**，
   并回一条 `error`（`code: 'program-already-inlined'`）说明原因。
   理由：**内联的那份才是"屏幕上看到的 = 导出的"那份**，运行期覆盖会让导出内容与显示内容不一致。
2. 若为空壳（路径 B）→ 写入 `PROGRAM_DATA`，**重新推导 `texSvg` 索引**，然后 `boot()`。
3. `slots` 必须**恰好含 §3.2 的 8 个键名**；不合法时回 `error`（`code: 'bad-program'`），不改动现场。

## 4. 时序（宿主应当遵守）

```
宿主创建 iframe（src = 空壳模板 或 成品页）
        │
        ├─ 等模板发来 ready            ← 模板 boot() 完成、播放器就绪
        │     { duration, stepCount }
        │
        ├─（路径 B）发 program          ← 注入 8 槽位
        │     模板会再发一次 ready
        │
        ├─ 发 setVectorMask / setRate   ← 恢复宿主侧记住的开关状态（可选）
        │
        ├─ 之后随时发 play/pause/seek/showStep
        │
        └─ 每 250ms 收 state            ← 宿主据此更新自己的进度条与读数面板
```

**关键点**：`ready` 之前发的控制消息**不保证生效**（播放器还没建）。
宿主应当**先等 `ready`**，或在 `ready` 到达后重发一次关键控制（推荐前者）。

## 5. 与 §13.3 的关系（控制项全部必做）

§13.3 要求的控制项，**模板页内都必须能独立完成**（因为导出后会脱离宿主）：

- 播放/暂停/重置 · 倍速（≥0.25/0.5/1/1.5/2/4）· 时间轴拖拽 · 逐帧前后 · 关键时刻跳转；
- 矢量三类独立开关 + 轨迹 + 网格；
- 步骤联动（点解析第 N 步 → 画布跳到该步 `t0`）；
- 开关状态**在动画页内持久化**（`localStorage`）。

宿主协议是这些能力的**远程版本**，不是替代品。

## 6. 错误码（模板 → 宿主的 `error`）

| code | 含义 | 宿主应当做什么 |
|---|---|---|
| `runtime-missing` | `window.ODRuntime` 未定义（构建链损坏） | 提示重新构建；这是构建期缺陷 |
| `no-program` | 空壳模板且宿主未注入 `program` | 提示用户先生成动画 |
| `program-already-inlined` | 已内联却又收到 `program` | 忽略即可（协议规定不改动现场） |
| `bad-program` | `slots` 不满足 8 键名 | 说明是内部缺陷；提示重新生成 |
| `load-failed` | 装配失败（语法错误等） | 展示 `message`（含槽位与行号） |

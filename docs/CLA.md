# 贡献许可协议（CLA）

> **为什么需要**：本项目按 AGPL-3.0 开源，同时保留商业授权。
> 如果外部贡献的代码只按 AGPL 授权，维护者就**没有权利**向外发放商业许可——两条路会当场断掉。
> 所以贡献者需要额外给一项"可重许可"的授权。

---

## 一、谁要签

| 情况 | 要签吗 |
|---|---|
| 提 PR 改代码、改提示词、改示例 | **要** |
| 只提 issue、只报 bug | 不要 |
| 只改错别字、只调文档标点 | 不要（视为已同意，见 §五） |
| 受雇期间写的代码，且雇主拥有著作权 | **要**，且需雇主出具同意 |

## 二、你授予什么

你就自己贡献的内容，向本项目维护者授予：

1. **著作权许可**：永久、全球、非独占、免费、不可撤销的许可，
   允许复制、修改、改编、公开传播、分发，以及**再许可**（包括按商业授权条款再许可）。
2. **专利许可**：永久、全球、非独占、免费、不可撤销的许可，
   允许制造、使用、销售、许诺销售、进口你的贡献所必然涉及的专利权利要求。
   若你对本项目提起专利诉讼，此项许可自起诉之日终止。
3. **再许可权**：允许维护者在 AGPL-3.0 之外，以**其他条款**（含商业授权）分发包含你贡献的版本。
   这是双轨许可能够成立的前提，也是本协议唯一"多要"的东西。

## 三、你保留什么

- **著作权仍归你**，本协议是许可，不是转让。
- 你可以在自己的项目里继续用这份贡献，不受限制。
- **署名权保留**：项目会在提交历史与贡献者列表中保留你的名字。

## 四、你保证什么

提交贡献即表示你确认：

1. 内容是你**原创**，或你有权按本协议授权；
2. 不含你没有权利授权的第三方代码、图片、题库、教辅素材；
3. 如果你在受雇期间创作，已取得雇主同意；
4. 你知道这份贡献会以 AGPL-3.0 与商业授权两种方式对外分发。

> 第 2 条不是客套：本项目明确**不收录**第三方教辅的题目与解析。
> 带进来的素材，会让整个仓库的许可失效。

## 五、怎么签（两种都算）

**方式 A（推荐，轻量）**：首次提 PR 时，在 PR 描述里加一行：

```text
I have read docs/CLA.md and agree to it.
（我已阅读 docs/CLA.md 并同意。）
```

**方式 B（重）**：签署独立文件，由维护者提供模板。适合公司贡献或有人事变动的情形。

只改文档标点、错别字这类，视为已同意，不单独要求。

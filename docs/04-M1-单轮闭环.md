## 1. 一次运行长什么样

```
第 1 步：请求模型…
        ↓ write_animation（完整 HTML）
第 2 步：run_checks → 沙盒快进 5 帧 + 90 个采样点 → 报错清单
        ↓ 有错？write_animation 改 → run_checks 再验
第 3 步：look_at([0, 1.3, 2.6, 4.0]) → 4 张真实截图直接进对话
        ↓ 模型看图，觉得不行就再改
第 4 步：finish(申报 3 个关键数值) → 程序重新采样核对
        ↓ 对不上就拒绝交付，让它继续改
交付 animation.html
```

工具只有 4 个：`write_animation` / `run_checks` / `look_at` / `finish`。

## 3. 自动质检真的在干活

斜面那题的第一版被拦下，报错原文：

```
1. [错误] 播放 1.00s：文字重叠 66%——「s = 0.37 m」与「mg = 9.8 N」
   → 把其中一个标签移到空处，或缩短/错开显示。
2. [错误] 播放 2.00s：文字重叠 56%——「s = 1.50 m」与「mg = 9.8 N」
```

模型下一版就把重力标签挪到箭头末端，一轮通过。

平抛那题的四版里有三版是**它自己看截图后主动改的**（球没贴地、速度标签贴到标题、加速度标签压到支柱）——
这正是"截图回传"想要的效果：不是程序告诉它错，是它自己看见不对。

## 4. 这轮抓到的两个"规格漏洞"

第一版斜面动画**没有播放控制条**（我漏写在提示词里了），也**没画加速度箭头**。
两条都已补进系统提示：

- 画布内 56px 控制条：播放/暂停、可拖时间轴、0.5×/1×/2×、重播；主体只占 `y ∈ [0, 660]`
- 有加速度就必须画紫色 a 箭头，并与速度箭头沿法向错开

平抛那题验证了修补有效：控制条、a 箭头、答案卡片都出现了。

## 5. 成本结构（要紧）

**输入 tokens 是大头**（40–46 万），因为每轮都要把之前的对话和截图重新发一遍。
按几毛钱一题的预算还能接受，但如果要压成本，抓手是：

- 每轮少发几张图（现在每次 `look_at` 发 4 张，可以减到 3 张）
- 截图缩到 0.4 倍（现在是 0.5 倍 640×360 的 2 倍 → 1280×720）
- 减少无谓的 `run_checks`（模型有时连续调用两次）

## 6. 已知不足

- 只支持单幕。多小问的"第二幕"还没做（数据结构里已经留了 `acts`）。
- 不接受图片题目输入（模型能看图，但入口还没接）。
- 3 轮上限、10 分钟超时、取消按钮、手动打回——后端逻辑有雏形，还没有界面。
- 没有界面，现在是命令行。

# 改知识卡与导入导出

> **状态：v1.1.15-dev（基于 v1.1.12）。** 旧版设置页的 v1 知识卡界面已删除；
> 现在只有**知识卡**：触发只来自词表，不再有 `keys` / 考点 / 题型 / 次级键 / 解题槽。
> 数据写在 `%APPDATA%\physics-animation-studio\data\ai-rules\`；写前自动备份。

---

## 一、三类卡

| 类型 | 触发方式 | 它管什么 |
|---|---|---|
| **动画规范卡** | 常驻（`constant`） | 坐标/单位/颜色/读数、阶段表、30 个元件总览 |
| **元件卡** | 模型判出 `elements` 里的元件 | "这个元件怎么画、最容易错在哪" |
| **场景卡** | 模型判出 `scenes` 里的场景（最多 1 个） | "这类题怎么摆、什么顺序、什么关系" |

> 提示词卡与本地规则卡不是 `knowledgecard` 条目：前者在「提示词卡」里改，后者在「本地规则卡」里改。

---

## 二、触发：只看词表

一张卡要被注入，必须满足：

1. 卡是**启用**状态；
2. 类型对：
   - 元件卡：`elements` 至少 1 个词表元件；
   - 场景卡：`scenes` 恰好 1 个场景；
   - 动画规范卡：常驻，不需要触发；
3. 模型在 `read_problem` 的 `【动画元件】` / `【场景】` 里判出了对应 id；
4. 这个词条**没有被本地开关关闭**；
5. 没有被 30,000 字正文预算挤掉。

**不再有 `keys` 字面触发。** 以前"题面出现'传送带'就上卡"的写法已经退役；现在必须先在词表里有 `belt`，模型判出 `belt`，元件卡才会进。

---

## 三、词表：内置 + 用户新增 + 本地开关

### 内置

- 30 个元件：物块、斜面、传送带、弹簧、滑轮、电路、透镜……
- 3 个种子场景：`conveyor_block` / `incline_block` / `circular_track`（占位，按真题再调整）。
- 内置词条**只读**；不能删、不能改 id。

### 用户新增

在「知识卡」编辑卡片下面的「词表与开关」里点「新增词表项」：

- **元件**：必须填一个现有画法（`Draw.box` / `Draw.circle` / `Draw.incline` / `Draw.polygon` …）；
  不新增 SDK 函数，不能发明程序不会画的形状。
- **场景**：不绑定画法；一道题最多 1 个场景。

### 本地开关（按章节关）

「词表与开关」里每个词条右侧有一个启用/关闭勾选框（逐个点即可）：

- **关闭 = 只从 Prompt 和触发里拿掉，不删词条**；
- 适合"这周讲牛顿定律，先把电磁组合场关掉"；
- 关闭状态存在 `ai-rules/vocab.json` 的 `disabled.elements / disabled.scenes`，升级不丢；
- 卡片列表会给引用到关闭词条的卡标「触发关闭」。

> 不设数量上限；但词表越大，`read_problem` 每次带的名字越多、token 越多。开关就是为这个准备的。

## 四、编辑 / 保存 / 恢复

1. **编辑**：设置 → 知识卡 → 左侧选卡 → 中间改标题/触发/正文/示例。
2. **保存到本机**：
   - 内置卡保存 = 生成一条**同 id 的用户覆盖副本**，内置原件不动；
   - 用户卡保存 = 覆盖自己的 `<id>.json`；
   - 写前完整校验；不合法整张不写。
3. **新建卡**：顶部「新建卡」→ 选类型 → 选触发 → 建完编辑 → 保存。
4. **删除**：
   - 用户卡可删（删前备份）；
   - 内置卡不能删，只能停用或保存成覆盖副本。
5. **实时试触发**：编辑卡片下面可以勾选“模型可能判出的元件/场景”，立刻看当前库（含正在编辑的这张）会命中谁、正文多少字；不调模型、不改磁盘。
6. **恢复本版内置**：只撤销内置卡的覆盖副本，**不删你自己新建的卡**；恢复前备份。
7. **生效**：下一次跑题生效；已经生成的动画不会自己变。

---

## 五、导出 / 导入

- **导出知识卡包**：用户卡 + 用户新增词表一起打包；内置卡/内置词表不导出（随程序走）。
- **导入知识卡包**：先合并包里的用户词表，再逐卡校验；任何一张不合法就**整包拒绝**，不写半包。
- **本地开关不导出**：它是这台机器当前讲哪一章的状态，不是卡片内容。
- 旧 v1 包：v2 库载入时会尝试迁移有 `elements` 的卡；只有 `keys` 的卡会停用并报告。
  当前 v2 页面没有"导入 v1 包"按钮；旧包要走迁移层（把文件放回 `ai-rules/knowledgecard/` 后重启）。
- **安全**：`code_examples` 会在画布沙箱里跑；不要导入来路不明的包。

---

## 六、一张合格的卡

1. **一张卡一个元件/一个场景**；
2. 写"应该怎么画/怎么摆"，不要只写"绝对不许"；
3. 正文必须有「生成后自检」小节；
4. 元件卡示例要能通过 C1 静态检查；
5. 示例里的数字尽量来自 `state` / `setup`，不要写与题无关的死数；
6. 场景卡不要重复元件卡的 API，只写装配关系/顺序。

---

## 七、为什么没触发？按顺序查

1. 卡是否**启用**？
2. 卡是否**保存**？（新建后显示"未保存"就不生效）
3. 类型/触发是否填了？（元件卡至少 1 个元件；场景卡恰好 1 个场景）
4. 词条是否被**本地开关关闭**？（列表有「触发关闭」）
5. 模型这次有没有判出那个元件/场景？（看解题结果「知识卡依据」/`judgement_done`）
6. 是否被 30,000 字正文预算挤掉？（看「被截断」告警）
7. 是否是旧 v1 卡、只有 `keys`？（会停用并报告，需要重建为 v2 卡）

> 知识卡是上下文，不是判据。卡坏了改卡，不放宽 C1–C9。

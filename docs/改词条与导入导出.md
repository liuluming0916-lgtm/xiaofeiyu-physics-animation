# 改词条与导入导出

> **状态**：v1.1.2 起开放。v1.1.2 之前词条是编译进程序的，界面里看不到也改不了。

---

## 一、两种词条：改哪个有用

| 词条 | 进哪个槽位 | 它管什么 |
|---|---|---|
| **元件卡** | 动画代码 | "这个元件怎么画"。一卡一件（画布 / 传送带 / 箭头 / 标注 …） |
| **物理规范** | 动画代码 | "这类题必须守住什么"。比如"下滑块的加速度要沿斜面分解" |

**改哪里最有效**：动画不好看、动得不对 → 先看**元件卡**。
一卡一件的意思很硬：一张卡里塞两个元件，模型会混着用。

---

## 二、一张合格的卡长什么样

必须有三样东西：

1. **这是什么时候用**（触发词 + 一句场景描述）；
2. **规范怎么写**（要点式，别写散文）；
3. **生成后自检**小节 —— 让模型写完自己核一遍。

并且要给一段 **`code_examples`**：一段**能通过静态检查**的代码。
它不是装饰：门禁会把每段示例真跑一遍检查，**示例坏了会红**。
（"照抄我们的示例会被我们自己的检查打回"这种情况，比没有示例更糟。）

---

## 三、编辑 → 验证 → 生效

> 下面这些动作在软件的设置页里做，也可以直接改 `ai-rules/worldbook/` 下的 JSON。

1. **改/建**：一条词条一个 id。同 id 的**用户层词条会覆盖内置词条**，删掉覆盖副本就恢复内置。
2. **体检**：保存前会自动校验——
   - 元件 id 必须在官方清单里（写 `arroww` 这种表外 id 会当场报出来）；
   - 必须带「生成后自检」小节；
   - `code_examples` 必须通过静态检查（不许调用未登记的函数）。
3. **试触发**：设置页有**实时预览器**——贴一段题面，它告诉你会命中哪几张卡、进了哪个槽。
   这是调卡片最快的手段：不用真跑一遍模型。
4. **生效**：下一次生成就带上。已经生成好的动画不会自己变。

---

## 四、导出 / 导入（JSON）

- **导出**：把当前世界书导成一份 `.json`（格式标识 `od-worldbook` v1）。
  可以只导用户层，也可以连同内置一起，方便整套迁移到另一台电脑。
- **导入**：整批校验，**要么全进、要么全不进**（拒绝"进了一半"的状态）。
  导入前会自动备份你现有的词条。
- **幂等**：导出 → 导入 → 再导出，两次结果**逐字节一致**（门禁钉着这条）。

⚠ 导入别人的词条包之前，先看一眼 `code_examples`——那里面是可执行代码，
虽然只能在画布沙箱里跑，但**别导入来路不明的包**。

---

## 五、出问题怎么回退

| 症状 | 做法 |
|---|---|
| 改了词条之后效果变差 | 删掉 `ai-rules/worldbook/` 里对应的覆盖文件，立刻回到内置版本 |
| 不知道哪条卡生效了 | 看解题结果的「世界书依据」面板，或设置页的试触发预览 |
| 想全部复位 | 设置页「恢复默认」（会先备份） |

---

## 六、写卡的三条经验（血泪）

1. **不要写"绝对不许"清单**。只写禁令的卡，模型会绕开禁令但丢掉画法。
   把"应该怎么画"写清楚，比列十条"不许"有效。
2. **数值不要靠文字描述**。画布不写数值、矢量靠**颜色与长度**表达——卡里也别写"高度约为 3 米"。
3. **一张卡一个元件**。真要组合（比如"斜面上的块"），就在**斜面卡**里写下"块要跟着转"，
   而不是新开一张组合卡——否则两张卡会同时命中、互相打架。

# 打包文档：源码进 `app.asar`，知识卡仍可改

> **适用版本**：v1.1.12 起；**v1.1.17 沿用同一形态**（`resources/app.asar` + `app.asar.unpacked/`）。
> **一句话**：发布包不再把 `core/`、`tools/`、`sdk/` 这些源码目录散放在 `resources/app/` 里，
> 而是封装成一个 `resources/app.asar`；同时，**用户知识卡仍然写在 `%APPDATA%` 下、随时可改**。
>
> 本文回答三件事：为什么改、怎么打、改完之后用户还能不能改卡。

---

## 一、问题：上一版的源码是"明摆着"的

v1.1.11 及以前的绿色版，目录长这样（用户截图里也是这个形态）：

```
物理解题动画-v1.1.11/
  物理解题动画.exe
  resources/
    app/                  ← ⚠ 我们的源码，一个文件都不少
      core/               ← 编排、知识卡、Dry-Run、导出……全是 .mjs 明文
      tools/              ← 本机服务、构建脚本
      sdk/                ← 动画运行时
      contracts/          ← 契约与词表
      web/dist/           ← 前端产物
      node_modules/
    default_app.asar
```

只要用户在资源管理器里点进 `resources\app\`，就能直接看到并复制全部服务端代码；
甚至能改一行 `.mjs` 让软件按他的意思跑（改完还"看起来是同一版"）。

**这不是"用户太厉害"，是我们把源码放错了地方。**
Electron 的标准做法是把应用代码封装成 **ASAR 归档**（`resources/app.asar`），
运行时由 Electron 把它当只读虚拟目录挂载，`require` / `fs` 照常工作，但用户看不到散开的文件。

> `package.json` 里其实一直写着 `"asar": true`，但真正发版用的是
> `tools/electron-pack.mjs` / `tools/electron-repack.mjs` 的"手工组装绿色版"路线，
> 这条路线当时只做了 `resources/app/` 目录复制 —— 配置没生效，也没人核对产物形态。
> **教训**：产物形态这种关键属性，必须由打包脚本自己断言，并在发版清单里点名检查。

## 二、v1.1.12 起的产物形态（v1.1.15 同）

```
release/物理解题动画-v1.1.12/
  物理解题动画.exe                     ← electron.exe 改名
  启动并诊断.bat
  开源日志/                            ← 用户可打包发回的运行日志
  resources/
    app.asar                           ← ✅ 全部应用代码（单文件）
    app.asar.unpacked/                 ← ✅ 只放原生模块（*.node）
      node_modules/better-sqlite3/prebuilds/*.node
    default_app.asar                   ← Electron 自带，未改动
  locales/  *.pak  *.dll  icudtl.dat …  ← Electron 运行时，未改动
```

**没有 `resources/app/` 目录。** 打包脚本会在封装前主动删掉它，并在校验阶段断言"它不存在"——
两种形态同时存在时 Electron 会优先加载 `app.asar`，留着旧目录只会造成"看到的和跑的不是同一份"。

### 2.1 `app.asar` 里装了什么

| 目录 | 内容 | 说明 |
|---|---|---|
| `electron/` | `main.cjs` / `preload.cjs` | 主进程与预加载 |
| `core/` | 编排、知识卡引擎、Dry-Run、导出、清洗…… | 运行期全部逻辑 |
| `sdk/` | 动画运行时 | Worker 与浏览器播放器共用 |
| `contracts/` | 契约、词表、冻结字段 | 引擎与前端共用 |
| `tools/` | `rules-service.mjs` 等运行期工具 | **不含** `_` 开头的开发期取证脚本，也不含打包工具自己 |
| `web/dist/` | 发布形态前端（无规则页/蒸馏页） | 由 `OD_RELEASE=1` 构建 |
| `template/build/` | 成品页与 iframe 壳 | 导出/预览用 |
| `node_modules/` | 10 个运行期依赖 | 公式渲染 / SQLite / AST |
| `package.json` | 裁剪版 | 只留 `name/version/type/main/description`，不带 `build` 配方 |

`core/knowledgecard/source/`（写卡源文件）**不进包**；发行版的内置卡读的是编译进代码的
`builtin-bundle.generated.mjs`，`source/` 只服务于开发流程。

### 2.2 为什么 `app.asar.unpacked/` 只放 `.node`

Electron 的 `process.dlopen()` 不能从 asar 里加载原生模块（底层要一个**真实路径**）。
`better-sqlite3` 的 `prebuilds/*.node` 必须解包到 `app.asar.unpacked/`，
asar 头里对应的条目会标 `unpacked: true`，Electron 读取时自动改道。
其余文件（包括 `better-sqlite3` 的 JS）都在 asar 里，不需要解包。

> 校验脚本会断言：解包目录里**只允许** `.node`，并且 `win32-x64.node` 必须存在。
> 一旦有人图省事把整个 `node_modules` 解包，这条会红。

## 三、ASAR 到底能挡什么、不能挡什么

**必须先把预期说清楚**，否则"源码不泄露"会变成一句空话。

| 能挡住 | 挡不住 |
|---|---|
| 普通用户/老师在资源管理器里翻看、复制、误改源码 | 用 `asar extract` 之类工具**专门**解包的人 |
| "点进文件夹就看到 `.mjs`"这种零成本泄露 | 逆向、内存抓取、动态调试 |
| 用户直接改程序文件导致"版本对不上"的售后问题 | 前端代码（`app.js` 是编译产物，但仍是可读 JS） |
| 程序目录被当成"可写目录"的坏习惯 | 任何真正敏感的数据（**模型 Key 从来不进包**） |

ASAR 是**打包格式，不是加密**。它把源码从"明摆着"变成"要费点事"，
这符合"防随手翻看 + 防误改"的目标，但**不能当作商业秘密保护**。
真正需要保密的东西（端点 Key）只存在用户数据目录的 `ai-rules/keys.json`，打包时不会带上。

另外，v1.1.12 起发布形态**关闭 DevTools**（`devTools: !app.isPackaged`）：
用户按 F12 看不到内部 DOM / API / 状态。排查问题走「启动并诊断.bat」和 `%TEMP%\od-shell.log`；
开发运行（`app:start`）仍然可以 F12。

## 四、怎么打（命令与顺序）

### 4.1 两条路线，产物形态一致

| 路线 | 命令 | 运行时来源 | 适用 |
|---|---|---|---|
| **离线重打包**（常用） | `node tools/electron-repack.mjs --zip` | `release/` 里现成的绿色版目录（带 exe + `resources/app` 或 `app.asar`） | 本机已有旧版发布物，npm 不可达 |
| 从官方 zip 起 | `node tools/electron-pack.mjs --zip` | `.cache-electron/electron-v35.7.5-win32-x64.zip`（`OD_ELECTRON_VERSION` 可覆盖） | 干净环境，第一次组装 |

两者都走同一份载荷清单与封装逻辑（`tools/pack-payload.mjs`），不会各打各的。

### 4.2 完整发布顺序

```bat
:: 0) v1.1.17 起：v2 卡（data-v2/）是手写源，不需要生成器。
::    只有改了 contracts/spec/ 或词表时才重新生成契约：
node contracts\generate-contracts.mjs

:: 1) 总门禁（会把 web/dist 重建成开发形态，这是正常的）
node tools\verify-all.mjs

:: 2) 打包（内部会 OD_RELEASE=1 重建前端与模板，再把载荷封装成 app.asar）
node tools\electron-repack.mjs --zip
```

`npm run app:pack` 等价于第 2 步；`npm run app:green` 等价于 `electron-pack --zip`。

### 4.3 打包脚本内部做了什么

`tools/electron-repack.mjs` 的顺序（**不能换**）：

1. **发布形态前端**：`OD_RELEASE=1 node tools/web-build.mjs`
   —— 规则页 / 蒸馏页在编译期被摇掉，产物里根本没有；设置页保留。
2. **模板页重建**：`node template/build-template.mjs`。
3. **硬校验 dist**：`assertReleaseBundle()` 检查 `web/dist/assets/app.js` 里
   不得出现 `RulesPage` / `DistillPage`；出现就拒绝打包（与门禁 ㊳ 同一口径）。
4. **复制运行时**：`robocopy` 把旧版目录整体复制成 `release/物理解题动画-v<版本>/`
   （不用 `fs.cpSync`：实测复制 ~180 MB 运行时树会让 Node 崩）。
5. **重建载荷**：`buildPayload()` 从仓库复制 `electron/core/sdk/contracts/tools`、
   `template` 的几样、`web/dist`、运行期 `node_modules`，写一份裁剪版 `package.json`。
6. **封装 asar**：`packPayloadAsar()` 先删 `resources/app`、旧 `app.asar`、旧 `.unpacked`，
   再用 `tools/asar-archive.mjs` 写 `app.asar`，`.node` 进 `app.asar.unpacked`。
7. **产物校验**：`verifyPackagedAsar()` 逐项点名（必须文件、版本、无 `.map`、
   无写卡源、无 `_` 开发探针、解包目录只含 `.node`、`resources/app` 不存在）。
8. **真 exe 自检**：`物理解题动画.exe` 带 `OD_SELFTEST=1` 跑一遍
   （服务 / 首页 / 账本 / **Worker 沙箱** / 载荷形态），退出码非 0 就不压缩。
   自检结果会写到 `OD_SELFTEST_OUT` 指定的文件（打包脚本指到程序目录），
   因为 Windows 上 GUI 进程的 stdout 抓不到；这个文件在压缩前会被删掉，不会进包。
   **必须真的读到这个文件**：读不到就是"exe 没启动"，不能算通过（v1.1.17 首包踩过假绿）。
   同时必须清掉子进程的 `ELECTRON_RUN_AS_NODE`（否则 Electron 按 Node 跑、无参数直接 exit 0）。
   自检的布尔项也是判据：`worker=true` / `index=true` / `payload=app.asar`。
   `--no-sandbox` 与 `OD_USER_DATA_DIR` / `OD_DOCUMENTS_DIR` / `OD_CRASH_DIR` /
   `OD_DISABLE_CRASH_REPORTER=1` 只用于受限环境下的冒烟（把可写路径指到程序目录、
   并跳过会在沙箱里启动子进程的 crashpad）；生产运行不设这些变量。
9. **建「开源日志」目录**、放隐藏占位文件（否则 zip 会丢空目录）。
10. **zip**（加 `--zip` 时）。

> ⚠ **Electron 33 的 Node-API 是 9**，而 `better-sqlite3 13` 的预编译产物要求 **10**。
> 直接 `require` 会在原生层 0xC0000005（不是 JS 异常，catch 不住）。
> `core/history/index.mjs` 因此在 require 前检查 `process.versions.napi`，<10 就不加载，
> 账本/审计降级但应用、解题、导出正常。要恢复账本：升级 Electron 35+ 或换 N-API 9 产物。

### 4.4 为什么自己写 asar 写入器

`tools/asar-archive.mjs` 是 200 行左右的极简实现，格式与 `@electron/asar` 3.4.1 逐字节一致
（用官方 `default_app.asar` 反读并核对过 SHA-256）。原因很实际：
发布环境离线，`node_modules` 里没有 `@electron/asar`，npm 也不保证可达；
而我们要的只是"目录树 → app.asar"，引一棵 `glob/minimatch/commander` 依赖树反而多一个失败点。

它同时提供 `list` / `extract` 子命令，用于发版体检与排障：

```bat
node tools\asar-archive.mjs list release\物理解题动画-v1.1.12\resources\app.asar
node tools\asar-archive.mjs extract release\物理解题动画-v1.1.12\resources\app.asar .tmp\asar-check
```

## 五、发版验收清单（每次都要看）

```bat
:: 1) 产物形态一次校验（版本 / 缺件 / 泄漏 / 解包 / 「没有 resources/app」）
node tools\pack-payload.mjs verify release\物理解题动画-v1.1.12\resources
:: 期望：三行 ✓（app.asar 3364 个文件 / 没有 resources/app / 解包只含 .node），exit 0

:: 2) 想亲眼看看 asar 里有什么（可选）
node tools\asar-archive.mjs list release\物理解题动画-v1.1.12\resources\app.asar | findstr /C:"electron/main.cjs" /C:"web/dist/index.html" /C:"builtin-bundle.generated.mjs" /C:"better-sqlite3"

:: 3) 真 exe 自检（不开窗口；结果落到 OD_SELFTEST_OUT）
set OD_SELFTEST=1
set OD_SELFTEST_OUT=%TEMP%\od-selftest.txt
release\物理解题动画-v1.1.12\物理解题动画.exe
type %TEMP%\od-selftest.txt
:: 期望：payload=app.asar · worker=true · history=true · index=true，且 exit 0
```

另外确认：

- 设置页仍是四个分区（知识卡 v2 / 提示词卡 / 本地规则卡 / AI 帮写占位），能保存、能恢复内置；
- 帮助菜单里有「知识卡目录（可直接改 JSON）」；
- `开源日志/` 在 exe 旁边，跑一题会落 `.html` + `.json`；
- 发布包体积与上一版同量级（asar 不压缩，体积不会明显变小，**不要**拿体积当"有没有打进去"的判据）。

## 六、用户还能不能改知识卡？——能，而且更清楚了

这是本次改动最容易被误解的一点：**源码封进 asar ≠ 知识卡被封死**。
两者走的是完全不同的路径：

| | 内置知识卡 | 用户知识卡 |
|---|---|---|
| 存放位置 | `core/knowledgecard/data-v2/*.json`（v2 运行时直接读；`builtin-bundle` 仍打 v1 数据，仅供 v1 引擎/对照） | `%APPDATA%\physics-animation-studio\data\ai-rules\knowledgecard\` |
| 在不在 asar 里 | 在（只读，用户改不到原文件） | **不在**（用户数据目录，可读可写） |
| 升级时 | 随版本更新 | **绝不覆盖、绝不删除** |
| 用户怎么改 | 编辑后自动生成"同 id 的覆盖副本" | 直接改 / 设置页改 / 导入导出包 |
| 怎么还原 | 设置页「恢复 X 内置」只撤销覆盖，不删自建卡 | 自己删文件或改回 |

### 6.1 三条改卡路径

1. **设置页（推荐）**：知识卡列表 → 选中 → 编辑 → 「保存到本机」。
   内置卡是只读的，编辑它会生成一条同 id 的**覆盖副本**；「恢复内置」只删覆盖副本。
2. **直接改 JSON**：帮助菜单 →「**知识卡目录（可直接改 JSON）**」，打开
   `%APPDATA%\physics-animation-studio\data\ai-rules\knowledgecard\`。
   每个 `.json` 是一张 v2 卡或旧 v1 包（v2 库载入时会迁移有 `elements` 的卡；格式见 [改知识卡与导入导出](改词条与导入导出.md)）。
   改完在设置页点「重新读取」，或重启软件。
3. **导入/导出包**：设置页「知识卡 v2」的导入/导出可以整包校验后落盘；导出的包会带上用户新增词表，方便同事之间传卡。

### 6.2 为什么用户层必须留在 asar 之外

- **asar 是只读的**：把用户卡写进 asar，第一次保存就会失败；
- **升级会换掉整个 `resources/`**：用户卡若在程序目录，升级即丢；
- **`Program Files` 只读**：安装到受保护目录时，写程序目录会静默失败。

所以 v1.1.12 继续沿用 v1.1.9 以来的口径：
**内置层封死（只封发行产物，不封开发源码），用户层永远落盘到 AppData。**
打包时 `electron/main.cjs` 设置 `OD_BUILTIN_BUNDLE=1`，内置卡读编译常量；
`rules-service.mjs` 的 `root` 指向 `%APPDATA%\...\data\ai-rules`，所有保存动作都写那里。

### 6.3 用户能不能改"内置卡原文"

不能直接改 asar 里的原文，但**效果等价**：编辑内置卡会生成同 id 的覆盖副本，
命中时用户副本优先；「恢复内置」再撤销。这是 v1.1.9 就定下的治理口径，
也是"升级不丢用户改动"和"内置可回退"能同时成立的原因。

## 七、版本号与发版改动面

页面上的版本号由构建期从 `package.json` 注入（`__OD_APP_VERSION__`），
关于框也改成 `require('../package.json')`，所以**手改的地方比上一版少了一处**。

发版时要同步：

| 文件 | 改什么 |
|---|---|
| `package.json` | `version` / `description` / `build.copyright` |
| `package-lock.json` | 顶层与 `packages[""]` 的 `version` |
| `electron/preload.cjs` | `version`（预加载在 sandbox 里，读不到 package.json，只能手写） |
| `web/index.html` | `<title>` 里的版本号 |

`electron/main.cjs` 的关于框不再手写版本；发布目录名与 zip 名都由脚本按 `package.json` 生成。

## 八、常见问题与坑

**Q：为什么发布包里没有 `resources/app`，但软件还能跑？**
A：Electron 会把 `resources/app.asar` 当应用根目录挂载；`__dirname` 变成
`...\resources\app.asar\electron`，`fs` / `require` 都透明。`main.cjs` 里的 `APP_ROOT`
就是 `...\resources\app.asar`。

**Q：`better-sqlite3` 报 `was compiled against a different Node.js version` / 找不到 `.node`？**
A：先看 `app.asar.unpacked\node_modules\better-sqlite3\prebuilds\win32-x64.node` 在不在。
`.node` 必须在 asar 外；在 asar 里会被 Electron 临时解包（慢，且可能被杀软拦）。

**Q：ESM（`.mjs`）能从 asar 里 `import` 吗？**
A：能（Electron 28+ 支持 ESM from ASAR；本项目用 Electron 33）。
打包脚本的 `--selftest` 会真的 `import()` 服务层并起 Worker；
如果哪天升级 Electron 把这条路弄坏了，自检会直接红，而不是等用户双击才发现。

**Q：Worker 沙箱起不来会怎样？**
A：`core/dryrun/dry-run.mjs` 会回退到主线程 `node:vm`（功能还在，但死循环抢不回 CPU）。
所以自检把 `Worker 可用` 当硬指标：为 false 就不许发版。

**Q：用户装到 `Program Files`，还能改卡吗？**
A：能。用户卡、账本、观测都在 `%APPDATA%\physics-animation-studio\data\`；
导出在 `文档\物理解题动画\导出\`；开源日志优先写 exe 旁边，写不进去会退回用户数据目录。

**Q：能不能把 `app.asar` 再加密/混淆一下？**
A：当前没做。可选方案是 V8 字节码（bytenode）或构建期混淆，但都会引入
"Electron/V8 版本必须严格匹配"的维护成本。以本项目的交付场景（教师工具、非商业机密），
asar + 关 DevTools 已经够用；真正敏感的东西（Key）本来就不在包里。
如果以后要做，先补"打包后自检 + 版本锁定"再谈。

**Q：为什么 zip 体积没明显变小？**
A：asar 只是归档，不压缩；zip 本来就会压。体积主要由 Electron 运行时和 `node_modules` 决定。
判断"源码有没有进 asar"看目录形态与自检输出，不看体积。

## 九、v1.1.12 变更摘要

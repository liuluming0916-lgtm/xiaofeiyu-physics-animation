# 播放器、多幕、图片题（M1.5）

- 日期：2026-10-27
- 这一轮把三件事搬到宿主一侧：**时间归一化、播放控制、多幕切换**。
  模型只回答一个问题：**给定物理时刻 t，这一帧长什么样。**

---

## 1. 契约 v2（比上一版更小）

```js
window.XFY = {
  title: '光滑斜面下滑',
  physical: 1.56,      // 这一幕真实的物理时长（秒）
  render(t) { ... },   // 画出物理时刻 t 的那一帧（0 ≤ t ≤ physical），纯函数
  sample(t) { ... },   // 返回 t 时刻的物理量，纯函数
};

// 多幕
window.XFY = { acts: [ {title, physical, render, sample}, ... ] };
```

**模型不再需要知道"播多久"。** 上一版还要写 `playback: 4.0`、把物理时间映射到播放时间，
现在这层换算完全由播放器做：每一幕固定播 4.000 秒，`t_物理 = τ/4 × physical`。

好处很直接：题目的物理时长再离谱（0.3 秒的碰撞、8 秒的阻尼振动），学生看到的节奏都一样，
而模型不用为此写任何代码。

## 2. 宿主播放器

`packages/player`，导出时注入：

- 播放/暂停、重播、时间轴拖动、0.5×/1×/2×
- 时间读数：`播放 3.07 / 4.00 s`、`物理 t = 1.20 s`
- 多幕时多出 `‹ ›` 和「第 1/2 幕 · 标题」
- 空格暂停、左右键单步 0.1 s

控制条是 DOM，不在画布里：不会挡画面，也不会因为压住文字被判"重叠"。

## 3. 多幕

- 契约：`XFY.acts = [...]`，每幕有自己的 `physical`、`render`、`sample`。
- 播放器：一幕放完自动接下一幕；可以手动跳。
- 沙盒：逐幕各取 5 帧 + 90 个采样点，报错信息带「第 N 幕」前缀。
- 截图：`look_at` 支持 `{act, times}`，可以指定看第几幕的哪一刻。

验证样例：`examples/two-acts.html`（同一斜面，无摩擦 vs μ=0.2，两幕物理时长 1.56 s / 1.94 s）。

## 4. 图片题

```powershell
node scripts/run-problem.ts --image 试卷截图.png
```

图片直接作为多模态消息发给模型，文字题和图片题走同一条链路。

## 5. 真实跑分（图片题：37° 斜面 + 水平面滑行）

| 指标 | 数值 |
|---|---|
| 交付 | 是，两幕 |
| 版本数 / 质检未通过 | 4 / 2 |
| 耗时 | 404 s |
| 输入 tokens | 853,644 |
| 输出 tokens | 93,357（其中思考 73,253） |

模型自己算出 a = 2 m/s²、t = √5 ≈ 2.24 s、v = 4.47 m/s、水平滑行 2.0 m，全部正确。

## 6. 这一轮踩的坑

**图片题把思考撑爆了。** 第一次跑，模型花了 32,000 个 token 全用在思考上，
一个字的代码都没输出（`finish_reason: length`），随后连续三轮回空，白烧 8 分钟。

已改两处：
- 输出上限 32k → **96k**
- 检测到 `finish_reason: length` 且没有工具调用时，直接催它"少想多写"，而不是继续空转

**成本也跟着涨了。** 图片题的输入是 85 万 token（纯文字题 40 万），因为每轮都要重发图片。
这是目前单题成本的主要来源，后面要么减少回看轮次，要么把图缩得更小。

# 需求调研问卷与访谈纪要 · 小肥鱼物理解题动画软件

| 项 | 内容 |
|---|---|
| 文档版本 | V1.0 |
| 编制日期 | 2026-10-25 |
| 阶段 | 需求调研与产品规划阶段 |
| 调研对象 | 高中物理教师 3 位（教龄 6 / 12 / 20 年），教研员 1 位 |

## 一、调研目的

1. 确认“过程讲不清”是否是真实痛点，还是研发方的想象；
2. 确认教师对“自动生成动画”的接受边界（能不能改、要不要联网、能不能导出）；
3. 确认交付形态（网页 / GIF / 视频）与使用场景（课堂投屏 / 课件 / 课后）。

## 二、调研方法

| 方法 | 样本 | 产出 |
|---|---|---|
| 结构化问卷 | 3 位教师 | 定量偏好与使用习惯 |
| 半结构化访谈 | 3 位教师 + 1 位教研员 | 场景、顾虑、验收标准 |
| 素材走查 | 2 位教师试用早期原型 | 交互问题清单 |

## 三、问卷题目与统计

| # | 题目 | 结果 |
|---|---|---|
| 1 | 讲“过程类”题目时，主要用什么方式演示？ | 板书 3/3；动画 0/3 |
| 2 | 做一条 10 秒物理动画，通常要多久？ | 1 小时以上 2/3；不做 1/3 |
| 3 | 最希望自动生成的是哪类题？ | 传送带/连接体 2/3；电磁场 1/3 |
| 4 | 生成的动画如果不能改，能接受吗？ | 不能接受 3/3 |
| 5 | 题目会被上传到服务器，介意吗？ | 介意 3/3 |
| 6 | 希望导出成什么？ | 能直接播放的网页 2/3；GIF 1/3 |
| 7 | 一节课愿意为几道题做动画？ | 1–2 道 2/3；3 道以上 1/3 |
| 8 | 单次生成能接受多长等待？ | 3 分钟内 3/3 |
| 9 | 如果动画画错了，你希望看到什么？ | 明确指出错在哪 3/3 |
| 10 | 会不会自己调整“讲法模板”？ | 会 1/3；可能 2/3 |

## 四、访谈纪要（要点摘录）

**受访教师 A（教龄 12 年）**
- “传送带那道题，我讲三遍学生还是不懂共速之后摩擦力怎么变。”
- 明确要求：**能暂停在某一步讲**，不能只是一段从头播到尾的视频。
- 顾虑：如果生成的图“不像物理”，宁可不做。

**受访教师 B（教龄 6 年）**
- 平时用课件里的静态图，但“静态图讲不了过程”。
- 要求：**画错了要能看出来**，不然不敢在课堂上用。

**受访教师 C（教龄 20 年）**
- 关心数据安全：“题目里有我自己编的，不能传到网上。”
- 关心复用：“今年讲的，明年还能改一改再用。”

**教研员 D**
- 关心统一性：“同一道题，不同老师讲出来不一样；如果能沉淀成模板，教研就有抓手。”

## 五、调研结论

| 结论 | 对应的产品决策 |
|---|---|
| 痛点是“过程讲不清”，不是“没有题” | 不做题库，做“题目 → 动画”的转换 |
| 必须能按步骤讲 | 讲解步骤与动画时间双向联动 |
| 不能联网上传 | 全程本地运行，模型接口由用户自备 |
| 画错必须看得见 | 每次生成给校验报告，逐条列出未通过项 |
| 讲法要能改 | 知识卡（元件/场景/规范）可开关、可编辑 |
| 交付要能直接用 | 导出单文件网页（双击即播）与 GIF |

## 六、需求优先级

| 优先级 | 需求 | 排期 |
|---|---|---|
| P0 | 主链跑通（读题到导出） | v1.0 |
| P0 | 校验与自动修复 | v1.0 |
| P1 | 步骤联动、导出网页/GIF | v1.1 |
| P1 | 知识卡编辑与导入导出 | v1.1 |
| P2 | 批量生成、示例题库 | v1.3+ |

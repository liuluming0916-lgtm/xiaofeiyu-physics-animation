## 一、项目背景

中学物理的教学难点集中在“过程”：传送带上的共速、连接体的加速度分配、带电粒子在磁场中的圆周运动，
这些内容用板书和静态图讲不清，学生只能靠想象。教师现有的替代手段有三类：

1. **自己画图**：耗时，且一节课能讲透的题量有限；
2. **用通用动画软件手工制作**：一条 10 秒动画往往要 1–2 小时，无法随堂使用；
3. **用现成题库视频**：与自己的讲法、教材版本、班级进度不匹配。

大模型具备把题目转写成可执行绘图代码的能力，但直接让模型“算物理、画动画”存在两个硬伤：
运动不物理（速度莫名突变）、前后不一致（同一题两次生成结果不同）。这决定了产品的技术路线，
也决定了它必须是一个“工程化”的产品，而不是一个提示词。

## 二、要解决的问题

| 问题 | 现状 | 本项目要达成的状态 |
|---|---|---|
| 讲不清过程 | 教师口头描述，学生靠想象 | 生成可播放的二维动画，随讲解步骤联动 |
| 制作成本高 | 单条动画 1–2 小时 | 输入题目后 1–3 分钟内产出 |
| 结果不可信 | 模型算错无人知 | 内置九项判据与沙箱校验，未通过自动重画 |
| 数据顾虑 | 在线平台上传题目 | 全程本地运行，题目与密钥不出本机 |

## 三、目标用户

| 用户 | 特征 | 核心诉求 |
|---|---|---|
| 高中物理教师（主要） | 教龄 3 年以上，日常使用 Windows 办公电脑 | 快速得到能直接投屏讲解的动画 |
| 教研员 | 需要统一讲法、沉淀资源 | 可复用、可微调（知识卡） |
| 师范生 / 新教师 | 缺乏板书演示经验 | 看到规范的讲解步骤与图示 |

## 四、产品定位

一款面向中学物理教师的 Windows 桌面工具：**把一道题变成能讲、能暂停、能导出的动画**。
不做在线服务、不做题库售卖、不做学生端。

## 五、核心价值

1. **省时间**：把“做一条动画”从小时级压到分钟级；
2. **讲得准**：运动由程序按物理分析结果计算，不由模型估算；
3. **可信任**：每次生成都有校验报告，哪条没过、为什么没过，一眼可见；
4. **可积累**：知识卡可按教材章节开关与改写，讲法可以沉淀成自己的资产。

## 六、竞品与替代方案

| 方案 | 优势 | 不足 |
|---|---|---|
| 通用动画/演示软件 | 自由度高 | 学习成本高，单题耗时长 |
| 在线题库配套视频 | 即取即用 | 讲法固定，不能改题 |
| 通用大模型对话 | 零成本 | 不产出动画，物理正确性无保障 |
| 本项目 | 单题成本低、物理可信、可改讲法 | 需教师自备模型接口 |

## 七、目标与里程碑

| 阶段 | 目标 |
|---|---|
| v1.0 | 打通“读题 → 解题 → 分析 → 画图 → 校验 → 修复 → 导出”主链 |
| v1.1 | 补齐导出（单文件网页 / GIF）、知识卡管理、本地规则 |
| v1.2 | 正式公测：面向教师发布，收集真实使用反馈 |
| v1.3+ | 示例题库、卡片社区、写卡工作台 |

## 八、投入与风险

| 项 | 说明 |
|---|---|
| 开发形态 | 单人自研，按迭代推进，每版以回归题集与门禁验收 |
| 主要成本 | 模型调用费用（由用户自备 Key，本项目不承担） |
| 风险 1 | 模型输出不稳定 → 以九项判据 + 沙箱 + 自动修复兜底 |
| 风险 2 | 生成内容涉及他人教材/题目 → 不内置第三方题库，题目由用户输入 |
| 风险 3 | 同类产品先发 → 以“本地化 + 可改讲法 + 物理可校验”形成差异 |

## 九、立项结论

需求真实、技术路线可行、投入可控，**同意立项**，按 v1.0 → v1.2 的节奏推进。

## 1. 已经跑通的三件事

| 机制 | 位置 | 证据 |

| 虚拟时钟（可任意快进/倒带） | `packages/sandbox/src/page-runtime.js` | 4 秒的动画，5 个时刻截图 + 90 个采样点，实际只花 **4.3 秒** |

顺带跑通的还有：**外网请求拦截**（违规请求会被记录）、**页面报错收集**、**离线校验**。

## 2. 怎么跑

```powershell
npm install --cache .npm-cache     # 只装一次
npm run m0
```

产物：

- `开源日志/m0/incline-00.png` … `incline-04.png`（0 / 1 / 2 / 3 / 4 秒五帧）
- `开源日志/m0/report.json`（每帧摘要、探针值、检查结论）

样例动画：`examples/incline-ball.html`，倾角 30°、长 6 m、小球由静止下滑。
它同时是"理想输出"的参照物——后面给模型的提示词，就是照着它写的。

## 3. 这一轮真正抓到的东西

**① 自动抓到了文字重叠。**
第一版里"已滑行 s = 1.50 m"的标签压住了刻度数字 1 和 2，程序直接报出
“文字重叠 91%——「1」与「s = 1.50 m」”。这是肉眼要盯很久才发现的错，程序一秒就抓到了。

**② 圆弧包围盒一开始算错了。**
我最初把圆弧当成整圆算外接矩形，结果 30° 的角弧被判成"越出画布"。改成按起止角精确计算后消失。
——这类**误报**比漏报更讨厌：它会让模型去改一个本来没错的地方。所以检查项以后都要有"误报回归"。

**③ 一个绕不开的环境限制。**
在 DSH 的受限沙箱里，无头 Chrome 一启动就崩（crashpad 拿不到进程权限）。
所以跑 `npm run m0` 需要"完全访问"授权；打包成 exe 给你用的时候没有这个限制。
这是开发环境的问题，不是产品的问题。

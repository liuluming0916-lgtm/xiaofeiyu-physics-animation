# 门禁都盯什么（给贡献者）

一条命令跑全部检查：

```bat
node tools\verify-all.mjs
```

全绿会打印 **`✓ 全部门禁通过`**（当前共 **47 步**；另有 ⓪ 覆盖自检在 47 步之前先跑）。
红了不要改断言让它变绿——**先判断是代码错了还是断言过时了**，
两者必居其一，且都要在提交信息里说清楚。

> 这个项目是"**门禁当裁判**"的做法：很多约定（8 个槽位名、契约字段、词条格式）
> 靠断言钉住，而不是靠人记得住。改代码前先看对应的断言。

---

## 一、门禁守的四类事

| 类别 | 它在防什么 |
|---|---|
| **契约** | 字段名 / 枚举 / 必填项被悄悄改动。契约是生成物：改 `contracts/spec/` 后必须重新生成，手改产物会红 |
| **生成物逐字节相等** | `source/` 与 `data/` 不一致、浏览器副本与本源不一致、打包常量与源不一致 —— 一律红。**只改一处、忘了重跑生成命令**是最常见的红 |
| **运行时行为** | 8 个槽位程序的静态检查、干跑（不调用模型也能跑）、判据 C1–C9、修复轮次、SSE 事件序 |
| **对外观感与形态** | 测试次数、页面标题与版本、发布产物里**不该有**开发页、导出页里烧了哪些信息 |

---

## 二、改不同的东西，要跑不同的命令

| 你改了什么 | 必须先跑 |
|---|---|
| `contracts/spec/`、词表（`contracts/knowledgecard-concepts.json`） | `node contracts\generate-contracts.mjs` |
| 知识卡 `core/knowledgecard/source/` | `node tools\build-animation-cards.mjs` → `node tools\rewrite-knowledgecard-entries.mjs --prune` → `node tools\build-builtin-bundle.mjs` |
| 知识卡落盘 / 恢复内置（`core/knowledgecard/editor.mjs`、`tools/rules-service.mjs`） | 单跑 `node tests\knowledgecard-selftest.mjs` 与 `node tests\rules-service-selftest.mjs`（覆盖真实 HTTP） |
| 前端 `web/src/` | `node tools\web-build.mjs` |
| 模板 `template/` | `node tools\build-template.mjs` |
| **任何改动** | 最后都跑一遍 `node tools\verify-all.mjs` |

> ⚠ **顺序不能换**（生成链是有方向的）：卡片 → 词条 → 打包常量 → 前端 → 总门禁。
> ⚠ `verify-all` 会把 `web/dist` 重建成**开发形态**；要打包发布版，交给
> `node tools\electron-repack.mjs`（它内部会用 `OD_RELEASE=1` 重建，并把载荷封装成 `app.asar`）。
> 打包后的形态校验、真 exe 自检与"用户还能不能改卡"见 [打包文档](打包文档.md)。

## 三、Windows 上的两个坑（都会让门禁"假红"）

1. **编码**：仓库统一 UTF-8（无 BOM）、换行统一 LF，已写进 `.gitattributes`。
   用 PowerShell 改文件时别用默认编码，否则中文变乱码、逐字节比对直接红。
2. **管道会吃掉退出码**：`node tools\verify-all.mjs | Select-String ...` 在 PowerShell 里
   可能报 `exit 1`，而门禁其实是绿的。改成重定向再读：

   ```bat
   node tools\verify-all.mjs > _v.log 2>&1
   echo %ERRORLEVEL%
   type _v.log
   ```

## 四、新增一条断言的规矩

- 断言要写成**推导式**，不要写成"当前恰好是什么"。例：不要断言"覆盖了 0 个"，
  要断言"完成度 = 已覆盖 ≥ 应有数"——否则内容一做完，门禁就按计划变红，
  而那时最省事的做法就是改断言。
- 断言失败时的提示里要**带上实际值**，让人不用加打印就能查。
- 说人话：断言名写在报告里，别人靠它判断"哪条规矩被破了"。

## 五、哪些东西**不能**进仓库

`ai-rules/keys.json`（密钥）、`ai-rules/knowledgecard/`（用户知识卡）、第三方教学素材、
`release/` 产物、`node_modules`、用户数据。
清单见 [.gitignore](../.gitignore)。**别把密钥提交进去**——提交历史里删不干净。

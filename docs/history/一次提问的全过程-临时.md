## 0. 先回答你的问题：每次发前缀，对不对？

**对，而且必须发。** 原因有三层，从浅到深：

1. **模型没有记忆。** 每次请求是一次独立的 HTTP 调用，服务端不会替你记住"上一句说过什么"。
   所谓"对话历史"，其实是客户端每次都把之前的消息**重新发一遍**。我们这里更极端：
   每个阶段是一次**独立请求**，所以五个阶段各要一份 system。
2. **前缀放在最前面，是为了命中缓存。** 缓存的工作方式是"从头开始逐字节比对"——
   一旦中间有一处不同，后面全部作废。所以要把**永远不变的**放最前（固定前缀），
   **每阶段会变的**放其次（阶段指令 + 命中词条），**每题不同的**放最后（题面与上一阶段的产出）。
   现在的顺序正是这个（`前缀 → 阶段指令 → 词条 → 任务段`）。
3. **"发"和"付钱"是两件事。** 发 5 次共 17,815 字；但如果服务端命中前缀缓存，
   那 4 次重复是按缓存价算的。**所以真正要关心的不是"能不能不发"，而是"发出去的是不是逐字节一样"**。
   这也解释了为什么代码里要堵死"往前缀塞题面"——那会让 4 次缓存全部失效。

**唯一还能省的，是"减少调用次数"**（比如把"解题+答案+分步"合并成一次），代价是失去
"只重生成出错那一槽"的能力。当前设计选择了"多调用、可局部重试"，在本项目里是对的
（因为打回率是主要成本，不是 token）。

```text
## 规范·符号、单位与正方向
- 一维问题先声明正方向，之后一律用**带符号标量**：向右为正，则向左的速度写负值。
- 符号固定：位移 x、速度 v、初速 v0、加速度 a、时间 t、间隔 T；力 G/N/f/F_T；能 Ek/Ep/W/P/Q；电 q/E/phi/U/I/R/B/Phi。
- 单位一律 SI。g 取题面给定值；题面没给就取 10 m/s²，并在解析里写明。
- 角度在解析里写度数。非常用单位（cmHg、km/h、eV）先换算成 SI 再代入。
## 规范·矢量与分量
- 矢量先交代**大小 + 方向**（与正方向的夹角，或两个正交分量），再参与运算。
- 分解按已声明的两个正交轴投影：沿轴用 cos、垂直轴用 sin；两轴全程不换。
- 合成写成矢量式再取大小：v = √(vx² + vy²)，方向 tanθ = vy / vx。
## 规范·公式与数值的写法
- 先推**符号表达式**，再代数值；每条结论写成「符号 = 数值 单位」。
- 数值取 2–3 位有效数字，与题面数据的精度对齐；中间量保留符号，最后一步才代入。
- 代入的数值与题面逐字一致，不要"约等于改写题面"。
## 规范·量纲与极限自检
- 量纲：等号两侧、可相加各项的单位必须相同；指数与三角函数里必须是无量纲量。
- 极限：让关键参数趋于 0 或无穷，结果应退回已知模型（μ→0 无摩擦、θ→0 水平面）。
- 特殊值：取一组好算的数代进去，与物理直觉对一遍；量纲不符时**改式子**，不改结论。
## 规范·守恒式与过程式的写法
- 守恒式三步走：**先声明系统与正方向** → 写守恒量（初态 = 末态）→ 再代入具体量。
- 过程式（动能定理、动量定理）先写"谁对谁做功 / 谁给谁冲量"，再写等式。
- 摩擦生热单独一项：Q = f × **相对位移**，与物体自身位移区分开。
- 守恒不成立时（有外力、有摩擦）改用含外功的式子，并说明差额补在哪一项。
## 规范·临界与极值
- 临界点写成**某个力或约束等于零（或取到极值）的等式**：N = 0（脱离/过顶）、f = f_max（刚要滑）、T = 0（绳刚松）。
- 先写临界条件式，再解出待求量；结论里说清取到极值的时刻或位置，并说明为什么在这里取到。
```

**模型交出的东西**：解题过程（写死的模拟结果）

```text
取向右为正方向。物块刚放上传送带时速度为零，传送带速度 $u=2\ \mathrm{m/s}$，故物块相对传送带向左滑动，所受滑动摩擦力方向向右，大小 $f=\mu mg$，加速度 $a_1=f/m=\mu g=2\ \mathrm{m/s^2}$。

物块做匀加速直线运动，速度 $v=a_1t$，直到 $v=u$ 时与传送带共速，所需时间 $t^{*}=u/a_1=1.0\ \mathrm{s}$，该段位移 $\Delta x=\tfrac{1}{2}a_1t^{*2}=1.0\ \mathrm{m}$。

共速之后两者无相对滑动，摩擦力为零，物块随传送带一起匀速运动。

摩擦生热用**相对位移**计算：$\Delta s=ut^{*}-\Delta x=1.0\ \mathrm{m}$，$Q=\mu mg\,\Delta s=2.0\ \mathrm{J}$。

结论：(1) $t^{*}=1.0\ \mathrm{s}$，$\Delta x=1.0\ \mathrm{m}$；(2) $Q=2.0\ \mathrm{J}$。
```

# 动画基本约定（常驻 · 任何题都适用）

这段代码由机器播放、机器量、机器对答案，所以"坐标、正方向、单位"必须**全片一套**。

## 坐标与尺寸
- **世界坐标**：x 向右、y 向上、单位米；视口由系统算，**不许写像素**（`pixels_per_meter`、`canvas.width`、`getContext` 一律判失败）。
- 长度就是题面的米数（板长 3 m 就画 3 m）；天文/微观用示意比例，并在图注写"示意图，未按比例"。
- 位置一律由物理量算出来（`Draw.box([state.x, 0.15], …)`），不要写死一屏坐标。

## 正方向（最容易翻车）
- 解析里定了哪个方向为正，代码里就同一个：向右为正 ⇒ 向左的速度写负值，`state.v` 可以是负数。
- 矢量的 `vec` 只表示**方向**（可带负号），**长度由 `mag` 决定**（真实量级）：
  `state.v = -2` 时写 `vec: [state.v, 0]` + `mag: Math.abs(state.v)` —— 箭头朝左、长度 ∝ 2。
- 角度：代码里用**弧度**；但 `Draw.incline` 的 `angleDeg`、`Draw.arc` 的 `a0/a1` 是**角度制**，两套别混。

## 单位、常量与时间
- 一律 SI（m、s、kg、N、J、A、V、T）；cm、km/h、eV、cmHg 在 `setup()` 里换算一次并写注释。
- 题面给的数（`g`、`mu`、`L`、`R`）在 `setup()` 里以**同名常量**出现；没给 `g` 就取 10 并写注释。**不许中途换值**（C7 要拿读数对答案）。
- `t` 单位秒，范围 `[0, SIM.duration]`；`stateAt(t)` 全程有定义、且 O(1)（解析式或查表，不在里面积分）。
- `STEPS` 的 `t0/t1` 首尾相接、不重叠，**末步 t1 = SIM.duration**（C5）；这个数写成一个字面量，注释给出算法。
- **槽位正文从第一行代码开始**：`setup` 的第一行就是 `const …`、`readouts` 的第一行就是 `return [`（函数头与收尾括号由装配器提供）。

## 读数（readouts）
- 每项 `{ label, value, unit }`；`label` 与 `ANSWERS.symbol` **逐字一致**（C7 就靠它）。
- 键集合与单位**全时段不变**（C8）；数值必须有限（C3：NaN / Infinity 直接判失败）。
- 画面上显示数值用 `Phys.format(value, unit)`；中文说明放数据面板，不挂在箭头上。
- **符号题（`value: null`）照样要画图**：图表数据取 `setup()` 里的示意取值，并在图注写"示意"；不要因为没有数值就把图省掉。

- [ ] 全片没有像素量；每个 `Draw.arrow` 都有 `category` 与 `mag`，且没有 `color` / `scale`。

## 3. 干跑：第 6 步**不调模型**

程序交出来之后，本地会跑一遍 C1–C9（静态预检 + 沙箱执行 + 逐帧判据）。这一步**不花 token**。
只有没过时才回到模型，而且**只重发生错的那几个槽位**：

```text
[本阶段指令：自愈修复]
上一轮生成的动画代码没过校验。请只输出被要求修改的槽位，一个不多、一个不少……
（+ 诊断：哪一槽、第几行、什么规则、证据强度）
```

每轮约再发一次"前缀 + 动画阶段指令 + 动画槽词条 + 诊断"，上限 3 轮。

## 5. 这份回放暴露的三个事实

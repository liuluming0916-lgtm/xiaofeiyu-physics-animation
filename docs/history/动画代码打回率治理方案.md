# 动画代码总被打回：诊断 + 改造方案

> 依据：我逐行读了 `core/prompts/`、`core/lint/`、`core/dryrun/`、`core/worldbook/`、`sdk/`、`ai-rules/`、`template/build/`，并在本机上跑了几次实测（结果都写在第 0 节和第 12 节，可以复核）。

## 0. 一句话结论

**你的方向是对的，但只做你提的那两件事，效果会打对折。**

因为真正的病根不是一个，而是三个叠在一起：

1. **考卷很严**（约 30 条硬性规则、9 道自动检查，7 道不通过就判失败）——这一项是对的，不该动；
2. **考试大纲（给 AI 的说明）只有 744 个字，而且全是"不许这样"**——这一项要重写，就是你说的那件事；
3. **样卷锁在抽屉里**：我们库里已经有 **78 条词条、178 段示例代码、15 道真题的完整程序**，而模型**一行都没看见过**。

第 3 项是最大的漏，也是最容易被忽略的：**示例不是"写得不够好"，是"根本没送出去"。**

## 1. 模型现在到底看到了什么（实测数字）

给动画阶段（`scene_code` 阶段）的 system 消息，由三段拼成：

| 段 | 内容 | 字符数 |
|---|---|---|
| 固定前缀 · 角色 | "你是高中物理解题与动画生成助手……" | 332 |
| 固定前缀 · 模板骨架 | 8 个槽位名字 + `/* @slot:KEY */ … /* @end */` 标记格式 | 339 |
| 固定前缀 · SDK 签名摘要 | 23 个 `Draw.*`、4 个 `Phys.*` 的一行式说明 | 2886 |
| 条件段 · 本阶段指令 | `templates.mjs` 里 `scene_code.system` 的全文 | **744** |
| 条件段 · 世界书词条 | 命中才注入；命中 1 条传送带词条约 1046 字；**一条都没命中时是 0** | 0 ~ 24000 |

一共 **3659 + 744 = 4403 字起步**。我在这 4400 多字里数了一遍用词：

- "禁止" 3 次、"不要" 14 次、"不得" 1 次、"必须" 12 次 —— 合计 **30 处"必须/不许"**；
- "示例" 0 次、"范例" 0 次、"照抄" 0 次 —— **0 处"可以这样写"**；
- **能完整照抄的程序：0 行**。

对比一下：你那个第 5 期的老参照（教学素材，**已从仓库移除**）是 **7020 字**，里面有 4 处"例："、1 处"正确写法"、2 处"错误/正确"对照、3 处自检段落。**我们现在这份，是从那份退化成了一份禁令清单。**

> **术语解释 · 槽位（slot）**
> 把一整段动画代码切成 8 个"抽屉"，每个抽屉只放一类东西：`PROBLEM`（题干）、`STEPS`（分步）、`ANSWERS`（答案）、`VIEW`（时长等视图参数）、`setup`（开场算一次）、`stateAt`（任给一个时刻，报出那一刻的位置）、`drawFrame`（画这一帧）、`readouts`（右下角读数）。每个抽屉要用 `/* @slot:KEY */` 和 `/* @end */` 两行"标签"包起来，机器靠这两行认抽屉，**猜不出来，缺一个就整份作废**。

## 2. 三段"闸门"在哪（为什么它老是被打回）

一代代码要活下来，必须连过三关。任何一关红，就是你说的"打回"：

| 闸 | 代码位置 | 查什么 | 打回方式 |
|---|---|---|---|
| 第一关 · 分拣 | `core/cleaner/marker-split.mjs` | 8 个抽屉标签齐不齐、名字对不对 | 标不出抽屉 → 整份作废 |
| 第二关 · 静态体检（C1） | `core/lint/contract-lint.mjs` | 语法错误、`import/require/eval/window/document` 等 25 个禁用名、`constructor/__proto__`、死循环、自己调自己、**用了没声明的名字**、`stateAt` 里偷偷积分、单槽 >400 行、`Draw.arrow` 少 `mag` 或多写 `color/scale` | 逐条报行号 |
| 第三关 · 试跑（C2–C9） | `core/dryrun/dry-run.mjs` | 跑得动不超时；数字不是 NaN；坐标不飞出世界、不瞬移；STEPS 的 t0/t1 无缝且末步 = 总时长；阶段交界处位置不跳；**答案能在指定时刻被读数复现**；读数键集合/单位全程不变；画面真的在动 | C2/C3/C4/C5/C6/C7 阻塞，C8/C9 只警告 |

然后还有**第三次机会**：`dry_run` 不过就进"自愈修复"（`core/repair/`），最多 **3 轮**，每轮只让模型改"被判错的那几个抽屉"。

⚠ 这里有个隐蔽的坑，我实测确认过：**修复时喂给模型的只有"哪一行错、错成什么样"，没有一份"对的样子"**（`core/repair/plan.mjs` 的 `buildRepairTask`）。所以模型是在**盲改**。3 轮盲改不过，就带告警横幅交付——这正是你看到的现象。

> **这三关不能拆。** 它们被 `tests/` 里的取证用例钉死（`CHECK_SEVERITY` 冻结、C1–C9 一条不许改），拆了等于把"绝不把没验过的结果当成品交付"这个承诺作废。
> **所以正确的方向不是"放宽"，而是"教清楚"。** 这也是你的判断，我同意。

## 3. 你的方案：哪儿对、哪儿缺

你的原话：重写 `prompts/scene_code.md` 的 prompt、重写 `ai-rules/worldbook/` 里的常驻动画指导 prompt，用正向示例、教学、参考，告诉 AI 我们允许什么样的代码。

**三个"对"**：
1. 方向对：把"禁令清单"换成"范文 + 对照 + 自检"，是提高一次通过率最划算的手段；
2. 位置对：这两处都落在**条件段**（每个阶段单独发的那段），不改固定前缀，所以 **promptHash 不变、缓存不失效、成本不会涨**；
3. 手段对：世界书词条是**唯一能"无条件注入"**的通道（`constant: true`），适合放"任何题都要遵守"的教法。

**三个"缺"**（这就是我这份方案比你的方案多出来的部分）：

**缺 1 · 会入库 ≠ 会发送。**
`code_examples` 这个字段，78 条词条**每条都有**，共 178 段代码。但注入时用的函数是：

```js
// core/worldbook/engine.mjs
export function renderEntryBlock(slot, title, content) {
  return `【世界书·${label}：${title}】\n${content}`;   // ← 只拼 content，code_examples 丢了
}
```

我实测验证过：把传送带那条词条（正文 1015 字 + 示例 729 字）注入后，注入段落里**搜不到示例里的任何一行**。
**所以光写词条，示例依然到不了模型。这根管子必须先接上（方案 L3）。**

**缺 2 · 现在一条"常驻动画词条"都没有。**
`scene_code` 槽能收到 28 条词条，但**全部靠"命中"**：要等第 0 步读题判定出【动画元件】（传送带 / 弹簧 / 磁场…）才会对应注入。
而读题这一步是模型判断的，**它写"无"，动画阶段就一条规范都收不到**——只剩那 744 字。我实测：注入空槽时 system 消息只有 4403 字。
**常驻词条（`constant: true`）是无条件注入的，这是唯一"保证模型一定能看到"的位置。**

**缺 3 · 我们自己的示例有 34 处过不了自己的关。**
我拿项目自己的 C1 把 178 段示例全跑了一遍：**21 段（约 12%）会直接被判失败，34 处 `Draw.arrow` 少 `mag`**。
也就是说：**照抄我们的示例，会被我们的闸打回。** 这比"没有示例"更糟——它会训练出错误写法。
（这个坑在早期整理教学素材时也踩过：当时记的是"778 处跨槽位裸引用"，性质一样。）

> **术语解释 · `mag`**
> `Draw.arrow` 画箭头时，除了方向，还要求给一个"这个量有多大"的数（`mag`）。原因：箭头的长度按"同类里最大的那支"等比缩放，没有 `mag`，速度箭头和加速度箭头混在一起就没法比长短。还有一个历史包袱：`scale` 和 `color` 这两个参数**已经废弃**，写了不报错、但完全不生效，所以现在**写了就判失败**（理由写在 `contract-lint.mjs` 的注释里："不要留一行看起来有用、其实没用的屎山"）。

## 5. L0 · 先止血：把 34 处违规示例修好

**做什么**：给每条 `Draw.arrow(...)` 补上 `mag`，删掉 `color`/`scale`。

**为什么先做**：不管后面怎么写提示词，只要示例是错的，模型照抄就被打回，而且我们没法解释"为什么范文也过不了"。

**怎么改**（举一个真实例子，来自 `wb_visual_conventions` 的示例）：

```js
// 改前（会被 C1 判 fail：arrow-missing-mag）
Draw.arrow([p.x, p.y], [fx, fy], { category: 'force', subtype: 'lorentz', label: 'F_L' });

// 改后（补 mag = 这个力的真实大小；subtype 是合法的受力子类）
Draw.arrow([p.x, p.y], [fx, fy], {
  category: 'force', subtype: 'lorentz', mag: state.F_L, label: 'F_L', unit: 'N',
});
```

**验收**：跑一遍我用的同一个脚本（把 `code_examples` 逐段喂给 `lintSlot`），`blocksWithLintErrors` 必须是 **0**；然后把这条检查写进 `tests/worldbook-selftest.mjs`（"示例必须过 C1"），以后不许回退。

## 6. L1 · 上"常驻动画教学词条"（最关键的一步）

### 6.1 为什么放 `ai-rules/worldbook/` 而不是内置库

- `core/worldbook/data/*.json` 是**内置库，升级会被覆盖**；
- `ai-rules/worldbook/*.json` 是**你自己的库，升级不动它**，同 `id` 还会覆盖内置（叫"覆盖副本"）。
- 所以：**你写的教学词条放 `ai-rules/worldbook/`，永远不会被升级冲掉。**

### 6.2 文件长什么样（可直接另存为 `ai-rules/worldbook/00-animation-core.json`）

```json
{
  "format": "od-worldbook",
  "version": 1,
  "entries": [
    {
      "id": "wb_user_animation_core",
      "title": "动画代码基本盘（常驻）：一份能通过全部校验的范文 + 六条写法",
      "origin": "user",
      "category": "scene_modeling",
      "enabled": true,
      "constant": true,
      "recursive": false,
      "keys": [],
      "secondary_keys": { "logic": "AND_ANY", "list": [] },
      "insertion_slot": ["scene_code"],
      "order": 1,
      "priority": "high",
      "content": "（正文见 6.3，把那段原文粘进来）",
      "code_examples": ["（范文见 6.4，把那段原文粘进来）"]
    }
  ]
}
```

四个字段的作用，一句话一个：
- `constant: true` → **每道题都注入**，不管题目考什么（这是这条词条存在的唯一理由）；
- `insertion_slot: ["scene_code"]` → 只进动画阶段，不污染解题阶段；
- `priority: "high"` + `order: 1` → 预算不够时**先保它**（排序规则是 `priority → order`），不会被别的词条挤掉；
- `keys: []` → 常驻词条不需要触发词（规则原文："keys 为空时 constant 为真仍注入"）。

> **术语解释 · 预算**
> 每个槽位最多注入 40 条词条 / 24000 字符，超了会按优先级截断。24000 字很宽裕：一份完整范文约 600–4400 字，放 1 篇完整 + 2 段片段没问题；**但别塞 5 篇完整的**，那会把预算吃光，还会稀释模型的注意力。

### 6.3 词条正文（`content`）建议写这五节

1. **这份代码是给机器播的，不是给人读的**（先建立预期：不要写解释、不要写"注意"）；
2. **6 条"这样写就对了"**（全部是正向句式，每条附一行正例）；
3. **4 个高频打回点 → 改前/改后对照**（`arrow` 缺 `mag`、在 `stateAt` 里积分、跨槽位直接引用变量、`readouts` 键名与答案符号对不上）；
4. **交卷前自检 4 条**（可以机检的那种，不是"请注意"）；
5. **一句话说明为什么必须有 8 个抽屉**（让模型理解约束，而不是背约束）。

### 6.4 那份"已验证通过"的范文（我实跑过，C1–C9 全绿）

这是我为这份方案现场写、并**在本机跑真校验**的最小范文（28 行，578 字）。它覆盖了"8 抽屉 + 一支带 mag 的箭头 + 一条轨迹 + 一个读数 + 答案闭环"这些最容易出错的地方，而且**没有任何花哨技巧**——正适合当"第一份样卷"：

```
/* @slot:PROBLEM */
质量 1 kg 的物块在水平面上以 v0 = 1 m/s 匀速向右运动，求 2 s 内的位移。
/* @end */

/* @slot:STEPS */
title: 第 1 步 · 匀速运动
tex: x=v_0 t
t0: 0
t1: 1

title: 第 2 步 · 读出位移
tex: x=2.0\ \mathrm{m}
t0: 1
t1: 2
/* @end */

/* @slot:ANSWERS */
symbol: x
value: 2
unit: m
tol: 0.01
at_t: 2
step: 2
/* @end */

/* @slot:VIEW */
SIM = { duration: 2 };
/* @end */

/* @slot:setup */
const V0 = 1;
RETURN('V0', V0);
/* @end */

/* @slot:stateAt */
const V0 = context.V0;
return { x: V0 * t, v: V0 };
/* @end */

/* @slot:drawFrame */
const x = state.x;
Draw.ground(-0.5, 3.0);
Draw.box([x, 0.2], 0.4, 0.4);
Draw.arrow([x, 0.2], [1, 0], { category: 'velocity', mag: Math.abs(state.v), label: 'v', unit: 'm/s' });
Draw.trace([[0, 0.2], [x, 0.2]]);
/* @end */

/* @slot:readouts */
return [{ label: 'x', value: state.x, unit: 'm' }];
/* @end */
```

本机实测结果（`core/dryrun/dry-run.mjs`，回退后端）：

```
VERDICT: pass
C1 pass  8 槽位全部通过（代码型槽位走 §6.2 全表；数据型槽位走行式表校验）
C2 pass  执行 11 ms / 481 步，均在预算内
C3 pass  所有 readouts 值与命令坐标均有限
C4 pass  单帧画面位移未超 0.0700
C5 pass  2 步无缝、有序、不重叠，末步 t1 = duration = 2s
C6 pass  1 个边界在 ±0.001s 邻域内位置连续（连续性分量：x）
C7 pass  1/1 条结论在 at_t 时刻由 readouts 复现
C8 pass  键集合与单位稳定（1 项）
C9 pass  随时间变化；单帧命令数峰值 4
```

⚠ 这份范文里每一行都是有原因的，写词条时要**逐条讲出来**（这才是"教学"）：
- `stateAt` 里先 `context.V0` 再算 —— 因为 `setup` 里的 `const` **在别的抽屉里看不见**（抽屉是独立函数体），这是 69 个词条 / 778 处踩过的坑；
- `Draw.arrow` 给 `mag: Math.abs(state.v)` —— 真实量级，不是凑一个 0.5；
- `readouts` 的 `label: 'x'` 与 `ANSWERS` 的 `symbol: x` **逐字一致** —— C7 就靠这个对上；
- `STEPS` 末步 `t1: 2` 与 `SIM.duration: 2` 相等 —— C5 逐点比对；
- 位置全程连续 —— C6 在 t=1 交界处 ±0.001s 取样，不能跳。

## 7. L2 · 重写 `scene_code` 指令（可直接落地）

### 7.1 落地位置与机制（三个必须知道的点）

- 文件路径：**`ai-rules/prompts/scene_code.md`**（文件名必须是小写 id + `.md`，`prompts/` 下不能套子目录，也不能留 `.bak`）；
- 内容是**整份替换**，不是追加：写多少就发多少，内置那 744 字会被完全替换掉；
- 保存时会检查两个记号：正文里必须还能看到 **"槽位"** 两个字（否则给警告，说明你可能把槽位协议讲丢了）。没有其他硬拦。

手工创建这个文件也能用（程序会自动登记成"来源不明"，只提示不拦）。想稳妥，就在软件的**规则页 → Prompt 编辑器**里改，那里会自动记录"这份是基于内置哪一版改的"。

### 7.2 新版正文草稿（约 2000 字，直接可用）

```text
现在执行【动画代码】阶段。你要交的不是一篇说明，而是一段**机器能直接播放的程序**：
8 个槽位，每个槽位用 /* @slot:KEY */ … /* @end */ 包起来，标记独占一行，正文不写解释。

════ 一、先看一份已经通过全部校验的完整程序 ════

（下面就是范文，八个槽位都在。它真的能跑，而且 C1–C9 全绿——照它的结构写，你大概率一次通过。）

/* @slot:PROBLEM */ …（题干原文）… /* @end */
/* @slot:STEPS */ …… /* @end */
/* @slot:ANSWERS */ …… /* @end */
/* @slot:VIEW */ …… /* @end */
/* @slot:setup */ …… /* @end */
/* @slot:stateAt */ …… /* @end */
/* @slot:drawFrame */ …… /* @end */
/* @slot:readouts */ …… /* @end */

════ 二、这份范文里，六个值得直接照抄的写法 ════

1. 跨槽位传数据：setup 里 `RETURN('V0', V0);`，别的槽位 `const V0 = context.V0;`。
   ✗ 不要写 `const V0 = 1;` 然后在 stateAt 里直接用（拿不到，会被判"未声明的名字"）。
2. 状态只需要算一个时刻：`stateAt` 里只有解析式或查表，**不许调 Phys.integrate**。
   需要积分就在 setup 里积好，用 RETURN 导出。
3. 箭头：`Draw.arrow(起点, 方向向量, { category, mag, label, unit })`。
   mag 是**真实物理量**（|v| / |a| / |F|），不是为了让箭头好看而凑的数；不要给 color 或 scale（已废弃，写了判失败）。
4. 时间：`VIEW` 里 `SIM = { duration: 总时长 }`，且必须**等于 STEPS 最后一步的 t1**。
5. 读数：`readouts` 每一项 `{ label, value, unit }`，label 与 ANSWERS 的 symbol 逐字一致，
   键集合与单位**全程不变**（不要某一帧多一项、少一项）。
6. 画：`drawFrame(t, state)` 拿不到画布对象，只能调 Draw.*；位置全用世界坐标（米，x 向右 y 向上），
   **不许写像素、不许写相机比例**（视口由系统自己算）。

════ 三、四个高频打回点（改前 → 改后） ════

① 箭头没 mag
   ✗ Draw.arrow([x,0.2],[1,0],{category:'velocity',label:'v'})
   ✓ Draw.arrow([x,0.2],[1,0],{category:'velocity',mag:Math.abs(state.v),label:'v',unit:'m/s'})

② 在 stateAt 里积分（架构上不许）
   ✗ stateAt: `return Phys.integrate(...)`
   ✓ setup 里算好 → RETURN('samples', …) → stateAt 里 Phys.interp(context.samples, t)

③ 跨槽位直接用变量（抽屉是独立函数体）
   ✗ drawFrame 里写 `const x = V0 * t;`（V0 在 setup 里）
   ✓ `const V0 = context.V0;` 或干脆用 state 里已经算好的量

④ 读数的 label 与答案符号对不上
   ✗ ANSWERS: symbol x / readouts: { label: '位移' }
   ✓ 两边都写 `x`（大小写、下标写法都算）

════ 四、交卷前自检（逐条对，任一条不对就先改再交） ════

□ 8 个槽位标记齐全，每个正文非空，标记之外没有任何解释文字；
□ VIEW 的 duration == STEPS 末步 t1；STEPS 从 0 开始、首尾相接、不重叠；
□ 每一个 Draw.arrow 都带 mag；没有任何一处出现 color / scale；
□ readouts 的每一项 label 都能在 ANSWERS 的 symbol 里找到同名的那一条；
□ 位置类量在 STEPS 的每个 t0/t1 处连续（不瞬移）；用到的每个名字要么自己声明了、要么是 context.X。

════ 五、为什么约束这么死 ════

因为这段代码不是给人读的：它会被自动播、自动量、自动对答案。一次失败会退回重改，
所以"照样式写"比"写得巧"重要得多。SDK 里没有的函数一律不要用（未登记的名字会被静态检查拒掉）。
```

**为什么这样写比原来好**（给不懂代码的你看的三条）：
1. **开头就给答案**：模型先看到"成品长什么样"，再听规则，理解成本最低；
2. **规则全部挂在一个具体例子上**："跨槽位用 `context.X`"这种话单独说是天书，配一行"✗ 这样写拿不到 / ✓ 这样写拿得到"就懂了；
3. **自检清单是可机检的**：和 C1–C9 的判据一一对应，模型能"自己当考官"，而不是交上来等被打。

## 8. L3 · 把 178 段示例接进注入通道（改一处引擎函数）

**现状**：`code_examples` 存了、校验了、算覆盖率了，**就是不发送**。

**改法**（`core/worldbook/engine.mjs` 的 `renderEntryBlock`，约 3 行）：

```js
export function renderEntryBlock(slot, title, content, examples = []) {
  const label = SLOT_MARKER_LABEL[slot] ?? slot;
  const body = examples.length
    ? `${content}\n\n### 可照抄的写法\n` + examples.map((c) => '```js\n' + c + '\n```').join('\n')
    : content;
  return `【世界书·${label}：${title}】\n${body}`;
}
```

配套改动三处（都在同一个文件里，不影响判据）：
1. `buildSlotConditional` 里把 `e.code_examples` 传进去；
2. **预算按"渲染后的整块"计**（现有实现本来就是按渲染后算的，注意别破坏这条）；
3. 覆盖率/自检的测试跟着更新（`tests/worldbook-selftest.mjs` 里"两个槽的拼接内容逐字节相同"那条要跟着改）。

# 附录十一：AEB 真题的两条红 —— 都是**我们的判据**错（程序本身完全合法）

## A. C1：「引用未声明的名字 isFinite」

用户的写法是 `if (!isFinite(xm)) xm = 0;` —— 标准的“防 NaN 守卫”，共 8 处。

- Dry-Run 沙箱（`core/dryrun/vm-context.mjs` 的 `slotGlobals()`）**一直就提供**

- 但 C1 的 `ALLOWED_GLOBALS` **漏了这四个** ⇒ 运行时能跑、静态检查判死；
- 更糟的是建议文案：`最近邻` 没有距离上界，于是给出
  “你是否想调用的是 `Infinity`、`BigInt`、`Date`”——纯噪音。

修法：
1. 白名单补齐这四个标准纯函数（并在注释里写死“**必须与沙箱提供的全局一致**”）；
2. 建议加边界：编辑距离 ≤ `max(1, ⌊长度×0.4⌋)` 才提，最多 2 个；否则一个字都不提。

这与取景那次是同一个教训：**标注与参考面不该参与几何判据**。
修法：位移判据改用**实体包络**（排除 `text` / `latex` / `dimension` 与可出血的阴影参考面），
一条实体都没有时退回原包络；世界盒检查仍用原包络（坐标越界是真错，与是不是标注无关）。

# 附录十三：开发模式首跑的三条反馈

## ① 播放键不动，但拖时间轴能动

截图上的 `0.00 / 0.00 s` 就是答案：**`player.duration` = 0**。
而模板的推进逻辑是：

```js
if (player.state.playing) { next = t + dt*rate; if (next >= player.duration) { next = duration; setPlaying(false); } }
```

`next >= 0` 恒成立 ⇒ **一按播放就被立刻停掉**；拖时间轴则走 `seek()`，它直接 `draw()`，所以看起来"能动"。
根因是 `SIM.duration` 没有给出一个正的有限数（否则播放器不可能一帧都推不动）。

修法（都做）：
1. 模板里**时长无效时当场报错**：`showNotice` + `postToHost('error', { code:'bad-duration' })`，
   文案直接点明"SIM.duration = …，请写成 SIM = { duration: <秒> } 并等于 STEPS 末步 t1"；
2. `els.timeline.max/step` **只在时长有效时**写（`max="0"` 会让滑块取值范围退化，拖起来更像坏掉）；
3. 宿主通信日志的 ready 行**带上时长**：`✓ 模板已就绪 · 时长 3.00 s` —— 一行就能看出是 0 还是正常。

实测后果：正文 25885 里那张「通用运动建模与阶段表（兜底·双槽）」（`wb_general_modeling`，**2113 字**）
差 228 字进不来 —— 而它正是那道题骨架的出处。**为示例牺牲正文核心卡，是错的。**

## B. 真正的病根：示例额度被算成"槽位额度 − 正文"

用户定的是 **正文 30000 + 示例 10000 = 合计 40000**，但旧公式是

```js
exampleRoom = min(示例池 10000, maxChars 30000 − 正文)
```

等于把示例塞进正文的 30000 里 ⇒ **"合计 40000"从来没生效过**，示例永远只吃正文剩下的零头（实测 4115）。
这才是"示例总被截断"的真正根因 —— 跟均分、跟单条上限都无关。

## C. 改法（两处）

| 改动 | 内容 |
|---|---|
| `WORLDBOOK_BUDGET.totalChars = 40000`（新增） | 正文与示例的**合计**上限，独立于 `maxChars`（正文 30000） |
| `exampleRoom = min(10000, 合计 40000 − 正文)` | 示例与正文**各用各的池子**；正文照旧吃满 30000，**不再预留、不再牺牲卡片** |

告警文案也一并改成写**实际生效**的数：

```
正文 25885 + 示例 10000 = 35885 ≤ 合计 40000
（示例池 = min(上限 10000, 合计 40000 − 正文 25885)）
```

正文截断那条也补上了"示例另有 10000 字、合计 40000 字，**示例不吃正文额度**"，
免得再出现"写着 30000 却在 24000 截断"那种不可信的告警。

## D. 实测（同一道宽题，11 条词）

```
示例 发 8 / 去重 0 / 跳 0 = 6424 字

```

# 附录十五：干净启动（偏好按"本次启动"隔离 + 时间不记忆 + 默认全开）

用户逐条拍板：①每次**打开**要干净（同一启动内刷新要保住开关）②时间轴永远 0 ③曲线图**一律默认开**
④三栏全显示 ⑤动画联动默认勾 ⑥允许清旧记录 ⑦同一启动内刷新要保住。

## A. 先纠正一个概念（也解释了为什么以前老出怪事）

双击 `3-OpenRules.bat` 打开的是**正式本机版**（`web/dist`），不是演示页。
但动画页里挂的是 **空壳模板**（`template/animation-template.html`），它的标题是**一句固定文案**；
而旧实现把偏好存成 `od-animation-prefs:` + `document.title` ⇒
**所有题目、所有启动共用同一份记忆，永不过期**。于是"上次停在结尾""上次把图关了"会一直跟着你。

## B. 改法

| 项 | 旧 | 新 |
|---|---|---|
| 存储键 | `od-animation-prefs:<标题>`（跨题共用） | `od-animation-prefs:v2:<启动编号>:<标题>` |
| 启动编号来源 | 无 | `/api/health` 返回（服务进程每次启动生成一个） |
| 时间轴 | 记 `t`、下次恢复 | **不写不读**，每次从 0 开始 |
| 旧记录 | 一直留着 | 启动时**一次性清掉**（只清本前缀；并显式删当前标题那个旧键） |
| 曲线图 | 跟着偏好可能被关 | **默认开**，只认作者显式 `SIM.chart === false` |
| 点播放 | 只在 `t >= duration` 时归零 | **差一帧也算结尾**（按倍速折算约一帧）⇒ 从头重播 |

三栏全显示、动画联动默认勾：**原本就是这样**，本轮不动。

## C. 用户体感（改完）

- 关掉黑窗重开 ⇒ 全新页面：时间轴 0、开关全开、曲线图开着；
- 同一次打开里刷新 ⇒ 你刚调的开关还在（键没变）；
- 你把时间轴拖到结尾再点播放 ⇒ 会**从头重播**（不再假装没反应）。

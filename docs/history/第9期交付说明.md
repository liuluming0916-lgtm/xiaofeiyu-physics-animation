## 4. 覆盖率台账：口径已作废（**0/111 是真相，不是退步**）

`core/worldbook/coverage-target.json` 原本记着"111 个题型各映射到哪条词条"。题型级物理讲义卡按用户目标
退役后，那些 `entryId` 指向了不存在的词条。

`targetFromFile()` **只数 entryId 是否非空、不校验词条是否存在** ⇒ 若不清空，台账会继续显示 111/111，
那是**绿着但没做**。已把失效映射清空，并在文件里写了：

```json
"superseded": { "since": "phase9", "reason": "…题型级卡已退役…", "libraryShape": "10+2+30+5" }
```

门禁 ㉒ 对覆盖率的断言是**推导式**（`contentComplete === (covered >= declared)`），所以 0/111 不会变红，
也不必改断言。**要不要彻底退役这套台账，由产品负责人决定。**

## 6. 判据分级（交接单 §8 落地）

| 检查 | 拦住方式 | 备注 |
|---|---|---|
| C2 / C3 / C5 / C7 | **硬拦** | 未变 |
| C1 | 语法、箭头契约、禁用标识符、`stateAt` 内积分、死循环 → **硬拦**；**孤立的 `unknown-global` → 告警** | 见下 |
| C4 / C6 | **降告警** | `status` 照旧报 fail，只是不再让交付判死 |
| C8 / C9 | 告警 | 未变 |

**C1 怎么拆的**（没有改诊断契约 —— `diagnostic-record.schema.json` 是 `additionalProperties: false`）：

- `core/lint/contract-lint.mjs` 定义 `C1_ADVISORY_RULES = ['unknown-global']`，并在 lint 结果上给出
  `advisoryDiagnostics` / `blockingDiagnostics` 两个计数；
- `core/dryrun/dry-run.mjs` 用它决定 C1 这一条的 `blocking`，并决定"要不要继续执行 + 跑 C3–C9"。

**为什么降级不放松**：`require` / `eval` / `process.x` 还会**另外**命中 `banned-identifier`（硬拦）；
而孤立的笔误若真被执行到 ⇒ 运行期抛错 ⇒ **C2 硬拦**。三条行为都钉在门禁 ㊺（15 → **18 条**）：
未执行到的笔误不拦路、执行到的笔误必拦、`require` 必拦。

> 顺带：旧断言"开发模式放行名单含 C1"用的夹具是"未声明的名字"，分级后它不再拦路 ⇒ 夹具已改成
> 真·硬拦的 `require`（断言本身没收窄）。

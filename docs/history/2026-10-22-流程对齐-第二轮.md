## 0. 先回答：STEPS 现在到底是什么

你的问题：

> 现在的 STEPS 功能是否完全为本地渲染动画时的归一化前置工作？

**答：不完全是。**

当前 `STEPS` 同时被三处使用：

| 用途 | 读什么 | 说明 |
|---|---|---|
| 动画页页签 | `title / tex / t0 / t1` | 本地渲染时把讲解切成「原题 + 第 N 步」 |
| C5 校验 | `t0 / t1` | 检查步骤时间无缝、有序、末步 = 总时长 |
| C6 校验 | `t0 / t1` | 在步骤边界检查位置是否跳变 |

它**不参与** analysis，也不参与 scene_code。
所以它是“本地渲染的归一化数据”，但**同时承担了校验契约**，不是纯展示。

而且现在的 `t0 / t1` 不是“第 1 步对应第 1 个物理段”，而是程序把
`[0, T_phys, 所有段边界]` 排序后**按步数平均取点**。
步数一多，就会出现：

```text
第 1 步 t0=0.00 t1=0.60
第 2 步 t0=0.60 t1=0.60   ← 零长度
第 3 步 t0=0.60 t1=1.70
```

所以“直接恢复联动”会跳错。要先把 STEPS 的定位定清楚。

### 0.1 三种可选定位

- **A. STEPS 只做“讲解的本地渲染归一化”**
  - 只保留 `title / tex`；
  - `t0 / t1` 不再放进 STEPS；
  - C5 / C6 改用 analysis 的段边界；
  - 讲解 ↔ 动画的时间绑定另做一张 `stepTimes` 映射。
  - 最干净，但改动最大。

- **B. STEPS 继续带 `t0 / t1`，但明确它是“步骤时间”**
  - 时间不再平均取点，而是由“耦合”给出；
  - C5 / C6 继续用 STEPS；
  - 联动直接用 STEPS 的 `t0 / t1`。
  - 改动中等，但 STEPS 同时承担“展示 + 校验 + 联动”。

- **C. 折中：STEPS 带 `t0 / t1`，但标记为“展示用”**
  - C5 / C6 改用 analysis；
  - 联动用独立的 `stepTimes`；
  - STEPS 的 `t0 / t1` 只用于页签显示，不参与校验。
  - 兼容旧模板，但会有两份时间，容易漂。

**我建议：A**。
理由：你已经明确“讲解与物理分析解耦”，那 STEPS 就不该再偷偷承担物理时间校验；
让 analysis 负责物理时间，让讲解只负责文字，让“步骤 ↔ 时间”成为一张明确的映射表。

## 1. 动画 ↔ 讲解：到底怎么耦合

### 1.1 联动的方向

- **A**：点第 N 步 → 动画跳到该步开始。

- **D**：其他。

**我建议：C**。

### 1.2 联动的“时间”从哪里来

如果 STEPS 按 0.1-A 降级为纯文字，那么需要一张独立映射：

```text
stepTimes = [
  { step: 1, t0: 0.00, t1: 0.60 },
  { step: 2, t0: 0.60, t1: 1.70 },
  ...
]
```

这张表可以由三种方式产生：

- **A**：analysis 之后加一次轻量“耦合”调用，让模型看着 analysis 给每步标时间。
- **B**：程序按 analysis 的全局段边界，把步骤按顺序分配（第 1 步给第 1 段，步数多就拆/并）。
- **C**：breakdown 生成时就让模型写 `t0/t1`，但那时它看不到 analysis，只能猜。
- **D**：其他。

**我建议：A**。
你之前说“如何完成再议”，这一条就是“如何完成”的核心；先定这个，联动才能落地。

### 1.3 步数 ≠ 物理段数时

- **B**：允许一段拆多步。
- **C**：允许“纯概念步”不跳时间。
- **D**：必须一一对应。
- **E**：其他。

**我建议：A + C**。

### 1.4 多个元件时间段不同，以谁为准

- **A**：全题时间轴（所有段边界并集）。
- **B**：主运动元件。
- **C**：最长元件。

### 1.5 点一步停在哪

- **A**：`t0`（该步开始）。
- **B**：中点。
- **C**：`t1`（该步结束）。

### 2.1 知识卡与页面合并（已实施）

#### A. 产品层 5 类，代码层 kind 只有 3 类

| 类型 | 产品层 | 代码字段 | 是否注入 | 说明 |
|---|---|---|---|---|
| 提示词卡 | `prompt` | 不走 `kind` | ✅ 只在**自己那个阶段** | 底层 `core/prompts` + `ai-rules/prompts` |
| 动画规范卡 | `anim_rule` | `kind: anim_rule` | ✅ 常驻 `scene_code` | 3 张；不叫“流程规范卡” |
| 元件卡 | `element` | `kind: element` | ✅ 按元件命中 | 30 张 |
| 场景卡 | `scene` | `kind: scene` | ✅ 按题型命中 | 当前 0 张，未实现内容 |
| 本地规则卡 | `local_rule` | 不走 `kind` | ❌ 不注入 | `core/cleaner`，模型输出后处理 |

> `knowledgecard` 是“知识卡”的代码名；`worldbook` 是旧称，只留在兼容层 / 历史文档。
> 提示词卡与本地规则卡算知识卡总集，但**不是** `knowledgecard` 条目，所以不写进它的 `kind`。

#### B. 页面

- 导航：**解题 / 动画 / 设置 / 导出**。
- 设置页四个分区：**知识卡 / 提示词卡 / 本地规则卡 / AI 帮写**。
- 原规则页、蒸馏页删除；端点与 Key 仍走右上角 ⚙ 连接设置。
- 知识卡保留：新建 / 编辑 / 保存到本机 / 删除 / 导入并保存 / 恢复本版内置。
- AI 帮写**本轮只做灰置占位**：不调模型、不生成、不自动保存。

#### C. 三张动画规范卡

| id | 标题 | 正文 | order |
|---|---|---:|---:|
| `wb_anim_conventions` | 坐标 / 单位 / 颜色 / 读数 | 1,995 字 | 1 |
| `wb_anim_stages` | 阶段表与状态组织 | 614 字 | 2 |
| `wb_anim_elements_overview` | 30 个元件的最小画法 | 3,260 字 | 3 |

- 全部 `kind: anim_rule`、`constant: true`、`insertion_slot: scene_code`。
- 三张常驻正文合计 **5,869 字**（≤ 10,000；总预算 30,000）。
- 内容修正：删 `Draw.text`、`readouts` 用 `{ key, label, value, unit }`、删 `Phys.format`、visual/anim 去重、
  `wb_anim_stages` 把旧卡的 `STAGES` 修正为真实 `STEPS` 契约。

#### D. 注入顺序

```
该阶段提示词卡（read_problem / solve / steps / answers / scene_code / repair 之一）
  → 动画规范卡（3 张，常驻）
  → 元件卡（按元件命中）
  → 场景卡（按题型命中）
```

- 提示词卡在 system 条件段按阶段取，不拼成一份前缀重发。
- 顺序只对 `scene_code` 有意义；`solve` 阶段没有动画规范/元件/场景卡。
- 实测：`solve` 槽 **0 条 / 0 字**；`scene_code` 按命中注入（样例 7 条 / 7,945 字）。
- knowledgecard 内部排序：`kind`（anim_rule → element → scene）→ `order` → `id`；预算保留也先保动画规范卡。
- 本地规则卡不参与这个顺序（模型输出后运行）。

| 旧 | 新 | 兼容 |
|---|---|---|
| `od-worldbook` 包 | `od-knowledgecard` | 新包写新格式；旧包仍可读，导入时提示 |
| `ai-rules/worldbook/` | `ai-rules/knowledgecard/` | 双读 + 启动复制；旧目录保留 |
| `stageModels.worldbook` | `stageModels.knowledgecard` | 读时改名；`distill` 读时丢弃 |

#### F. 已拍板的取舍

- AI 帮写：本轮只做可见占位，真生成下一版再做。
- `kind`：只允许 `anim_rule | element | scene`；提示词/本地规则卡走各自存储。
- 动画规范卡：**允许停用，但弹确认 + 常驻警告**。
- 端点：接受单模型口径，右上角 ⚙ 是唯一 UI 入口；高级用户可直接改 `ai-rules/endpoints.json`。

## 5. 关键口径（避免重复争论）

1. **图表读数与画布箭头不同源，这是设计。** 图表读 `readouts`（权威数值）；画布 v/a 是运行时对 `SIM.bodies` 求导的演示动画。不要为“一致”改图表来源（C7 依赖 `readouts`）。
2. **v/a 不由模型画。** 模型只在 `VIEW` 声明 `SIM.bodies`；手写 velocity / acceleration 会被过滤，C1 也会拦。`force` / `aux` 仍由模型画。
3. **内置知识卡只读。** 编辑内置卡 = 生成同 id 的 `origin: user` 覆盖副本；「恢复本版内置」只删副本，不删用户自建卡。
4. **每个发布版本自带“恢复本版内置”。** 发行产物读编译期常量（`core/knowledgecard/builtin-bundle.generated.mjs`），不会串版。
5. **发布版没有规则页 / 蒸馏页。** 编辑入口全在设置页；开发期用 `3-OpenRules.bat` 起本机服务。连不上服务时设置页明确显示“只读快照”，不假装能存。
6. **判定只有两态**：`通过` / `未校验`。
7. **画布不写数值**（坐标轴名除外）；颜色是语义（绿=速度、蓝=加速度、红=受力、紫=辅助）。
8. **知识卡是上下文，不是判据。** 它不进 C1–C9；卡坏了改卡，不放宽判据。
9. **真实真题才是质量基准。** 15 道回归题只保证“没退步”。
10. **本期不加 LICENSE。** 仓库当前不是公开仓库；正式上线时再补。

- **硬拦**：C2 / C3 / C5 / C7；C1 里的语法、箭头契约、禁用标识符、`stateAt` 内积分、死循环。

### 6.3 门禁能证明什么、不能证明什么

能证明：确定性夹具下的行为没退步（契约、判据、生成物逐字节、发布形态、HTTP 通道）。
**不能证明**：真实模型在这批题上的成画率。那需要真实真题基线（§4）。

## 10. 维护规则

1. **一个事实只写一处**：版本、门禁步数、卡片条数、页面集合，只写在本文件。
2. 改能力 / 改口径 → 先改本文件，再改面向用户的 docs；历史文档不再回填。
3. 删除任何文件前：先列清单与去向（归档到 `docs/history/` 或 `docs/plans/`），再删。
4. **不要用 `git clean -xdf`**：会删 `ai-rules/keys.json`、`ai-rules/knowledgecard/`、
   `ai-rules/worldbook/`、`data/history.db`、`release/` 与未跟踪的新文档。

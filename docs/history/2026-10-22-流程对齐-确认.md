## 1. 目标阶段链

```text
read_problem
→ solve
→ breakdown ┐
→ analysis  ┘  （并行）
→ scene_code
→ dry_run
→ repair（只在需要时）
→ couple（只在最终有可播放程序时）
→ run_done
```

- `breakdown` 与 `analysis` 并行；`scene_code` 等两者都完成。
- `couple` 是**可见阶段**，中文“步骤耦合”，在最终校验/修复之后、交付之前跑一次。
- `couple` 用 `scene_code` 端点。
- 本期**不改动进度条 UI**；后台并行，界面仍线性显示。

## 2. STEPS 的定位

### 2.1 只留 title / tex

`STEPS` 降级为**本地渲染的讲解归一化数据**：

```text
title: 第 1 步
tex: 这一步讲什么

title: 第 2 步
tex: ...
```

不再包含 `t0 / t1`。

### 2.2 C5 / C6 改读 analysis

- **C5**：只检查 `VIEW.duration` 是否等于 `analysis.T_phys`（±容差），并确认 `T_phys > 0`。
- **C6**：在 `analysis` 的每个段边界 ±ε 检查位置连续，不再看 STEPS 边界。
- 旧的 STEPS 时间字段如果出现在老数据里，按“忽略”处理，不参与新校验。

### 2.3 页签

- 页签只显示 `title / tex`。
- 删除页签下面的 `t ∈ [..]` 秒数显示。

## 3. 并发

### 3.1 范围

- `breakdown` 与 `analysis` **真正并行**。
- `scene_code` 等两者都完成再开始。
- `read_problem` 与 `solve` **不并行**（读题判定要触发知识卡）。
- 本期不改进度条 UI。

### 3.2 失败

- 一边失败：**保留另一边结果**，再报错；不立即取消。
- 如果 `breakdown` 失败但 `analysis` 成功：没有 STEPS，程序不能交付；整题报错。
- 如果 `analysis` 失败但 `breakdown` 成功：保留讲解文本，整题报错（没有动画）。

## 4. 动画 ↔ 讲解联动

### 4.1 对象

耦合的是**动画与讲解**，不是分析与讲解。
`analysis` 只提供物理时间轴，不读讲解。

### 4.2 方向

- 点第 N 步 → 动画跳到该步开始（`t0`）。
- 播放 / 拖时间轴 → 自动选中当前步。
- 恢复“动画联动”开关，**默认开启**。

### 4.3 步骤时间来源

- 由 `couple` 阶段调用模型，看 `analysis` 表 + `breakdown` 步骤，给每步标时间。
- `couple` 在**最终校验之后**跑；如果物理修复改了 analysis，必须重新跑 `couple`。
- `couple` 失败：**重试一次**；仍失败则按程序比例分配 + warning，不静默。

### 4.4 couple 的触发条件

- `pass` / `pass-with-warnings` → 跑。
- `fail` 但 `delivery.playable === true` → **也跑**。
- `fail` 且没有可播放动画（槽位不齐 / 无法装配）→ **跳过**。
- 跳过时不产出 `stepTimes`，页签只换文字、不跳动画；仍然带横幅交付。

### 4.5 stepTimes 结构

作为 `program` 的**附加字段**，不新增第 9 个槽位：

```js
program.stepTimes = [
  { step: 1, t0: 0.0, t1: 0.6 },
  { step: 2, t0: 0.6, t1: 1.7 }
]
```

规则：

- 只记录“有时间区间”的步骤；纯概念步可省略。
- 按 `step` 升序。
- 不重叠。
- 落在 `[0, T_phys]`。
- **不要求覆盖整段 `[0, T_phys]`**。
- 多个元件时间段不同：以全题时间轴（所有段边界并集）为准。

## 5. 知识卡

### 5.1 名字

- 界面统一叫**知识卡**；“世界书”是早期叫法，要清掉。
- 代码内部仍叫 `knowledgecard`（不为了改名动契约）。
- 知识卡是**总称**，保留现有分栏：
  - 知识卡 v2（元件 / 规范 / 场景）
  - 提示词卡
  - 本地规则卡

### 5.2 删 solve 槽

- `KNOWLEDGECARD_INSERTION_SLOTS` 从 `['solve','scene_code']` 改为 `['scene_code']`。
- 引擎、导入导出、UI、测试里的 `solve` 槽分支全部删除。
- `solve` 阶段不再触发知识卡。

### 5.3 旧卡迁移

- 元件卡 / 场景卡 → 迁到动画槽（`scene_code`）。
- 纯解题知识卡 → **停用**，不迁（挂到动画槽会污染画图上下文）。
- 迁移时记 warning，不静默。

### 5.4 concepts / tags

- **字段删除**：从契约、读题输出、事件、UI、测试里删掉。
- 读题只判 `elements / scenes`。
- 旧用户卡里如果还有 `concepts / tags`，迁移时剥离并记 warning。

## 6. 读题标题

- `read_problem` 新增一行：

```text
【题目标题】...
```

- 模型给什么标题就用什么，**不按 10–24 字强行打回**。
- 只有模型没给 / 给空串 → “未命名题目”。
- 纯文字题也走模型标题，不用程序截第一句。
- 只用于：
  - 动画页标题；
  - 导出文件名。
- **不进入** analysis / scene_code 的上下文。
- 导出文件名另做文件系统安全处理（去非法字符、必要时截断），但不改标题本身。
- 标题失败不中断整题。

## 7. 修复段

### 7.1 两类错误

- **画图错误**：诊断指向 `drawFrame`，或 C4/C8/C9。
  - 只重画 `drawFrame`。
  - 最多 3 轮。
- **物理错误**：诊断指向 `stateAt / setup / VIEW`，或 C3/C5/C6。
  - 重跑 `read_problem + solve + analysis + scene_code`。
  - `breakdown` 跟着重新生成。
  - 重新跑 `couple`。
  - 最多 2 轮。

### 7.2 归类

- 先看诊断的 `slot`：
  - `drawFrame` → 画图
  - `stateAt / setup / VIEW` → 物理
- C3 / C5 / C6 默认物理。
- C1 看诊断指向哪个槽位。
- C2 看崩溃堆栈落在哪个槽位。
- 无法归类时按物理处理（宁可多算一次，不要用画图修复去修物理）。

### 7.3 交付

- 修复失败仍按 `delivery.playable` 决定是否交付。
- 有可播放程序 → 交付 + 横幅；没有 → 报错。
- 物理修复后必须重新耦合，不能沿用旧 `stepTimes`。

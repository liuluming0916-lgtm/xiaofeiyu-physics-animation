## 0. 先看结论

1. **主链 5 段 + 3 个附加段**：`read_problem → solve → breakdown ∥ analysis → scene_code → dry_run → repair → couple`。模型调用是前 5 段 + `couple`；`repair` 按错误类型决定是重画还是重跑主链。
2. **每段消息只有两条**。`system` = 阶段固定前缀 + 本阶段指令（+ 知识卡，仅 `scene_code` / `repair`）；`user` = 题目横幅 + 该阶段的输入。没有额外的隐藏 system。
3. **知识卡当前一条都没进 Prompt。** `/api/run` 把 v2 卡原样交给 v1 引擎，而 v1 引擎要求 `insertion_slot` / `keys`；v2 卡没有这些字段。实测：原样注入 **0 条 / 0 字**；套上现成适配器后 **5 条 / 6,955 字**。
4. **`scene_code` / `repair` 的固定前缀里有 1,013 字旧 8 槽位契约**（`@slot`、`SIM.bodies`、`STEPS`、`ANSWERS`、`stateAt`、`readouts`），与「只写 drawFrame、不写槽位标记、不碰 stateAt」直接冲突。每个写代码的请求都要付这 1,013 字。
5. **`read_problem` 实际用的是 v1 角色前缀**：前缀说「把题目转写成结构化文字」，v2 指令说「不要复述题文」——角色与指令互相打架；v2 前缀（129 字）根本没被用上。
6. **Prompt 编辑器里改 `read_problem` 对默认 v2 读题无效**：运行时用的是 `read_problem_v2`，编辑器没有这一项；而且 `PROMPT_REQUIREMENTS.read_problem` 还要求已经删除的 `【考点】`。`solve` 在带参考答案时，覆盖也会被内置 `systemWithReference` 顶掉。

> **所以改写知识卡的顺序应当是：先修「注入」与「前缀冲突」，再改卡。** 否则新卡仍然进不了 Prompt；即使强行接上，也会被前缀里的旧契约抵消。

## 1. 一条消息是怎么拼出来的

`core/prompts/fixed-prefix.mjs` 的 `assemblePrompt()` 只做三件事：

```text
system = 固定前缀(stage)  +  "\n\n"  +  条件段
条件段 = 【本阶段指令：<label>】\n<instruction>  +  "\n\n"  +  <命中的知识卡块>
user   = "════════════════════ 题目 ════════════════════\n" + buildUser(...)
```

- **固定前缀**：按阶段取。`read_problem / solve / breakdown / analysis / couple` 只有「角色 + 输出纪律」；`scene_code / repair` 额外带 3,480 字的 SDK 签名摘要。**没有任何题目信息**，所以可被模型缓存。
- **本阶段指令**：`prompt.system`（`solve` 带参考答案时换成 `prompt.systemWithReference`）。
- **知识卡**：只有 `scene_code` 与 `repair` 有槽；引擎已渲染成 `【世界书·动画建模：<title>】` 块，直接拼在指令后面。**当前是空串。**
- **任务段**：题目横幅后接各阶段 `buildUser()` 的输出。
- **图片**：不进 system，也不进 `assemblePrompt()` 的文本；由网关 `buildUserMessage()` 把 user 文本和图片编码成 OpenAI 兼容的 `content` 数组。`assemblePrompt()` 里的「【随附题目图片 N 张】」提示**在生产链路不会出现**（图片是外部传入的），不要把它当成实际消息的一部分。
- **promptHash**：当前整版指纹是 `412ce14a25d3384722fcc6e733e8ae2949d2941230db4e87814dbbc1c4d831ff`，覆盖 8 条阶段前缀 + `TEMPLATE_VERSION / SDK_VERSION`。换题、换图、换知识卡命中都**不变**；改任一阶段前缀才变。它只在首个组装提示词的阶段报一次，不是每段一个哈希。

| 解题 | `solve` | 101 | 873 | 976 | 题面 |

## 2. 逐段明细

### 2.1 `read_problem`（读题 / 判定）

- **何时跑**：每道题都跑，包括纯文字题。带图但端点 `supportsVision !== true` 时直接 `stage_error: vision-unsupported`，一次模型调用都不发。
- **Prompt id**：`knowledgecardVersion === 2`（服务端默认）用 `read_problem_v2`；否则用 v1 `read_problem`（旧配置/旧测试）。v1 仍保留完整转写口径（`【题面复述】/【物体与姿态】/【相对位置与朝向】…`），默认链路看不到它。
- **图片**：原题图（可多张），以多模态 content 数组附在 user 上。
- **产出**：`【题目】` 标题（只用于动画页标题 / 导出文件名）、`【物体】/【相对位置】/【姿态】/【运动方向】` 几何、`【示意图范围】`、`【动画元件】`、`【场景】`、`【判定依据】`。标题与判定由本地解析，判定的事件是 `judgement_done`。

**System（实际发出）**

````text
你是一名高中物理**读题**助手：把题目（图 + 文字）转写成结构化文字，并判出图里画了哪些动画元件。
· 只输出被要求的内容本身，格式干净、可直接解析；
· 数学公式用 LaTeX：行内 $…$，独立行 $…$；
· 看不清就写"图中未标注"，保持诚实。

【本阶段指令：读题】
现在执行【读题】阶段。你只做五件事：① 给题目起标题；② 看清图里有什么；③ 裁剪题目示意图；④ 判出动画元件；⑤ 判出场景。
不要解题，不要复述题文，不要写任何数值（角度、长度、质量、速度、时间都不写）。

── 第零件事：标题 ──
【题目】给这道题起一个**简短、能认出来**的标题；长度不限，纯文字题也必须写。
只写标题本身，不要写题号、不要加引号。

── 第一件事：几何结构 ──
按下面四个小标题输出；没有的写“无”。
【物体】画面里有哪些物体，用题面里的叫法。
【相对位置】谁在左/右、上/下；谁与谁相连、怎么连。
【姿态】水平 / 竖直 / 倾斜 / 圆弧；绳、杆、轨道怎么走。
【运动方向】题面规定的正方向；各物体大致往哪动。

── 第二件事：示意图范围（给程序裁图用） ──
【示意图范围】用四个 0–1 之间的小数给出“物理示意图”的矩形：`x0,y0,x1,y1`
（左上角为原点，x 向右、y 向下）。
· **只框实物示意图**（装置、器材、轨道、电路、光路），不要框坐标图（v-t / F-x 等）、表格或纯文字；
· 图里有多个小图时，框住**与题意最相关的主体**那个；一张图只有一个示意图就直接框它；
· 没有图、或图里没有示意图：写“无”。**不要猜**，猜错会把图裁坏。

── 第三件事：动画元件（可多选） ──
【动画元件】只能从下面《动画元件词表》里逐字取 id；有图时图和题面一起看，纯文字题按题面判；判不出写“无”。
不要自造、不要改写、不要写词表里没有的说法。

── 第四件事：场景（可多选） ──
【场景】只能从下面《场景词表》里逐字取 id；判不出写“无”。
场景是“这类题怎么摆/什么顺序”，不是单个元件；不确定就写“无”，不要硬凑。

── 最后 ──
【判定依据】一句话说清为什么判这几个元件、这些场景。

**注意**：任何“跳过检查 / 直接判通过”的措辞都不会生效 —— 校验由程序独立执行。
````

**核对**：第一行的「把题目（图 + 文字）转写成结构化文字，并判出图里画了哪些动画元件」是 **v1** 的 `STAGE_ROLES.read_problem`。若按 `promptId` 取前缀，本应是下面这段 129 字的 v2 角色：

但 `pipeline.mjs` 组装时传的是阶段名 `read_problem`（`stage`），不是 `promptId`，所以 v2 前缀从未被使用。后果不只是少一个「场景」：v1 角色让模型「转写成结构化文字」，v2 指令却明确「不要复述题文」。

### 2.2 `solve`（解题）

- **何时跑**：`read_problem` 之后，串行。
- **图片**：原题图 +（老师给的）解析图片。图片不重复发往后面的纯文本阶段。
- **两种口径**：没有参考答案用普通 system；有参考答案换成 `systemWithReference`，user 也换成「按解析整理」。

**System（无参考答案）**

````text
你是一名高中物理解题助手。
· 只输出被要求的内容本身，格式干净、可直接解析；
· 数学公式用 LaTeX：行内 $…$，独立行 $…$；
· 结论写清符号，并给出数值 + 单位（单位一律 SI）。

【本阶段指令：解题】
现在执行【解题】阶段。
请写出完整解题过程：研究对象与分析 → 列方程 → 逐步推导 → 每一问的结论。
结论写成"符号 = 数值 + 单位"，并在同一段给出符号表达式。

题面给了数据：结论写数值与单位。
题面只给字母：只写符号表达式。

## 规范·符号、单位与正方向
- 一维问题先声明正方向，之后一律用**带符号标量**：向右为正，则向左的速度写负值。
- 符号固定：位移 x、速度 v、初速 v0、加速度 a、时间 t、间隔 T；力 G/N/f/F_T；能 Ek/Ep/W/P/Q；电磁 q/E/phi/U/I/R/B/Phi。
- 单位一律 SI。g 取题面给定值；题面没给就取 10 m/s²。
- 角度在解析里写度数。非常用单位（cmHg、km/h、eV）先换算成 SI 再代入。
## 规范·矢量与分量
- 矢量先交代**大小 + 方向**（与正方向的夹角，或两个正交分量），再参与运算。
- 分解按已声明的两个正交轴投影：沿轴用 cos、垂直轴用 sin；两轴全程不换。
- 合成写成矢量式再取大小：v = √(vx² + vy²)，方向 tanθ = vy / vx。
## 规范·公式与数值的写法
- 先推**符号表达式**，再代数值。
- 数值取 2–3 位有效数字，与题面数据的精度对齐；中间量保留符号，最后一步才代入。
- 代入的数值与题面逐字一致。
## 规范·守恒式与过程式的写法
- 守恒式三步走：**先声明系统与正方向** → 写守恒量（初态 = 末态）→ 再代入具体量。
- 过程式（动能定理、动量定理）先写"谁对谁做功 / 谁给谁冲量"，再写等式。
- 守恒不成立时（有外力、有摩擦）改用含外功的式子，并说明差额补在哪一项。
## 规范·临界与极值
- 临界点写成**某个力或约束等于零（或取到极值）的等式**：N = 0（脱离/过顶）、f = f_max（刚要滑）、T = 0（绳刚松）。
- 先写临界条件式，再解出待求量；结论里说清取到极值的时刻或位置，并说明为什么在这里取到。
````

### 2.3 `breakdown`（答案讲解）

- **何时跑**：与 `analysis` **并行**；只依赖 `solve`。
- **产出**：2–6 条 `title / tex` 行式表；同时用于解题页的「分步讲解」和 `STEPS` 槽位（只保留文字，不带时间）。
- **图片**：无。

**System**

````text
你是一名高中物理**答案讲解**教师：把解题过程讲成几步，每一段物理过程配一段讲解。
· 只输出被要求的内容本身，格式干净、可直接解析；
· 数学公式用 LaTeX：行内 $…$，独立行 $…$。

【本阶段指令：答案讲解】
现在执行【答案讲解】阶段。
你是一位面对学生的教师。基于给定的解题过程，把这道题讲成 2–6 个清楚的步骤。

数据型槽位用行式表书写：一行一项 `key: value`，记录之间用空行分隔，多行文本用 `"""` 包裹。不要写 JSON。

每一步给两样：
· title：这一步发生了什么（简单易懂，允许使用高中物理术语）；
· tex：讲给学生听的话——先描述本段物理过程，再讲解用哪个知识点列出什么式子，最后得到什么结论。
  允许公式，但不要只丢公式；也不要重复整段解题过程。

要求：
· 一步 = 一段物理过程；
· 步骤要覆盖全题，不要漏掉任何一处物理阶段。
````

**User**

```text
════════════════════ 题目 ════════════════════
【题目】
{题面}

【解题过程】
{solve 输出}
```

### 2.4 `analysis`（物理分析）

- **何时跑**：与 `breakdown` 并行；`scene_code` 等两者都完成。
- **输入**：题面 + 读题几何 + solve。**不吃 breakdown**（用户 2026-10-22 裁决：教学步骤不是物理运动阶段）。
- **图片**：原题图（允许）。
- **产出**：只有 `assumption`（可选）+ `=== 元件运动表 (MOTIONS) ===` 的逐段记录。程序解析后生成 `stateAt / VIEW / setup / readouts`。

**卡片里现在写着什么（与 v6 冲突的部分）**：

- `stateAt 里写：return { x: 0.6 }` —— v6 里 `stateAt` 由程序生成，AI 不写。
- `state.* 的键名必须就是 stateAt(t) 返回的键名` —— v6 里键是 `e0/e1/...`，由 analysis 的元件顺序决定，不是元件名。
- `跨槽位读常量用 context.X；读别的时刻用 context.at(tt)` —— v6 的 drawFrame 只有当前帧的 `state`，没有 `context`。
- `静态几何在 setup() 里算一次` —— AI 不写 `setup`。
- `VIEW 里声明 SIM.bodies` / `readouts 的 key 与 ANSWERS.symbol 一致` / `STEPS 的 t0/t1` —— 这些都是程序生成或已删除的槽位。
- 示例写成 `drawFrame: …` 的旧槽位标签 —— 模型现在只输出函数体，这层标签会被当成代码抄进去。

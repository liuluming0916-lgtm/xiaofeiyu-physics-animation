# v1.1.17 发布说明

> 发布时间：2026-10-23
> 基线：v1.1.16（参考答案 / 解析 + 拆图）
> 性质：**生成链重构 + 时空归一 + 内容换代**。原计划的“按真题重写卡 / 3 题 + 10 题 A/B”
> 没有按原样执行；v1.1.17 先把链路换成 v6，再用 3 道真实题验收。

---

## 1. 这一版做了什么（一分钟版）

1. **模型只写 `drawFrame`**：`stateAt / VIEW / setup / readouts / STEPS` 由本地物理分析生成，
   模型不再有机会把运动写错。主链变成：
   `read_problem → solve → breakdown ∥ analysis → scene_code → dry_run → repair → couple`。
2. **画面固定 10 × 6 舞台**：相机永远拍同一张纸，元件用固定布局尺寸；
   0.4 m 的物块在 11 m 宽的题里不再缩成 19 px。
3. **每小问固定 4 秒**：`couple` 给步骤标小问号，时长按小问归一；极端题用倍速调。
4. **步骤与动画联动**：点「第 N 步」跳时间；拖时间轴自动选中当前步；时间码按步显示。
5. **修复分流**：画图错只重画 `drawFrame`（≤3 轮）；物理错重跑主链（≤2 轮）；混合先修物理。
6. **知识卡换代**：v1 弃用；31 张 v2 卡（11 元件 + 18 场景 + 2 规范）接手，只注入动画槽。
7. **3 道真实题**：q04 候选、q06 / q09 人工验收通过。

## 2. v6 主链

| 阶段 | 谁跑 | 产出 |
|---|---|---|
| `read_problem` | 模型 | 题面转写 + `【题目】` + `【动画元件】` + `【场景】` + 几何转写 + 示意图框 |
| `solve` | 模型 | 解题过程（有教师解析时按解析整理） |
| `breakdown` | 模型 | 分步讲解（`title / tex` 行式表，**不带时间**） |
| `analysis` | 模型 | 物理分析表（每段 `x(t)/y(t)` + 锚点 + `sub`） |
| `scene_code` | 模型 | **只写 `drawFrame`** |
| `dry_run` | 本地 | C1–C9 + Worker 沙箱 |
| `repair` | 模型（未通过才跑） | 分类修复 |
| `couple` | 模型（交付前） | `stepTimes = [{ step, t0, t1, sub }]` |

### 2.1 程序形状没变，产出面变了

- 仍是 8 个槽位：`PROBLEM / STEPS / ANSWERS / VIEW / setup / stateAt / drawFrame / readouts`。
- `ANSWERS` 保留为空串（兼容形状）；`STEPS` 只留 `title / tex`。
- `VIEW / setup / stateAt / readouts / STEPS` 由 `core/analysis/generate.mjs` 生成。
- 表达式用“段锚点增量”：`x0 + vx0*(t - t0) + 0.5*ax*(t - t0)^2`；
  `t0/x0/y0/vx0/vy0` 由生成器原样代入；`^` 与 `**` 都认；裸函数名自动补 `Math.`。
- `kind: ode` 明确拒绝（ODE 没接）。

### 2.2 取消 / 并发 / 快照

- `breakdown` 与 `analysis` 并发；事件边到边推；`scene_code` 等两边都完成。
- 单边失败保留另一边结果，整题如实报错。
- 每题一份配置快照（Prompt / 端点 / 清洗规则 / 卡片 / 词表），跑动中改配置只影响下一题。

## 3. 舞台与时长

### 3.1 10 × 6 固定舞台

- `core/stage/frame.mjs`：从 analysis 估世界包络 → 保比例折进 10×6 纸。
- 三层坐标：物理 `x/y`（米）→ 布局 `u/v` → 元件 `cu/cv/w/h`（布局单位，固定尺寸）。
- `contracts/element-geometry-v2.json`：元件几何表（`w/h/r/minPx/rotatable`）。
- 有 `SIM.stage` 时，`drawFrame` 用 `state.*.x/.y` ⇒ C1 `physical-coord-in-draw` 硬拦。
- **版面骨架不做**：只保留 `auto_stage` 一条（用户裁决：过度工程）。

### 3.2 每小问 4 秒

- `core/timing/display-time.mjs`：同一 `sub` 的步骤取 `[min t0, max t1]`，
  映射到 `[4(k−1), 4k]`；写出 `timeMap / displayDuration / stepTimes`。
- 播放器内部仍是物理秒；时间轴、时间码、步骤跳转、播放推进、图表横轴用显示秒。
- **图表横轴仍是真实物理秒**（用户裁决）。
- 时间轴不显示秒，时间码「第 k / n 步」；倍速 6 档 + 自定义 `0.1–20×`。
- 老产物没有 `timeMap` ⇒ 恒等，行为与之前一致。

### 3.3 步骤耦合（couple）

- 提示词只输出 `step / t0 / t1`（以及小问号 `sub`）；
- 纯概念步可省略，不要求覆盖整段；
- 模型失败重试一次，仍失败按步骤均分回退 + warning；
- 前端「动画联动」默认开：点步骤跳 `t0`，播放/拖时间轴自动选中当前步；
- 导出页、宿主注入都带 `stepTimes`。

## 4. 修复与校验

| 失败类型 | 判据 | 动作 | 上限 |
|---|---|---|---|
| 画图错误 | C4 / C8 / C9，或 C1/C2 诊断落在 `drawFrame` | 只重画 `drawFrame` | 3 轮 |
| 物理错误 | C3 / C5 / C6，或诊断落在 `stateAt / setup / VIEW` | 重跑主链 | 2 轮 |
| 混合 | 同时命中 | 先修物理 | — |
| 未收敛 | 轮次用完 | 带告警横幅交付，verdict 如实 | — |

- `STEPS` 降级为 `title / tex`；C5 改为 `VIEW.duration == T_phys`；C6 改查 analysis 分段边界。
- C7 不再要求“答案在某时刻读数”（`ANSWERS` 为空）。
- 接线对账仍并入 C1：`stateAt` 提供、`drawFrame` 消费的键必须对得上。

## 9. 首包撤回与修复（2026-10-23 晚）

首包（`app.asar` 59.3 MB / 3401 文件）在用户机器上启动即退出，诊断脚本记录：

- `[2/4] headless selftest` → **exit -1073741819（0xC0000005）**；
- `[3/4] normal launch` → 进程不驻留；
- 连接设置：**未知阶段 `answers`** / **端点文件已被外部修改**。

### 9.1 根因一：原生模块 ABI 不兼容（崩溃）

`better-sqlite3 13.0.3` 的预编译产物要求 **Node-API 10**；Electron 33 内嵌 Node 20.18
只支持 **Node-API 9**。`require('better-sqlite3')` 在原生层直接 0xC0000005，
**不是可 catch 的 JS 异常**，所以 `try/catch` 拦不住。

修法：`core/history/index.mjs` 在 require **之前**检查 `process.versions.napi`；
小于 10 就不加载驱动，`history.driver-missing` 如实报出。应用其余部分（解题/动画/导出）不受影响。
要恢复账本：升级 Electron 35+（Node 22 / N-API 10），或换 N-API 9 的 better-sqlite3 产物。

### 9.2 根因二：旧用户配置的阶段名（打不开 / 保存冲突）

v6 把 `answers / steps` 换成 `analysis / breakdown`，但用户 `%APPDATA%` 里的
`endpoints.json` 仍是旧键 ⇒ `loadEndpointStore` 报 `unknown-stage`；
前端拿不到 `hash`，保存时 `expectedHash: null` ⇒ 又被判成"文件已被外部修改"。

修法：`core/gateway/legacy-stages.mjs` 增加 `answers → analysis`、`steps → breakdown` 的读时迁移
（保存时写回新键）；旧配置**不用手工改**。

### 9.3 根因三：冒烟测试假绿

`electron-repack` 的 `--selftest` 子进程继承了 `ELECTRON_RUN_AS_NODE=1`，
Electron exe 按 Node 运行、无参数直接 exit 0；冒烟只看退出码，于是"绿着但没启动应用"。

修法：冒烟前 `delete env.ELECTRON_RUN_AS_NODE`，并**必须读到 `od-selftest.txt`**；
再校验 `worker=true / index=true / payload=app.asar`（账本降级只告警）。
`electron-pack` 同步修复。

### 9.4 修复后的状态

- 应用能启动，解题 / 动画 / 导出正常；
- 账本与审计降级（无 UI 入口，不影响主流程）；
- 旧 `answers / steps` 端点配置自动迁移，连接设置可以正常保存；
- 发布包以同一版本号 **v1.1.17** 重新打包（首包未对外分发，已撤回）。

**重新打包时的实测**：

- `--selftest`：`health ok` / `index=true` / `worker=true` / `payload=app.asar`，退出码 0；
  `history=false` 并带 `history.driver-missing`（预期降级，只告警）；
- 用用户真实 `endpoints.json` 的副本启动：`GET /api/endpoints` → 200，
  `answers/steps` 自动迁移成 `analysis/breakdown`，`hash` 正常返回；
- 同一份配置 `PUT` 保存成功（`expectedHash` 对得上），重载后旧键已不落盘；
- 包：`app.asar` 59.3 MB / 3401 文件，绿色版 343.4 MB，zip 132.6 MB。

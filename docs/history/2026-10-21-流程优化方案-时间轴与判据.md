# 流程优化方案：让时间轴从物理里来

> 状态：**方案，未动手**
> 日期：2026-10-21
> 起因：力学基准跑里，同一道题三次给出两套答案；全开那版段内速度下陷（2.0 → 1.5 → 3.0）；
> 用户判断：现在的「分步解析 + 答案抽取」长不出好动画。

---

## 0. 一句话

**现在的时间轴是从讲解里抄的，不是从方程里解出来的。**
把"时刻"变成一等公民（由代码解、可校验），动画、答案、判据三方才可能自洽。

## 4. T0：收紧契约（不动阶段数量）

### 4.1 契约字段

`STEPS` 每步增加两个字段（**只加不改**，旧消费方用 `.find()` 不受影响）：

```
step1_event: 共速(v=传送带速度 2.0)
step1_t_expr: """由 v_0 + a_1 t = v_带 解得 t=1.0"""
step1_t0: 0
step1_t1: 1.0
```

- `event` 只允许枚举的几类：`共速` / `静止` / `到位` / `接触-分离` / `碰撞` / `落地` / `入场`；
- `t_expr` 必须写"由哪个方程解出"（LaTeX 或一句话），**没有方程的时刻不予受理**；
- 原有 `t0/t1` 保留，供 C5 使用。

### 4.2 新增判据 C10「事件时刻自洽」（先告警，不阻塞）

在每步边界 `t_i` 调 `stateAt(t_i)`，按事件类型比对：

| 事件 | 判据 |
|---|---|
| 共速 | `abs(v(t_i) − 声明值) ≤ tol` |
| 静止 | `abs(v(t_i)) ≤ tol` |
| 到位 | `abs(x(t_i) − 声明值) ≤ tol` |
| 接触-分离 | `abs(N(t_i)) ≤ tol`（要求 state 暴露 `N`） |

容差取 `max(1e-3, 0.5% × 量级)`。要求 `state` 至少暴露 `x` 与 `v`；没有则不判，记 `skipped`。

### 4.3 新增判据 C10b「段内速度不塌陷」（告警）

每段在 `t0 + 5%..95%` 采 9 个点，若中段速度比两端**低 5% 以上**，记一条：
"第 k 段中段速度低于两端（2.00 → 1.50 → 3.00），疑似用样条凑点"。
——只告警，先收集一周数据，再决定是否阻塞。

### 4.4 提示词改动（三处）

1. `steps`：把"时间锚点对准事件"升级为"**每个 t1 必须由一个方程解出**，并把方程写进 `t_expr`；写不出方程的步骤说明它不是独立阶段，合并"。
2. `answers`：`at_t` **只能取 STEPS 里出现过的事件时刻**，不许另填。
3. `scene_code`：加一条**正向**规则——"每一段用匀变速解析式：给定 `x0, v0, a`，位置由 `x0+v0Δt+½aΔt²` 算；**不要手填两端速度做平滑曲线**"。

> 注意：这一条要写在"一页范例"附近，并用范例代码示范；只写一句禁令等于没写。

### 4.5 T0 验收

- 15 题回归全绿（C10 为告警时允许有告警，但**判定不许变**）；
- 力学题重跑 3 次：`t_expr` 覆盖 100%，C10 告警数记录在案；
- 同题 3 次答案是否收敛，作为"是否值得上 T1"的依据。

## 5. T1：运动模型表（结构性）

### 5.1 数据流

```
solve（文字解析，不变）
  └─ kinematics（新阶段，替代 steps 里的"填时间"）
       输出 phases：
         [{ id, 描述, a: "-20x/5" 或常量, v0, x0, t0: 由代码算, end_event }]
  └─ timeline（确定性代码，不调模型）
       解 t：v(t)=v0+a t、x(t)=x0+v0t+½at²，解出每段 t1；
       校验：段末 v 与下段 v0 一致；总时长 = 末段 t1
  └─ steps（只写讲解，t0/t1 由 timeline 注入）
  └─ answers（at_t 只从 timeline 的枚举里取）
  └─ scene_code（stateAt 由 phases 表模板化生成，模型只写 drawFrame）
  └─ dry_run（C11 逐段比对）
```

### 5.2 `stateAt` 模板化（关键）

不再是模型写自由代码，而是由表生成：

```js
// 由 phases 表自动生成，模型不许改
function stateAt(t) {
  const p = phaseAt(t);
  const dt = t - p.t0;
  return { x: p.x0 + p.v0*dt + 0.5*p.a*dt*dt, v: p.v0 + p.a*dt, ...p.extra };
}
```

模型的自由度收缩到三处：`a` 的表达式、每段的 `drawFrame`、以及附加状态（T、f、N）。
**速度、位置、加速度从此三者天然一致**，段内不可能再下陷。

### 5.3 C11「运动模型自洽」（阻塞）

- 每段：`stateAt` 与表中的 `x0/v0/a` 逐点比对（相对误差 ≤ 0.5%）；
- 段末 `v` 与下段 `v0` 一致（≤ 1e-6 相对）；
- 表里声明的 `end_event` 在该段末成立（同 C10 的算法）。

### 5.4 T1 的风险

| 风险 | 应对 |
|---|---|
| 模型不会填表 | 给"填表示例"（改造现有 golden example，比散文提示有效） |
| 非匀变速段（弹簧、变力） | 允许 `a` 为表达式，用 `Phys.integrate` 数值积分；表中标注 `a_kind: "expr"` |
| 旧题回归被打回 | C11 先只对"声明了 phases 表"的题生效；旧题走旧路径 |

## 6. T2：状态量答案（1.1.18）

现在 ANSWERS 是"考试形态"（符号 + 最终数值），动画需要的是"状态量"（x/v/T/f 随时间）。
做法：

- ANSWERS 增 `state` 字段：`{ symbol, expr }`，如 `{"symbol":"v_A","expr":"v0+a*t"}`；
- C7 从"该时刻读数=答案"升级为"该时刻读数 = 状态量表达式求值"，并保留最终答案对照；
- 答案抽取阶段同时输出"符号解"与"数值解"，两者在 `at_t` 必须互相印证。

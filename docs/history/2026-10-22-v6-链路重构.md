# 2026-10-22 · v6 链路重构归档

> 本日把动画生成链从旧 5 段重构为 v6，并完成步骤耦合、两类修复、读题标题。
> 运行链路的知识卡最后收口为**只注入动画槽**；旧卡数据迁移按用户决定暂缓，等卡片重写时一起做。

## 最终链路

```text
read_problem → solve → breakdown ∥ analysis → scene_code
→ dry_run → repair → couple → run_done
```

模型阶段：`read_problem / solve / breakdown / analysis / scene_code`；`couple` 是交付前的最后一次模型调用。
`dry_run` 是本地沙箱；`repair` 按错误类型分支。

## 本日完成

### 1. STEPS 降级

- `STEPS` 只保留 `title / tex`，不再携带时间。
- C5 改为 `VIEW.duration == T_phys`。
- C6 改为检查 analysis 的分段边界。
- 旧 STEPS 时间只做旧数据兼容。

### 2. breakdown / analysis 并发

- 两阶段同时发起，事件边到边推。
- `scene_code` 等两边都完成。
- 单边失败保留另一边结果，整题如实报错。

### 3. couple（步骤耦合）

- 新增 `core/prompts/couple.mjs`、`core/couple/parse.mjs`。
- 产出 `program.stepTimes = [{ step, t0, t1 }]`。
- 纯概念步可省略；不要求覆盖整段。
- 模型失败重试一次；仍失败按步骤均分回退 + warning。
- 前端「动画联动」默认开：点步骤跳 `t0`，播放/拖时间轴自动选中当前步。
- 导出页、宿主注入都带 `stepTimes`。

### 4. 修复分两类

- 画图错误：C4 / C8 / C9，或 C1/C2 指向 `drawFrame` → 只重画，最多 3 轮。
- 物理错误：C3 / C5 / C6，或指向 `stateAt / setup / VIEW` → 重跑
  `read_problem + solve + breakdown/analysis + scene_code`，最多 2 轮。
- 混合先修物理；物理没修完不空转重画。

### 5. 知识卡运行链路

- 运行链路只注入 `scene_code`；`solve` 不再触发知识卡。
- 解题页知识卡面板只显示动画槽。
- **没有停用任何卡**：动画规范卡、元件卡、场景卡都保留。
- 旧 v1 数据里的 `solve / concepts / tags` 字段暂留，仅兼容；当前链路不读。
- 用户决定：卡片本来要重写，现在迁移等于无用功，暂缓数据迁移。

### 6. 读题标题

- `read_problem` / `read_problem_v2` 都要求输出 `【题目】`。
- 标题长度不限；本地不截断。
- 缺失 / 空 / 只写“无” ⇒ `未命名题目`。
- 纯文字题也采用模型标题。
- 标题只用于动画页标题、导出网页 `<title>`、导出文件名，不进入后续 Prompt。
- 事件：`run_label`。

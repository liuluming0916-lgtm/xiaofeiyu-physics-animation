## 1. 为什么必须去掉 10×6（方案二的核心约束）

v/a 箭头是本地根据 `SIM.bodies` 求导画的，它必须和画面里的物体在**同一个坐标系**。

- 方案一：本地把物理米折成 `cx/cy`，`bodies.at` 返回 `[cx,cy]`，箭头和画图都用纸坐标 → 一致。
- 方案二：AI 自己决定比例和构图。如果本地还按固定的 `s` 算 `cx/cy` 给箭头，
  而 AI 按自己的比例画物体，**箭头就会和物体错位**。

所以方案二只有两种自洽做法：

1. **去掉固定纸**：`state.x/y` 是物理米，AI 也用物理米画，相机自动取景（这份旧文件就是这样）；
2. 保留 10×6，但要求 AI 把“自己用的映射”声明给运行时，让箭头按同一个映射算 ——
   这会引入一套新的映射协议，复杂且容易错。

**本契约选 1。** 旧文件已验证这条路能跑：`stateAt` 返回 `xA/xB/xC`（米），
`drawFrame` 用 `state.xA`，`VIEW` 没有 `SIM.stage`，相机自动 fit。

## 2. 数据契约

### 2.1 `analysis`（不变）

仍是逐元件、逐段的物理运动表；`x/y` 是**质心**，单位米。

### 2.2 `stateAt`（改）

```js
state.block_A = {
  x: 1.2,          // 物理米，质心
  y: 0.05,         // 物理米，质心
  type: 'block',
  // 可选：angleDeg（运行时按速度方向注入）
};
```

**删除**：

- `cx / cy`（纸面坐标）
- `anchor`（方案二不再承诺“底面贴支撑面”，接触由 AI 按画面摆）
- `w / h / r`（尺寸由 AI 定，state 不给）

### 2.3 `VIEW`（改）

```js
SIM = {
  duration: 10.1,
  bodies: [
    { id: 'A', at: function (s) { return [s.block_A.x, s.block_A.y]; } },
  ],
  phases: [{ t0: 0, t1: 1 }, ...],   // 可选
};
```

**删除 `SIM.stage`**（新程序）。运行时走“无 stage ⇒ 相机自动取景”的旧路径
（15 道旧回归题已经验证过这条路）。

### 2.4 `drawFrame`（改）

```js
// 物理世界坐标：x 向右、y 向上、单位米
Draw.ground(-4, 12, 0);
Draw.box([state.block_A.x, state.block_A.y], 1.0, 1.0);
```

- 位置一律用 `state.<key>.x / .y`；
- 尺寸、地面长度、弹簧自然长度、斜面角度等由 AI 定；
- **允许示意**：物块可以画 1.0 m 宽，即使题面是 0.2 m；
- 不写字、不画 v/a、只调 `Draw.*`、不重算运动。

### 2.5 时间归一化（不变）

仍由 `couple` + `core/timing/display-time.mjs` 本地做；`drawFrame` 不承担时间映射。

| 谁 | 负责 | 不负责 |
|---|---|---|
| `analysis` AI | 物理运动方程（米、秒、质心） | 画多大、相机、构图 |

| 播放器 | 物理世界 → 屏幕像素（自动 fit）、播放/时间轴 | 物理、布局 |

## 5. 风险 / 取舍（用户已接受）

| 风险 | 说明 | 处理 |
|---|---|---|
| 接触/贴面不再保证 | AI 只拿到质心，尺寸自己定；“物块底贴带面”不再有结构性保证 | 用户接受“示意”；靠卡里的画法提示 + 人工打回 |
| 相机可能被静态件撑大 | AI 把地面画得很长，相机会 zoom out，主体变小 | 提示词要求“主体别太小/别太偏”；必要时加一条画面告警 |
| 同一题两个物体比例不一致 | AI 自己定尺寸，可能 A 画 1 m、B 画 0.5 m | 允许示意；卡里给“同类元件用同一量级”的正向引导 |
| v/a 箭头 | 因为都退回物理坐标，箭头与物体会一致 | 无需额外映射 |
| C10 / 物理包络 | 仍按物理米算，不受影响 | 保留 |
| 旧程序 | 没有 `SIM.stage` 的旧程序继续走 auto camera | 运行时保留两条路径 |

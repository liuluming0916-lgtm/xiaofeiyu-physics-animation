## 1. 知识卡是什么（非程序员版）

这里的“卡”**不是给学生看的复习卡**，是给**画图 AI** 的“画法提示卡”。

一道题从题面到动画，卡是这样进去的：

1. **读题模型**先读题，输出【题目】【动画元件】【场景】；其中【动画元件】和【场景】写的是**词表 id**（如 `block`、`belt`），不是中文原词。
2. **系统**拿这些 id 去卡库里找：
   - **常驻规范卡**：每道题都注入，2 张；
   - **元件卡**：`elements` 和【动画元件】有交集就注入，可以多张；
   - **场景卡**：`scenes` 和【场景】有交集就注入，目前代码允许多张。
3. 命中的卡按“常驻 → 场景 → 元件”的顺序，拼进**画图阶段**的提示词。
4. **画图模型**只写 `drawFrame`；卡就是它手里的“这类题怎么画”的说明书。

几个关键事实：

- **卡不直接决定物理**：位置、时间、速度由物理分析生成；卡只管“怎么画”。
- **禁用卡不注入**：`enabled: false` 的卡不会进提示词；用户也可以在设置页开关。
- **预算很宽**：正文最多 30000 字、示例最多 10000 字；31 张全命中也不会超。所以“卡多不多”主要不是字数问题，而是**互相打架/噪音**问题。
- **本单的“命中”**：q04 是当前 accepted 的真实证据；q06/q09 是旧产物（正要按方案二重跑），只作参考；q01/q05/q07/q08 等第 3 批跑完再回填。

## 状态字段
- 本元件通常静止，不需要 `state`；端点写**带面顶**（米），本地会把带体画在端点下方。
- 若读题判定它也会动，才按 user 消息的映射读 `state.<key>.x / .y`；静止时不要读 state。
- 放在带上的物体，带面顶的 `y` 尽量接近物块 `state.<key>.y`；允许示意。

## 自检

## 5. 全局问题（不属于某一张卡，但会影响所有题）

### G1. “场景卡最多 1 张”与实际不符

- 文档口径：场景卡最多命中 1 张。
- 代码实际：所有 `scenes` 有交集的卡都会注入，没有“最多 1 张”的限制。
- 证据：q04 同时命中 `belt`、`pulley`、`axis_box` 三张场景卡，加上 2 张常驻 + 3 张元件，共 8 张 / 4668 字，q04 已验收。
- 建议：**允许一题命中 1–3 张场景卡**（真实题确实可能同时有传送带、滑轮、图像），把文档改成这个口径；如果你坚持“只留 1 张”，就要在触发引擎里加限制，并接受 q04 的 axis_box 可能被丢掉。

### G2. 连接件示例用了“不存在的 state key”

- `spring`、`rope`、`trace_path`、`light_rod` 的示例都写 `state.spring_A` / `state.rope_A` / `state.trace_path_A` / `state.light_rod_A`；这些是连接件，运行时不一定有独立 state。
- 模型照抄会 undefined；C1 查不出（它不知道运行时有哪些 key），要到 Dry-Run 才炸。
- 建议：示例改成从两个真实物体端点取，或明确写“`xxx_A` 只是占位，换成实际 key”。

### G3. 多张卡说“由场景给数值”

- 场景卡是**通用卡**，不含某道题的具体数值；`incline`、`pulley`、`electric_field`、`magnetic_field`、`wire`、`meter` 都有这句。
- 模型会等一个不存在的“场景数据”。建议统一改成“按题面/题图给”。

### G4. 封存卡可以被用户手动打开

- `mercury` 打开后，`analysis` 不产出 `yA/yB`，画出来是 undefined/NaN；`graph_wave` 打开后示例只是固定折线，不是真波形。
- 建议：在封存卡正文顶部加一行“封存原因 + 开启会怎样”，或在设置页把“封存卡”做成只读；至少让用户打开前看到警告。

### G5. order 有重复

- 同类型重复：`909`（`conductor_rod` / `light_rod`）、`913`（`plates` / `meter`）、`915`（`ray` / `magnetic_field`）。
- 后果：注入顺序退化为按 id 排序，不确定但通常无害。建议把同类型 order 改成唯一值，让顺序可预期。

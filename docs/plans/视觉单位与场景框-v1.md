# 视觉单位与场景框 v1

> **2026-10-23 裁决：骨架（第 4/5/6 步）不做 —— 用户判定"过度工程"。**
> 已实现的只有第 1、2、3、7、8 步：10×6 固定纸、u/v 折算、元件固定布局尺寸、相机拍纸、视觉尺寸一致性门禁。
> 下文关于 `single_stage` / `same_figure_circuit_stage` / `circuit_inset_stage` / `optics` / `thermal` /
> `celestial` 的部分**全部搁置**，只当历史方案看。

> 状态：方案（2026-10-22）
> 前置：长距离 `u/v` 压缩补丁已回退；`state` 只保留物理 `x/y` 与视觉 `cx/cy`。
> 目标：元件、场景在**所有题**里都保持可读的视觉单位，而不是只在“列车题”里打补丁。

## 1. 回退与教训

已回退的东西：

- `state.u / v / cu / cv` 字段；
- `core/analysis/layout.mjs`；
- `block / board / ...` 卡片里的 `cu/cv` 写法；
- `scene_code` 里的“布局中心”提示；
- 相关测试与文档。

回退原因：

- 用 **50 m 阈值**决定是否压缩，是特例，不是“始终”；
- `w/h` 在 identity 时是米、压缩时是布局单位，语义混了；
- 只压缩运动元件，静态布景仍用物理坐标；
- 1 m 题和 1.2×10⁶ m 题里，物块的视觉尺寸仍不一致。

## 2. 旧包络方案：保留什么

现有 `AutoView` / `fullEnvelope` / `computeFramingPlan` 做对的事：

1. **包络从命令缓冲来**，不让模型声明相机；
2. **全时段取并集**，相机一次锁死，不逐帧跳；
3. **排除箭头、尺寸标注、hatch 参考面**，不让标注/背景决定主体大小；
4. **两遍法**：先实体包络，再按类归一箭头，避免“箭头越大、画面越小”；
5. **Nice Numbers 只决定网格**，不决定画幅。

它解决的是“**相机怎么拍**”，没有解决“**元件在画面里该多大**”。
所以新的方案不是推翻它，而是把它降级为：

- **自动场景框的兜底**；
- **包络/覆盖率/越界检查**；
- **箭头归一的名义相机**。

## 3. 三层，始终分离

```text
物理层    x / y              米；只给物理、readouts、C10
场景层    u / v              布局单位；由场景框映射
元件层    cu / cv / w / h    布局单位；固定视觉尺寸
```

### 3.1 物理层

- `state.<key>.x / .y`：题目的真实坐标，单位米；
- 不参与绘制，不参与尺寸；
- `readouts`、C10、物理核对只读它。

### 3.2 场景层

**不是每张场景卡各自定义框。** 场景框属于**少量布局模板**；场景卡只声明“我属于哪个模板”，并在模板给的锚点上画。  
（上一版写成“每个场景”，是我表述错了，那确实不现实。）

```js
sceneFrame = {
  mode: 'schematic' | 'to-scale',
  width: 10, height: 6,          // 布局单位；16:9
  padding: 0.08,
  x0, x1, y0, y1,                // 物理包围盒
  u0, u1, v0, v1,                // 布局框
}
```

映射：

```text
schematic: u = u0 + (x - x0) / (x1 - x0) * (u1 - u0)
           v = v0 + (y - y0) / (y1 - y0) * (v1 - v0)
to-scale:  同一比例尺，保比例，允许框内留白
```

- **schematic**：长距离路线、需要压缩的示意图；
- **to-scale**：光学、p–V、需要真实比例的图；
- 两种都输出 `u/v`，区别只在比例是否统一。

### 3.3 元件层

视觉几何表改成**布局单位**：

```json
{
  "block": { "w": 0.4, "h": 0.3, "anchor": "bottom" },
  "ball": { "r": 0.08, "pointR": 0.02, "anchor": "bottom" }
}
```

- `w/h/r` 不再表示米，不再随题面尺寸变化；
- `cu/cv = u/v + 视觉偏移`；
- 卡片只写 `Draw.box([state.e0.cu, state.e0.cv], state.e0.w, state.e0.h)`；
- 所有题里，物块都占布局框的同一比例。

## 4. 场景框从哪来

### 4.1 少量布局模板，不是每张卡

场景卡有 18 张，但**布局骨架只有少数几个**（外加 auto 兜底）。骨架不是“按题”分的，而是按**空间关系**分的；同一张卡可以出现在不同骨架里。

| 布局骨架 | 什么时候用 | 版面 |
|---|---|---|
| `single_stage` | 纯力学/纯场，没有独立电路 | 一张主舞台；地面/斜面/场都画在里面 |
| `same_figure_circuit_stage` | 电路和主画面**电气相连**（导轨、极板、线圈） | 左电路条 + 右主舞台；导轨/极板/场在右侧 |
| `circuit_inset_stage` | 电路是**另画的一张图**（如“图乙”） | 主舞台 + 右侧电路插图框 |
| `optics_stage` | 光路/透镜 | 光轴 + 光学件 |
| `thermal_stage` | 气缸/玻璃管 | 竖直容器框 |
| `celestial_stage` | 天体轨道 | 椭圆框 |
| `auto` | 没有骨架可用 | 实体包络自动套 10×6 |

**新增题目不自动等于新增骨架。**  
只有空间关系真的变了（例如“两张独立电路图 + 力学主图”），才加骨架；否则只是换布景卡/换右侧内容。

### 4.1.1 中文命名

`same_figure_circuit_stage` 是“同图电路舞台”的英文 id，保留“同图”二字，避免和“电路插图”混淆。  
建议显示名统一成：

| 内部 id | 中文显示名 | 含义 |
|---|---|---|
| `same_figure_circuit_stage` | **电路同图舞台** | 电路和导轨/极板/线圈画在同一张图里，导线真的连过去 |
| `circuit_inset_stage` | **电路插图舞台** | 电路是另画的一张图，放在主画面旁边的插图框 |
| `single_stage` | **单主舞台** | 没有独立电路，只有一张主画面 |
| `auto` | **自动舞台** | 没有骨架可用时，按实体包络自动套框 |

代码里的 id 可以不改；文档、界面、对话里统一用中文名，避免“电路舞台”到底是不是插图的歧义。

每个模板给出：

```js
layout = {
  id: 'mechanics_lab',
  mode: 'schematic',
  frame: { u0: 0, u1: 10, v0: 0, v1: 6 },
  anchors: { groundV: 0, left: 0.5, right: 9.5, panel: null },
  map: { x0, x1, y0, y1, u0, u1, v0, v1 },
}
```

场景卡只读 `state.layout.anchors` / `state.layout.frame`，不自己算框：

```js
// ground
Draw.ground(state.layout.frame.u0, state.layout.frame.u1, state.layout.anchors.groundV);

// belt
Draw.belt([u0, groundV + 0.05], [u1, groundV + 0.05], { ticks: 16 });

// circuit
Draw.line([panel.u0, panel.v0], [panel.u1, panel.v0]);
```

### 4.2 没有布局模板

用现有**实体包络**自动生成 `auto` 布局：

1. `fullEnvelope`（复用现有实现）取全时段实体包络；
2. 排除箭头/尺寸/hatch（复用现有 `FRAME_EXCLUDE_OPS` / `isReferenceSurface`）；
3. 把包络映射到 `10×6` 布局框；
4. 元件尺寸仍用固定视觉单位。

这一步就是“始终归一化”，**没有 50 m 阈值**。  
场景卡带 `layout` 就用对应模板；没带就继承 `auto`。

### 4.3 全自动舞台 = 自动分面板，不是一个包围盒

电磁感应题经常同时有：

- 导轨 + 导体棒 + 受力（力学面板）；
- 电源、电阻、电表（电路面板）；
- 磁场点叉（场面板）。

这三类不能用同一个比例尺硬塞进一个包围盒，否则电路和导轨总有一个看不清。

所以“全自动舞台”正确的含义是：

1. 本地舞台引擎根据场景 id / 元件 id 自动决定要开几个面板；
2. 每个面板有自己的物理→布局映射；
3. 面板在 10×6 舞台上的位置由规则决定（例如主面板 + 右侧电路插图）；
4. 相机 fit 整张舞台，不分别 fit 每个面板；
5. 元件视觉尺寸仍然固定。

示例：

```text
rail + conductor_rod + magnetic_field + wire
  → same_figure_circuit_stage：左电路条 + 右导轨/场主舞台
plates + magnetic_field + wire
  → same_figure_circuit_stage：左电路条 + 右极板/磁场主舞台
```

面板由**本地排版规则**声明，不由大模型声明。  
大模型只负责“画什么”，场景卡只声明“我属于哪个面板”，不写面板坐标。

### 4.4 舞台由谁声明

| 角色 | 能声明什么 | 不能声明什么 |
|---|---|---|
| `read_problem` / 场景卡 | 语义：这题有导轨、电路、磁场、光学件 | 画幅、坐标、比例尺 |
| 元件卡 / 场景卡 | 我属于 `main / circuit / field / optics` 哪个面板 | 面板矩形、相机 |
| 本地舞台引擎 | 面板数量、面板矩形、物理→布局映射、相机 | 物理运动、题目答案 |
| 模型 `drawFrame` | 只写绘制命令，带面板标签 | 不写像素、不写相机、不写比例尺 |

结论：**舞台由本地渲染声明，大模型最多声明“语义归属”。**

### 4.3 相机

`AutoView.fit` 改成 fit **场景框**：

```js
AutoView.fit({ minX: 0, minY: 0, maxX: 10, maxY: 6 }, viewport)
```

- 物理包络只用于自动场景框和检查；
- 相机不再直接 fit 物理包络；
- 这样 1 m 题和 1.2×10⁶ m 题都落在同一个 10×6 画面里，物块像素大小一致。

## 5. 静态场景也必须走布局

这是旧方案最大的缺口，也是“元件、场景始终适合演示”的关键：

- 地面/斜面/传送带/导轨/场/光路/电路全部用 `u/v` 画；
- 不允许场景卡再写 `Draw.ground(-1.5, 2.5)` 这种物理坐标；
- **布局模板是作者，场景卡是零件**：卡从 `state.layout.anchors` 取锚点，不自己定义框；
- 运动元件从 `x/y` 映射到 `u/v`，再叠视觉尺寸；
- 这样块和地面、斜面和物块、绳和滑轮才会在同一布局里对齐。

## 6. 判据

新增门禁（或扩展现有）：

1. **视觉尺寸一致性**：同一元件在 1 m、10 m、1.2×10⁶ m 三套题里，屏幕宽度差 < 20%；
2. **场景覆盖率**：静态场景框覆盖所有实体，实体不越界；
3. **u/v 合法性**：所有 `u/v` 有限，落在场景框内；
4. **物理不回退**：`x/y` 仍用于 readouts / C10；
5. **AutoView 不跳**：全时段相机锁定，不逐帧变；
6. **长距离题**：物块可见，路线仍完整，二者都在框内；
7. **to-scale 场景**：比例尺统一，不允许用旧 `w/h` 米制。

## 7. 迁移顺序

1. 定义 `layout` 契约（骨架 + anchors，本文件第 3/4 节）；
2. 在 `analysis` 生成 `u/v/cu/cv`；始终归一化，无阈值；
3. 改视觉几何表为布局单位；
4. 先做 `single_stage`（地面/斜面/传送带）和 `same_figure_circuit_stage`（导轨/极板 + 电路条）；
5. 用两道题验收：导轨导体棒、平行板带电粒子；
6. 再做 `optics / thermal / celestial` 骨架；
7. 相机改 fit 布局框；`fullEnvelope` 保留为 auto 骨架/检查；
8. 加视觉尺寸一致性门禁。

## 8. 不做什么

- 不再用物理跨度阈值决定布局；
- 不再让 `w/h` 在不同题里一会儿米、一会儿布局单位；
- 不再只压缩运动元件、放着静态布景不管；
- 不把 `text/latex` 重新引回画布。

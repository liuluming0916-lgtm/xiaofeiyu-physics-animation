> 状态：P0 契约冻结（2026-10-22）
> 范围：为 P1 垂直切片定死口径；本文件不改变运行时行为。
> 2026-10-22：长距离 `u/v` 压缩已回退；布局坐标的最终方案改由 `docs/plans/视觉单位与场景框-v1.md` 定义。
> 相关：`core/prompts/analysis.mjs`、`core/analysis/generate.mjs`、`core/knowledgecard/v2/runtime.mjs`

## 1. 三层坐标

| 层 | 字段 | 单位 | 谁产生 | 用途 |
|---|---|---|---|---|
| 物理坐标 | `state.<key>.x / .y` | 米 | `analysis` | 物理位置、读数；默认是物体与支撑面的**接触/参考点** |
| 视觉中心 | `state.<key>.cx / .cy` | 米（视觉） | 本地程序 | 画形状、v/a 箭头、旋转 pivot |
| 布局坐标 | `state.<key>.u / .v` | 视觉单位 | 场景卡映射（P2） | 长距离/示意图压缩；P1 暂不实现，先令 `u=x, v=y` |

**硬规则**

1. `analysis` 只写物理运动，不写半高/半径/绘图偏移。
2. 视觉尺寸来自**视觉几何表**，不依赖题面尺寸；题面尺寸只服务物理比例。
3. 偏移由本地程序算，卡片不写 `+0.1`、不写死 `0.4 / 0.3`。
4. 箭头和旋转都用 `cx/cy`，不用接触点。

## 2. `analysis` 的 `type` 字段

`MOTIONS` 每个元件增加一行：

```text
element: block_A
type: block
```

- `type` 取词表 id（`block / ball / board / belt / incline / ...`）。
- 同一个 `element` 的多段必须使用同一个 `type`。
- 缺失或拿不准写 `unknown`；`unknown` 不硬失败，但只退化为 `cx=x, cy=y`，并允许卡片按 `x/y` 画。
- 解析结果：`analysis.elements[i].type`。

## 3. 视觉几何表

文件：`contracts/element-geometry-v2.json`

```json
{
  "format": "od-element-geometry",
  "version": 1,
  "elements": {
    "block": { "anchor": "bottom", "shape": "box", "w": 0.4, "h": 0.3, "minPx": 36, "rotatable": true },
    "ball": { "anchor": "bottom", "shape": "circle", "r": 0.08, "pointR": 0.02, "w": 0.2, "h": 0.2, "minPx": 14, "rotatable": false },
    "board": { "anchor": "bottom", "shape": "box", "w": 3.0, "h": 0.1, "minPx": 36, "rotatable": true },
    "belt": { "anchor": "top", "shape": "belt", "w": 4.0, "h": 0.1, "minPx": 24, "rotatable": false },
    "incline": { "anchor": "bottom", "shape": "incline", "w": 1.2, "h": 0.6, "minPx": 24, "rotatable": false }
  }
}
```

P1 只填 5 个元件：`block / ball / board / belt / incline`；后两个先作静态占位，不参与 P1 的 `cx/cy` 计算。

字段：

| 字段 | 含义 |
|---|---|
| `anchor` | `bottom` = `x/y` 是底部接触点；`center` = 已经是中心；`top` = 顶部接触点 |
| `shape` | `box / circle / belt / incline` |
| `w / h` | 视觉宽高（米，示意比例） |
| `r / pointR` | 球的视觉半径 / 质点点标记半径 |
| `minPx` | 最小屏占比兜底（P2 用） |
| `rotatable` | 是否允许按速度定向（P5 用） |

## 4. 生成后的 `state`

```js
state.e0 = {
  x: x0, y: y0,             // 物理接触点
  type: "block",
  cx: x0 + 0.2, cy: y0 + 0.15, // 视觉中心（由几何表算）
  w: 0.4, h: 0.3,
};
```

- `VIEW.bodies.at` 用 `cx/cy`。
- `readouts` 仍用 `x/y`。
- 卡片用 `cx/cy/w/h/r`。

## 5. 场景与注入顺序

- 静态元件与布局归**场景卡**；元件卡只负责运动体与无质量约束。
- 注入顺序：`anim_rule → scene → element`。
- 当前代码是 `anim_rule → element → scene`，P2 改。

## 6. P1 验收

1. `analysis` 能解析 `type: block`，缺省 `unknown` 不崩。
2. q01 传送带题：物块底 = 带面顶（误差 < 1e-6）。
3. v/a 箭头从物块中心出发，不从地面出发。
4. `block / ball / board / belt / incline` 五张卡不再写死 `+0.1 / 0.05`。
5. `analysis-selftest`、`analysis-pipeline-selftest`、`knowledgecard-v2-contract-selftest` 全绿。

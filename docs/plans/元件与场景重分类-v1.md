## 3. 第一件事的拦路虎：场景怎么被命中

现在的 `scenes` 词表只有 3 个**模型场景**：

```text
conveyor_block / incline_block / circular_track
```

`read_problem_v2` 的 `【场景】` 现在表示“这类题怎么摆/什么顺序”，不是“图里有哪些静态件”。  
如果直接把 `incline / ground / pulley / ...` 改成 `kind:'scene'`，它们**永远不会被命中**，因为模型不会把这些 id 写进 `【场景】`。

三种方案：

- **A（推荐）扩展 `【场景】` 的定义**：场景 = “模型场景 + 静态布景”；词表扩到 17 个静态场景（+ 3 个模型场景可选）；`read_problem_v2` 可多选。  
- **B 新增 `【静态场景】` 段**：模型场景和静态布景分开输出，卡片按 union 触发；解析器多一段。  
- **C 场景卡仍按 `elements` 命中**：最省事，但“场景卡”名不副实，也违背“场景词表 ↔ 场景卡”的对应关系。不推荐。

现有 3 个模型场景：**已裁决直接删除**（`conveyor_block / incline_block / circular_track`）。
batch 1 暂时保留它们，避免一次改太多；下一批删除，并同步改 `read_problem` 测试。

## 4. 已定细节

### 4.1 长木板/小车

一张 `board` 卡，不加轮子；小车就是“示意图上的矩形”，不画轮子。  
`block` 的别名“小车”移到 `board`，避免两张卡抢触发。**已落地。**

### 4.2 电路

已拆成 `wire` 场景（导线、电源、开关、电阻、滑动变阻器）和 `meter` 场景（电流表、电压表、多用电表）。  
`circuit` 这个统一 id 已删除。

### 4.3 导轨

新增 `rail` 场景；`导体棒` 在导轨上运动时，导轨由 `rail` 场景画，`conductor_rod` 只管棒。

### 4.4 传送带划痕

本期不做。`belt` 场景只负责带面、带速、支撑 y；划痕需要派生量 `s_rel(t)=∫|v_block-u_belt|dt`，后续版本再加。

### 4.5 受力箭头

本期不画。`analysis` 给不出完整受力，`vector` 卡删除，`Draw.arrow` 原语保留但不再由元件卡主动教。

### 4.6 卫星/椭圆

卫星并入 `ball`；`celestial_orbit` 场景画轨道。`Draw.arc` 只能画圆，需新增椭圆 SDK（`Draw.ellipse` 或等价原语）。

### 4.7 水银柱

`mercury` 元件不画整根柱，只画液面 A / 液面 B，并在两液面之间填色；`analysis` 分别算两个液面位置。  
`gas_tube` 场景负责管壁与裁剪，溢出问题后续再议。

## 5. 迁移顺序

1. **先定场景触发口径**（A/B/C + 3 个模型场景去留）；
2. 写分类清单；扩词表；改 `read_problem_v2`；
3. 场景卡先落地：`incline / ground / arc_track / pulley / belt / circuit / rail`；
4. 元件卡拆分：`conductor_rod / light_rod / piston / mercury`；
5. 删旧卡、停用 `graph_wave`；
6. 重写或删除 `overview`；
7. 加 1:1 门禁；
8. 回归：q01、q02、电磁感应、光学各一道。

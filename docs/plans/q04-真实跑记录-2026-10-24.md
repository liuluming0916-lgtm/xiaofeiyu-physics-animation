## 3. 画面：通过门禁，但有一个明显问题

用 mock canvas 量了一下（960×540）：

| t | 相机比例 | A 的屏幕位置 | A 方块宽 | C 的屏幕位置 |
|---:|---:|---|---:|---|
| 0 | 12.6 px/m | (442, 89) | **11.4 px** | (543, 229) |
| 2.05 | 12.6 px/m | (518, 89) | 11.4 px | (543, 305) |
| 3.6 | 12.6 px/m | (421, 89) | 11.4 px | (543, 456) |

- A 的方块是 0.9×0.6 m，在 12.6 px/m 下只有 **11 px 宽**；
- 原因：C 剪断后自由落体，t=3.6 s 时 y 已到约 -29 m；
- 相机自动 fit 所有被画出来的实体，C 把画面往下拉，A 被压到顶部；
- 门禁 C1–C9 不管“主体大小/构图”，所以它 pass，但人看着会觉得 A 太小。

**这不是方案二本身错，而是 q04 这道题的画法选择：**

> C 剪断后已经离开题目焦点，但 `drawFrame` 仍然每帧画 C，导致相机被它拉远。

可选修法（等你定）：

1. **画图 AI 只画剪断前的 C**（`if (t < 2.05) Draw.box(...)`），剪断后 C 不再参与取景；
2. **analysis 在剪断处把 C 的段截断**（不再给自由落体段），C 停在剪断位置；
3. **相机只 fit “本题主角”**（例如 A/B），C 允许出画；
4. 不改，接受 A 小。

我倾向 **1 或 2**：C 已经剪断，没必要为了它把整个画面拉远。

## 4. 其它观察

### 4.1 读题判定有多余项

`read_problem` 判了：

```
【动画元件】block、board、rope
【场景】belt、pulley、axis_box
```

- `board` 和 `axis_box` 在这道题里没有实际用到（`drawFrame` 没有画板/坐标轴框）；
- 它们会触发多余的卡（`board`、`axis_box`）注入，浪费 token，也可能误导；
- 真正需要的是 `block`、`rope`、`belt`、`pulley`。
- 这不是方案二 bug，是读题判定精度问题（P2-2 一类）。

### 4.2 接触关系

- A 质心 y=0.05，方块高 0.6 ⇒ 底边 y=-0.25；
- 传送带带面顶 y=-0.25；
- 两者刚好贴上，没有悬空。这点是好的。

### 4.3 文字 / v-a

- `drawFrame` 没有 `Draw.text` / `Draw.dimension` / `axisBox`；
- 没有手写 v/a 箭头；
- 力箭头有 `category: 'force'` 与 `mag`，符合 C1。

## 5. 物理核对：第 4 段是按答案拟合的

按题面受力，剪断 B–C 后 A、B 系统：

```
a = (F + f + m_B g) / (m_A + m_B)
  = (−20x + 10 + 30) / 5
  = 8 − 4x
  = −4(x − 2)
```

从 x=6、v=0 积分到最左端：

```
v²(x) = −4x² + 16x + 48
令 v=0 ⇒ x² − 4x − 12 = 0 ⇒ x = 6 或 x = −2
```

按这个受力模型，最左端是 **−2 m**，和参考答案差 0.286 m。用户确认答案正确，说明**我的受力模型/题面还漏一个条件**；这个条件目前没有被写出来。

程序 segment 4 却写成：

```
x = 2.143203 + (6 − 2.143203) cos(2(t − t0))
```

平衡位置从 2 改成 2.143203，相当于额外加了约 2.86 N 常量力；题面没有写这个力。
把 −1.7136 代回上面的 v²(x)，还有约 **8.84 (m/s)²**，即按这个受力模型 A 仍在向左走，并没有停。

**关键：程序不是从这个受力模型推出来的，而是用“起点 x=6、终点=参考答案”反推的。** analysis note 也直接写了“按参考答案取...作为该段终点”。

详见 [`q04-A运动方程核对-2026-10-24.md`](q04-A运动方程核对-2026-10-24.md)。

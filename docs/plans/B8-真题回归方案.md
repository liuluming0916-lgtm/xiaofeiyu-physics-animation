### 2.2 字段与状态机

| 字段 | 说明 | 谁写 |
|---|---|---|
| `status` | `placeholder`（占位，本轮不做）/ `todo`（题面已抽、程序还没产）/ `candidate`（模型产出、待人工验收）/ `accepted`（人工验收通过） | 人 |
| `semantics` | `v6`（必须语义 key + 物理 `w/h` + 无 `cx/cy`）/ `legacy`（C 方案之前的冻结产物，按"自洽"豁免） | 人 |
| `program` / `preview` | 相对 `tests/real-exam/`；`placeholder`/`todo` 必须为 `null` | 人 |
| `frozen` | `candidate`/`accepted` 必填：`{ sha256, frozenAt, provenance }`，程序或预览任一字节变了就得重签 | 冻结脚本 |

**状态 ⇒ 文件**（加载器与体检都按这张表判）：

| status | 有 program/preview？ | 进 ③⑦ 门禁？ | 进 ⑫ 总览页？ |
|---|---|---|---|
| `placeholder` | 否（必须 `null`） | 否 | 否 |
| `todo` | 否（必须 `null`） | 否（只打印"待做 N 道"） | 否 |
| `candidate` | 是（缺一即红） | **是** | 否（总览页只吃 `regression-15`，已核对 `build-overview.mjs:20`） |
| `accepted` | 是（缺一即红） | **是** | 否 |

写入本批（用户勾选后）：3 道现有 + 5 道新做 = `candidate`/`accepted`/`todo` 混合；`q03`、`q10` = `placeholder`。

### 2.3 `pilot.json` 退役

`pilot.json` 现在被 4 个 `_` 工具读：`_run-question.mjs`、`_run-q04.mjs`、`_run-q06.mjs`、`_make-q06.mjs`，
外加 `_pilot-note.mjs`、`_check-real-exam.mjs`。做法：**内容并入 `index.json` 后删掉 `pilot.json`**，
6 个工具一次性改成读 `index.json`（`items.find(x => x.id === id)` 的写法不变）。
理由：一个事实只写一处；两份清单必然漂移。
（若用户想保留 `pilot.json` 作为"历史三道"的存档，就把它改成纯说明 + 指向 `index.json`，不保留数据字段。）

## 3. 加载器：`core/dryrun/question-sources.mjs`（新增）

放在 `core/`（不在 `tests/` 与 `tools/` 的覆盖自检扫描面里，不需要新豁免）。

```js
export const SUITES = {
  'regression-15': { dir: 'tests/regression-15', kind: 'module' },
  'real-exam':     { dir: 'tests/real-exam',     kind: 'manifest' },
};

/** 两套题统一成 run-suite / render-check 认的形状 */
// → { id, entry, suite, file, program: { index, title, mode, slots, examPoint? }, meta }
export async function loadSuite(suite, filters = []) {}

/** 从 setup 的 T_PHYS 与 VIEW.phases 反推 C5/C6 要的两个数（现在在 tools/_check-real.mjs 里） */
export function deriveTiming(slots) {}   // → { tPhys, boundaries }

/** 清单体检 + 负对照；返回 { errors, counts, items } */
export function auditManifest(manifest, { dir }) {}
```

要点：

1. **`entry` 用 `program.id`**（`q08`），不加前缀 —— 与现有 `_check-real.mjs`、`tests/reports/` 的命名一致。
2. **C5/C6 的 meta 只对真题需要**：`deriveTiming()` 把 `_check-real.mjs` 的 12 行解析搬过来，
   `run-suite` 与 `_check-real` 共用一份（`_check-real.mjs` 退化成 5 行 wrapper）。
3. **清单体检是硬失败**（不是打印）。规则：
   - `id` 唯一、`number` 唯一；文件里的 `id/index/title/mode` 与清单一致；
   - `placeholder`/`todo` ⇒ `program === null`；`candidate`/`accepted` ⇒ 程序与预览都在、能 `JSON.parse`；
   - 盘上没有任何"清单外的 `qNN.program.json`"（防孤儿）；
     例外：`*.handwritten.program.json`（反例，`q06` 那份）与 `*-model.program.json`（中间产物）不算孤儿；
   - `semantics: "v6"` ⇒ `stateAt` 里**不得出现** `state.e0`、`cx:`、`cy:`；
   - 任何 status ⇒ `VIEW.SIM.bodies` 引用的 key 必须都在 `stateAt` 里赋值（**自洽体检**，这条同时覆盖 `legacy`）；
   - `candidate`/`accepted` ⇒ `frozen.sha256` 与文件实际 sha256 一致（冻结后偷改会红）。
4. **负对照每次真跑**（这是"绿着且真的跑过"的关键）：体检函数自带 4 份坏清单，
   必须各自报出指定错误码，否则整站失败 ——
   `题号不符` / `非 placeholder 缺程序` / `占位却带程序` / `semantics=v6 但仍有 state.e0`。
   这样不需要新增门禁步骤，体检本身也不可能"写了没跑"。
5. **至少 3 道真题必须被加载**（现有的 `q04`/`q06`/`q09`）：防止有人把 status 全改成 `todo`
   让门禁"绿着但一道真题都没跑"。

## 4. 程序形态（真题一律按 v6 生成形态冻结）

以 `core/analysis/generate.mjs` 现在真正吐出来的形状为准：

| 项 | 要求 | 依据 |
|---|---|---|
| `state` key | **语义 key**：`state.block_A`；非法/中文/保留字按 `core/analysis/` 的清洗规则退化 | C.5 |
| 位置 | `x/y`（物理米）+ `u/v`（纸面 0–10 / 0–6，内部量）；**不写 `cx/cy`** | C.5 |
| 尺寸 | `w/h/r` = **卡里的 `physical`（物理米）**，渲染时与位置同乘 `s` | C 方案 §C.1 |
| `VIEW.SIM.stage` | `{ u0,u1,v0,v1, s, cx, cy }`（`cx/cy` 是**舞台中心**，与元件无关，保留） | `buildView()` |
| `VIEW.SIM.bodies` | `{ id: "block_A", at: s => [s.block_A.u, s.block_A.v] }` | `buildView()` |
| `drawFrame` | 只画；位置用 `state.*.x/y`（物理米）或 `u/v`（场景），尺寸不再手写 | `scene_code` 契约 |
| `setup` | `const T_PHYS = …;`（C5 与时长归一都读它） | `_check-real.mjs` |

**旧三道（`q04`/`q06`/`q09`）怎么办**：它们各有 `state.e0` + `cx/cy` + 纸面尺寸，但在 `stateAt` 里
**自洽**（`e0` 是它们自己唯一的来源，没有别处再引用 `block_A` 之类的 key），已被人工验收。
本轮处置 = **保持原样、`semantics: "legacy"`**，体检只要求"`bodies` 引用的 key 都在 `stateAt` 里"。
要迁到语义 key 是独立一件事（改 `stateAt` + `drawFrame` + 重出 `qNN.html`），
**建议排到 1.1.19**，不和"换真题"混在一个提交里。

## 7. 门禁口径

- **仍 56 步**。理由：③ 与 ⑦ 本来就是"跑全部题"的两站，真题是它们的输入面扩展，
  不是新判据；新增独立步骤只会让"56 步"这个数变成维护负担。
- 若用户坚持要独立一步（`㊿ 真题清单与加载器取证` → 57 步），需要同步改：
  `tools/verify-all.mjs` 的 STEPS、`项目现状与路线.md` §1/§5/§10、`AGENTS.md` §5（三处 56）、
  `docs/门禁都盯什么.md` 第 9 行、`verify-coverage.mjs` 的候选脚本口径。
  **不建议**：体检已经在 ③ 里带负对照真跑，独立一步是重复。
- 运行时预算：`dryRun` 每题几十到几百 ms，8 道真题 < 3 s；`render-check` 每题 25 帧，可忽略。
  ③ 的现有耗时主要来自 15 道合成题，不会被真题拖慢。

## 9. 风险与止损

| 风险 | 表现 | 止损 |
|---|---|---|
| 真题进 ③ 后老是红 | 某道题 C5/C6 边界对不上（`deriveTiming` 只认 `T_PHYS` + `phases`） | 先只在 `candidate` 状态跑；红了就改程序，不改判据；必要时该题退回 `todo` |
| ⑦ 的"长小数"判据误伤真题 | 画面印出 `3.3859…` 这类 | 属真实缺陷，修程序（不调判据）；现有 3 道已证明判据可用 |
| 选择题时长口径没定 | 第 1、2 题 4 s 快进 | 清单 §3.1 三选一后再做；否则先只做计算题 |
| `pilot.json` 退役漏改工具 | `_run-question` 报 ENOENT | 第 3 个提交里 grep 全仓 `pilot.json` 一次 |
| tex-svg 新产物 | ⑧ 只扫 `regression-15`，新 `qNN.json` 变"额外文件" | 已核对：⑧ 只校验自己产出的 15 条与 `manifest.json` 一致，**不管额外文件**；新文件的 tex 由 `_tex-for.mjs` 生成并入库（与 `q04/q06/q09.json` 同做法） |
| 冻结后偷改 | `frozen.sha256` 变了但没人发现 | 体检里加 sha256 断言（§3.3-6） |
| 门禁变慢 | ③ 从 ~15 题变 ~23 题 | 已估：< 3 s；若超预算，把真题表单独计时打印 |

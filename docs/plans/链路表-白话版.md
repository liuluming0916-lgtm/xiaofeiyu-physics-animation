# 链路表（白话版）：每个阶段吃什么、产什么、字段是什么意思

> 给不写代码的人看。技术版在 [`v1.1.18-链路I-O与注入审计.md`](v1.1.18-链路I-O与注入审计.md)。
> 当前版本：**方案二**（物理世界坐标 + 相机自动取景）；没有 10×6 纸、没有 `cx/cy`、没有 `anchor`。

---

## 0. 先记住一句话

**物理分析负责“物体怎么动”，画图 AI 负责“长什么样”，本地程序负责“检查、对时间、放动画”。**

---

## 1. 动画程序的 8 个“盒子”（槽位）

最终交给播放器的动画，固定是 8 个盒子。你可以把它想成 8 个抽屉：

| 盒子 | 中文叫法 | 里面装什么 | 谁产生 | 谁用 |
|---|---|---|---|---|
| `PROBLEM` | 题面 | 题目文字；纯图片题用读题标题或“题目见图片”兜底 | 程序 | 页面左栏 |
| `STEPS` | 分步讲解 | 每一步的标题 + 讲解公式（**不带时间**） | 分步 AI → 程序整理 | 页面步骤栏 |
| `ANSWERS` | 答案 | **v6 起故意空着**；答案在解题/分步里 | 程序 | 不再使用 |
| `VIEW` | 播放说明书 | 总时长、哪些物体要自动画 v/a 箭头、可选阶段边界 | 程序（从物理分析生成） | 播放器 |
| `setup` | 开场准备 | 目前只放总时长常量 `T_PHYS` | 程序 | 播放器 |
| `stateAt` | **每时每刻物体在哪** | 一个函数：给它一个时刻 `t`，返回每个物体的位置 | 程序（从物理分析生成） | `drawFrame`、`readouts` |
| `drawFrame` | **每一帧怎么画** | 地面、斜面、滑轮、物块、绳……怎么画 | **画图 AI 唯一写的地方** | 播放器 |
| `readouts` | 仪表盘 | 每个物体的 x / y / vx / vy，供读数和曲线 | 程序（从 `stateAt` 生成） | 读数面板、图表 |

### 1.1 `stateAt` 到底是什么

它不是一个“文件”，也不是一段说明，而是一个**函数**。

播放器每秒钟会调用它很多次：

```js
stateAt(1.2)  // “第 1.2 秒时，每个物体在哪？”
```

返回：

```js
{
  block_A: { x: 2.4, y: 0.05, type: 'block' },
  ball_B:  { x: 3.1, y: 0.80, type: 'ball'  }
}
```

- `x / y` 是**物理米**，而且是**质心**；
- `drawFrame` 拿这个位置去画；
- `readouts` 拿这个位置去算速度和读数；
- 它由程序根据物理分析表生成，**AI 不写它**。

> 为什么不让 AI 写？因为 AI 写运动容易算错；让物理分析只写公式，程序统一翻译成每帧位置，更稳。

### 1.2 `VIEW` 到底是什么

它是给播放器的“播放说明书”，里面有两样关键东西：

```js
SIM = {
  duration: 10.1,                 // 物理总时长（秒）
  bodies: [                       // 哪些物体要自动画 v/a 箭头
    { id: 'block_A', at: (s) => [s.block_A.x, s.block_A.y] }
  ],
  phases: [ ... ]                 // 可选：阶段边界
};
```

- `duration`：整段动画物理上多长；
- `bodies`：告诉播放器“这个物体在任意时刻的位置”，播放器用它求速度/加速度，自动画 v/a 箭头；
- `at(s)`：给一个时刻，返回这个物体的 `[x, y]`；
- `phases`：可选，阶段边界，主要用于联动/检查。

**`VIEW` 不是相机。** 现在相机自动取景，AI 不写相机。

### 1.3 `setup` / `readouts` 是什么

- `setup`：开场准备。目前只放 `T_PHYS = 总时长`，给后面的代码用；AI 不写。
- `readouts`：仪表盘数据。每个物体的位置和速度，右侧读数、曲线图从这里取；AI 不写。

### 1.4 `drawFrame` 是什么

**唯一由画图 AI 写的盒子。** 它只描述“怎么画”，例如：

```js
Draw.ground(-2, 8, 0);
Draw.box([state.block_A.x, state.block_A.y], 0.6, 0.4);
```

- 位置只从 `state.<key>.x / y` 读；
- 尺寸、地面长度、斜面角度、弹簧长度由 AI 自己定；
- 不写字、不画 v/a、不重算运动。

## 2. 链路总表：从题目到动画

| # | 阶段（界面上的名字） | 谁做 | 它拿到什么（人话） | 它产出什么（人话） | 产出给谁 |
|---|---|---|---|---|---|
| 0 | **读题** `read_problem` | AI | 题面文字、题目图片、你手打的补充描述/已知条件、元件/场景词表 | 标题；图里有什么、谁在左谁在右、斜面朝哪；示意图范围；用到哪些动画元件/场景 | 标题→题面；几何→物理分析/画图；判定→卡片；范围→裁图 |
| 1 | **解题** `solve` | AI | 题面、补充描述/已知条件、参考答案（文字/图片） | 完整解题过程与结论 | 分步讲解、物理分析 |
| 2a | **分步讲解** `breakdown` | AI | 题面、解题过程 | 第 1 步/第 2 步的标题 + 讲解公式（不带时间） | 步骤耦合、`STEPS` 盒子 |
| 2b | **物理分析** `analysis` | AI | 题面、解题过程、读题几何、补充描述、参考答案原文、元件真实尺寸表 | **每个物体每一段的运动公式**：`x(t)、y(t)`、起止时间、初态、说明 | 步骤耦合、画图、自愈；程序用它生成 `stateAt/VIEW/readouts` |
| 3 | **步骤耦合** `couple` | AI | 物理分析表、分步讲解、总时长 | 第几步对应哪段时间、属于第几小问 | 时间归一化、画图（步骤时间） |
| 4 | **画动画** `scene_code` | AI | 题面、物理分析、读题几何、元件 id→state key 对照、步骤标题+时间、裁出的示意图 | **只写 `drawFrame`**：怎么画 | 8 个盒子 → 本地校验 |
| 5 | **本地校验** `dry_run` | 本地程序 | 8 个盒子 | 通过/告警/失败 + 具体哪条检查、哪一行 | 自愈、交付/播放 |
| 6 | **自愈修复** `repair` | AI | 失败项、上一轮画法、物理分析、读题几何 | 新的 `drawFrame`；物理错误则重跑主链 | 本地校验 |
| 7 | **交付/播放** | 本地程序 | 通过校验的程序 | 动画页、导出网页 | 你 |

> 第 2a 和 2b 是**同时**跑的：一个切讲解步骤，一个算运动公式，都只依赖解题过程。

## 3. 字段词典（看到这些词不用怕）

### 3.1 物理分析表里的字段

物理分析只写一张“运动表”，每个物体一段一条：

| 字段 | 大白话 |
|---|---|
| `element` | 这个物体叫什么（例如 `block_A`） |
| `type` | 它是什么类型（block / ball / board / conductor_rod …） |
| `segment` | 第几段运动（从 1 开始） |
| `t0` / `t1` | 这一段从第几秒到第几秒 |
| `x0` / `y0` | 这一段开始时，质心在哪（米） |
| `vx0` / `vy0` | 这一段开始时的水平/竖直速度（米/秒） |
| `ax` / `ay` | 这一段的水平/竖直加速度（米/秒²） |
| `x` / `y` | 这一段的运动公式，例如 `x0 + vx0*(t - t0) + 0.5*ax*(t - t0)^2` |
| `note` | 这一段是什么物理过程（给人看的） |
| `assumption` | 题面没给数时，模型先声明“我取了哪些示意值” |

> 这些是“物理”，不是“画面”。程序会把它们翻译成 `stateAt` 的每帧位置。

### 3.2 步骤耦合的字段

| 字段 | 大白话 |
|---|---|
| `step` | 第几步 |
| `sub` | 这一步回答第几小问（1/2/3） |
| `t0` / `t1` | 这一步对应动画的起止秒数 |

### 3.3 画图阶段的字段

| 字段 | 大白话 |
|---|---|
| `state.<key>.x / .y` | 这个物体**质心**的物理位置（米）；画图只用它 |
| `state.<key>.type` | 物体类型（block / ball …） |
| `state.<key>.angleDeg` | 运行时按速度方向注入的角度；有些卡会用它转动物块 |
| `stateMap` | “元件 id → state 键”的对照表，告诉 AI 画哪个 key |
| `steps` | 步骤标题 + 时间；目前保留，给“某一步才出现的绳/挡板”用 |
| `diagram` | 从题目图裁出的示意图；裁失败就退整图 |
| `stageNotes` | 按阶段补充信息：读题 / 解题 / 物理分析 / 画图 / 修复各一段；空着 = 该阶段不注入 |
| `description` / `knownConditions` | 旧版全局补充；新界面用 `stageNotes`，旧字段保留兼容 |

### 3.4 界面/日志里会看到的词

| 词 | 大白话 |
|---|---|
| `stage_start` / `stage_done` | 某一阶段开始/结束，界面进度条用 |
| `stage_delta` | 模型正在流式输出的文字 |
| `dryrun_done` | 本地校验结束，带“通过/告警/失败”和每条检查 |
| `run_done` | 整题结束，带最终结论 |
| `stage_error` | 某一步出错，带原因和修复建议 |
| `prompt` | 给 AI 的“阶段说明书” |
| `knowledgecard` / 卡片 | 给 AI 的小抄；元件卡/场景卡命中才发，2 张常驻卡每题都发 |
| `promptHash` / `knowledgecardHash` | 这一版说明书/卡片的“指纹”，用于溯源 |
| `C1–C9` | 本地自动检查清单（见 §5） |

### 3.5 已经退役、旧文档还会出现的词

| 词 | 现状 |
|---|---|
| `10×6` / 布局纸 | **已退役**；现在用物理世界坐标 + 相机自动取景 |
| `cx / cy` | **已删除**；以前是“纸上的格子坐标”，现在只用 `x / y`（米） |
| `anchor` | **已删除**；以前表示“这个点是底面/顶端/中心”，现在不承诺贴面 |
| `t0States` | **已删除**；以前给 t=0 的纸面坐标 |
| `SIM.stage` | **新程序不再生成**；旧程序仍可被播放器兼容 |
| `physical` | 卡片里的物理尺寸，只给物理分析算质心高度；**不进画面**，画多大由 AI 定 |

## 4. 一个具体例子

题目：物块在传送带上，`analysis` 给出：

```
element: block_A
type: block
segment: 1
t0: 0
t1: 2
x0: 1.2
y0: 0.05
vx0: 2.0
vy0: 0
ax: 0
ay: 0
x: x0 + vx0*(t - t0)
y: y0
note: 随传送带匀速
```

程序把它变成：

```js
stateAt(1.0) → { block_A: { x: 3.2, y: 0.05, type: 'block' } }
```

画图 AI 写：

```js
Draw.ground(-2, 8, 0);
Draw.box([state.block_A.x, state.block_A.y], 0.6, 0.4);
```

播放器：

- 相机自动把这个物理世界框到屏幕；
- 每帧调用 `stateAt(t)`，物块在物理 `(3.2, 0.05)`；
- v/a 箭头按 `VIEW.bodies.at` 求导，画在同一个位置；
- 右侧读数从 `readouts` 取。

## 5. C1–C9 是什么

本地自动检查清单。不是“AI 评分”，是程序检查：

| 编号 | 检查什么 |
|---|---|
| C1 | 语法、接线、禁用函数、箭头契约 |
| C2 | 跑得完、不超时 |
| C3 | 不出 NaN / Infinity |
| C4 | 相邻帧不突变 |
| C5 | 步骤时间与总时长一致 |
| C6 | 步骤边界不跳变 |
| C7 | 已退役（答案复现） |
| C8 | 读数键/单位稳定 |
| C9 | 画面不是一张静止图 |

没过 → 自愈：画法错误只重画 `drawFrame`；物理错误重跑主链。

---

## 6. 时间归一化 / v/a 箭头在哪

- **时间归一化**：步骤耦合之后，本地把“每小问 4 秒”映射成显示时间；`drawFrame` 不管时间。
- **v/a 箭头**：本地按 `VIEW.bodies` 的位置求导，自动画；`drawFrame` 不画 v/a。
- **相机**：本地自动取景；`drawFrame` 不写相机/像素。

## 7. 一张图记住

```
题目（文字 + 图片）
  ↓
读题 AI：标题、几何、元件/场景
  ↓
解题 AI：解题过程
  ↓
分步 AI（切步骤） ∥ 物理分析 AI（写 x(t)/y(t)）
  ↓
步骤耦合 AI：步骤 ↔ 时间
  ↓
本地程序：把物理公式变成 stateAt（每帧位置）+ VIEW（播放说明）
  ↓
画图 AI：只写 drawFrame（读 state.x/y，自己定大小/布景）
  ↓
本地校验 C1–C9 → 不过就自愈 → 过了播放/导出
```

**记住三句话：**

1. **物理分析管“怎么动”**；
2. **画图 AI 管“长什么样”**；
3. **本地程序管“检查、对时间、放动画”**。

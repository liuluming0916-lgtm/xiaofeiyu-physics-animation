## 3. 为什么动画会变成这样

### 3.1 题目本身是“两个不同场景”，不是一条连续运动

正确的时间线应该是：

```text
0 – 1.71    第1段：板间类平抛 a→b
1.71 – 2.74 第2段：纯磁场圆周 b→c（第1、2问）
2.74 – 3.00 第3段：回到 b，正交电磁场（第3问，条件变了）
```

用户给的参考 HTML 正是这样：

- `VIEW` 只有 1 个 `particle`，`stateAt` 里有 `phase`；
- phase 1：板间偏转；
- phase 2：`th = 240° → 480°` 的圆周，b→c；
- phase 3：**从 b 重新开始**的正交电磁场运动（注意 `x/y` 回到 b，不是接着 c 走）；
- `drawFrame` **分段画轨迹**，段与段之间不连线；
- 开关画成**闭合**。

### 3.2 这次 q08 的 `stateAt` 把第 3 问的运动塞进了第 1、2 问后面

实际 `VIEW` 只有 2 段：

```js
phases: [{ t0: 0, t1: 1.7320508 }, { t0: 1.7320508, t1: 3.0410477 }]
```

实际 `stateAt` 的第二段：

```js
x = 1.7320508 + 0.5*sin(2τ) + 0.866*(1 - cos(2τ));
y = -0.5 + 0.5*(1 - cos(2τ)) - 0.866*sin(2τ) + 1.1547*τ;
```

这是**第 3 问的“正交电磁场：漂移 + 回旋”解**（含线性漂移项 `1.1547*τ`），不是第 1、2 问的**纯磁场圆周**。

所以画面从 b 点出来后，直接走第 3 问的波浪形轨迹；**b→c 的 240° 圆周完全没有出现**。`drawFrame` 又只有一条 `context.at(tt)` 采样轨迹，把两段连成了一条线。

### 3.3 为什么门禁没拦住

C1–C9 检查的是：

- 语法/白名单；
- 数值有限；
- 同一元件相邻段位置连续；
- 时间边界、关键帧非空；
- 画图命令预算。

它**不检查“第 3 问是否换了场景”**。这条轨迹连续、有限、自洽，所以 pass。  
`couple` 又允许“纯概念步没有时间区间”，于是第 3 步（圆周）被静默丢掉——**门禁管不到“物理场景是否对”**。

## 4. 根因：analysis 的“单一连续时间线”契约

`core/prompts/analysis.mjs` 明确要求：

> 同一元件相邻两段在交界时刻（上一段 `t1 = 下一段 t0`），位置必须相等；速度除非碰撞，否则也必须连续。

这条规则对“一个连续过程”是对的，但 q08 第 3 问是：

> **若**粒子离开 b 点时，在右侧**再加**一个水平向右的匀强电场……

这是一个**条件变更后的另一种情形**，它和 Q1/Q2 不是同一次运动。把它硬塞进同一条连续时间线，只有两种结果：

1. 从 c 继续走（位置不回到 b）→ 物理错；
2. 强行回到 b（位置跳变）→ 违反 analysis 的连续性契约 / C6 瞬移。

模型选了折中：把 Q3 的公式直接接到 b 后面，导致 Q1/Q2 的圆周消失。

## 5. 应该如何修正

### 方案 A（正确，建议 1.2 做）：给 analysis / VIEW 增加“场景分支”

1. **analysis 提示词**：识别“若 / 再加 / 改变条件 / 另一种情况”的小问，单独标成 `scenario`（或 `branch`）；  
   - 分支从分叉点（q08 的 b）重新起算；
   - **分支内**仍要求连续；**分支之间不要求连续**。
2. **analysis 输出**：允许 `scenarios: [{id, from, t0, t1, ...}]` 或 `phase.branch = true`。
3. **generate.mjs**：`stateAt` 支持分支；分支处位置重置到分叉点，时间可用绝对时间 + `branchAt`。
4. **couple**：第 3 步（圆周）必须拿到时间区间；分支小问不能当“纯概念步”丢掉。
5. **scene_code 提示词**：不同 scenario 的轨迹**分段画**，段间不连线；切换处画虚线/幽灵，粒子回到分叉点。
6. **门禁**：C6 对 `branch: true` 的跳变放行；新增“分支场景”检查（至少保证每个改变条件的小问有独立段）。
7. **测试夹具**：用 `湖南-25-14.html` 的三段式程序做正例，钉住“圆周 b→c + Q3 从 b 重新开始”。

工作量：中等，涉及 analysis/生成器/couple/画图提示词/门禁；但它不是“给 q08 单题打补丁”，而是补一类题（条件变更、再加场、换初值）的通用能力。**建议放 1.2**，因为 1.1.19 定位是 debug，不应该塞新机制。

### 方案 B（1.1.19 最小应急）：用“第二个 body”绕开分支

- `particle`：Q1/Q2 连续，板间 → 圆周 b→c；
- `particle_q3`：在分支前一直停在 b，分支后走 Q3 的正交电磁场；
- `drawFrame` 按 `t` 只画当前 scenario 的那一个，轨迹分段；
- 这样每个 body 自身连续，不触发 C6，不需要改 schema。
- 代价：模型要理解“一个 hidden body 只用于另一 scenario”，提示词容易走偏；不是长久方案。

### 方案 C（推荐 1.1.19 采用）：q08 先挂起

- `q08` 保持 `todo`，在 B8 清单里标“需要场景分支支持”；
- 先把 q01 / q07 跑完；q08 放到 1.2 的场景分支能力之后重跑；
- 用户给的 `湖南-25-14.html` 作为 1.2 的**正例夹具**，不直接拿来冻结（它不是本次模型产出，不能冒充 model output）。

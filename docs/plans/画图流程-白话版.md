# 画图流程白话版：谁在算坐标？`cx/cy` 到底是什么？

> 这份只回答 P0-4 / P1-1 背后的那个问题：
> **“布局坐标到底是谁在算？画图 AI 到底负责什么？”**
> 不写代码、不讲行号；看完你应该能判断“要不要把比例交给 AI”。

---

## 0. 一句话

**现在：本地程序算“位置”，画图 AI 算“大小和布景”。**

- 本地程序把题目里的**物理米**（真实长度）折成一张 **10×6 的纸**；
- 纸上每个运动物体的位置叫 `cx/cy`；
- 画图 AI 拿到 `cx/cy`，负责“画多大、怎么摆、地面/带/滑轮放哪”；
- 播放器只负责把这张纸放大到屏幕。

所以 P0-4 的答案是：**`cx/cy` 现在是本地程序算的，不是 AI 算的，也不是播放器算的。**

---

## 1. 一张图看懂

```
题目（文字 + 图片）
   │
   ├─① 读题 AI：图里有什么、谁在左谁在右、用到哪些元件/场景
   │
   ├─② 解题 AI：解题过程
   │
   ├─③ 物理分析 AI：每个物体每一段的运动公式 x(t)、y(t)（单位：米）
   │
   ├─④ 本地程序（不调 AI）：
   │     · 看这些公式“物体最左/最右/最高/最低到哪”
   │     · 算一个比例尺 s：把这段真实范围缩进 10×6 的纸
   │     · 算纸上位置 cx/cy = 纸中心 + (物理位置 - 世界中心) × s
   │
   ├─⑤ 画图 AI：只写 drawFrame
   │     · 位置：读 state.<key>.cx / cy
   │     · 大小：自己定（0.4 宽还是 0.6 宽，由它按画面决定）
   │     · 布景：地面、带、滑轮、斜面放哪，由它按读题几何摆
   │
   ├─⑥ 本地检查 C1–C9：语法、接线、有没有瞬移、时间对不对
   │
   └─⑦ 播放器：把 10×6 的纸放大到屏幕，1 格 = 多少像素由相机算
```

**关键分工：**

| 谁 | 负责什么 | 不负责什么 |
|---|---|---|
| 物理分析 AI | 运动公式（米、秒） | 画多大、放哪 |
| 本地程序 | 把米折成纸上的 `cx/cy`；算比例尺 `s` | 元件画多大；布景怎么摆 |
| 画图 AI | 元件大小、布景、构图、`drawFrame` | 重算运动；改 `cx/cy` 的公式 |
| 播放器 | 纸 → 屏幕像素；播放/暂停/时间轴 | 物理、布局 |

## 2. `cx/cy` 是什么？用一道题算给你看

假设题目是：**传送带从 x=0 到 x=6 m，物块从 x=1.2 m 开始向右走。**

### 2.1 物理分析给出的（单位：米）

```
物块在 x=1.2 m，y=0.05 m（质心离带面 5 cm）
整道题物体活动范围：x 0–6 m，y 0–0.1 m
```

### 2.2 本地程序算的（单位：纸上的格子）

- 纸是 **10 宽 × 6 高**，四周留 6% 边距；
- 可用的纸：宽 8.8 格、高 5.28 格；
- 比例尺 `s = min(8.8 / 6, 5.28 / 0.1) = 1.47 格/米`（取小的，保证不超出纸）；
- 世界中心：x=3 m，y=0.05 m；纸中心：cx=5，cy=3；
- 物块在纸上的位置：

```
cx = 5 + (1.2 - 3) × 1.47 ≈ 2.36
cy = 3 + (0.05 - 0.05) × 1.47 = 3
```

所以画图 AI 收到的是：

```js
state.block_A = {
  x: 1.2, y: 0.05,     // 物理米，只给读数/检查
  cx: 2.36, cy: 3,     // 纸上的位置，画图用这个
  anchor: 'bottom',    // 这个点是“底面中心”
  type: 'block',
}
```

### 2.3 画图 AI 做的事

它看到 `cx=2.36, cy=3, anchor=bottom`，知道：

- 物块底面中心要放在纸上 (2.36, 3)；
- 如果它决定物块画 **0.4 宽 × 0.3 高**，那方块中心要抬到 `cy + 0.15 = 3.15`；
- 传送带顶面要画在 `cy=3` 这条线上，否则物块会悬空；
- 地面、滑轮、绳的位置，它按读题几何自己摆。

**注意：`cx/cy` 不是“物块中心”，是“`anchor` 说的那个点”。**
`anchor=bottom` 时它是底面中心；`anchor=center` 时它才是中心。
这就是为什么物块要“抬半个高度”，而小球要“抬一个半径”。

## 3. 为什么会有“两套坐标”的混乱？

因为**卡片里有两套说明书**：

- 现在的画图指令说：用纸上的 `cx/cy`；
- 两张“常驻卡”却还说：用 `state.x/y`（物理米）、世界坐标、`e0/e1`；
- 12 张元件/场景卡正面写“固定世界坐标”，背面自检写“布局 `cx/cy`”。

画图 AI 每次都会收到常驻卡，所以它**每道题**都同时看到两套说法。
它只能猜：猜“纸”，物块就在纸上；猜“米”，物块就可能跑到纸外。

**这不是“AI 笨”，是“说明书打架”。**

---

## 4. 那“比例交给 AI”是什么意思？

你之前说：

> 比例等影响演示的效果交给大模型；scene_code 除了时间归一化和 v/a 箭头，全部交给大模型。

这句话对应的是**另一种分工**，和现在不一样：

### 方案一：现在这样（本地算位置）

```
物理米 → 本地算 s、cx/cy → AI 只读 cx/cy，自己定大小
```

- 好处：所有物体用同一把尺子，物块一定在纸内，接触/对齐稳定；
- 坏处：AI 不能决定“整体放大一点/缩小一点”，只能决定“单个元件画多大”；
- 适合：先保证“不出错、能看”。

### 方案二：你说的“比例归 AI”

```
物理米 + 活动范围 → AI 自己算“这张纸上 1 米画几格” → AI 自己写纸上坐标
```

- 好处：AI 可以为了“好看”整体放大/缩小/挪位置，自由度最大；
- 坏处：同一道题里两个物体如果用了不同比例，就会对不上；
  纸就那么大，AI 自己算也可能算超；
- 需要改：`state` 不再给 `cx/cy`，卡片不再教 `cx/cy`，改教“怎么自己折纸”；
  本地只保留纸/相机/时间归一/v-a/门禁。

### 方案三：折中（本地给“建议比例”，AI 可微调）

- 本地仍算 `s/cx/cy`，但同时告诉 AI“这张纸 1 米 ≈ 1.47 格”；
- AI 可以在这个基础上微调，但不能改到物体出纸；
- 好处：比方案一自由，比方案二稳；
- 坏处：还是两套说法，容易回到“到底听谁的”。

## 5. 怎么选？用三个问题判断

1. **你更怕“画面呆”还是更怕“画面错”？**
   - 怕错 → 方案一（本地算）；
   - 怕呆 → 方案二（AI 算）。

2. **同一道题里，两个物体的大小/位置必须严格对得上吗？**
   - 必须（滑轮、绳、接触面）→ 方案一；
   - 可以示意 → 方案二。

3. **你愿意为“AI 自己折纸”接受偶尔出纸/比例怪吗？**
   - 不愿意 → 方案一；
   - 愿意，靠修复轮兜 → 方案二。

> 我的建议：**1.1.18 先用方案一把“卡打架”修掉**（让画面先稳），
> 把方案二作为 1.1.19 的 A/B 实验；不要在同一个小版本里既改分工又改卡。

## 6. 一句话回答 P0-4 / P1-1

- **P0-4“布局坐标谁在算？”**：现在本地 `generate.mjs` 算 `s/cx/cy`；AI 只读。
- **P1-1“画图流程是什么？”**：见上面第 1 节；`cx/cy` 是“物理位置按本地比例尺折到 10×6 纸上的坐标”，
  不是米，也不是像素。
- **两张常驻卡 + 12 张卡的问题**：它们在教另一套（`x/y`、世界坐标），与本地算的 `cx/cy` 打架。
  不管最后选方案一还是二，**卡必须先统一**，不能同时教两套。

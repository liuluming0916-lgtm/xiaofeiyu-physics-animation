## 一、规则

| 情况 | 处理 |
|---|---|
| 维护者本人（著作权人） | **不需要签**——他本来就是权利人 |
| 每个外部贡献者 | 在**第一次 PR 合并前**签一次，之后不再重复 |
| 签一次覆盖后续全部贡献 | 除非明确撤回；撤回只对之后的贡献生效 |
| 公司/职务贡献 | 需要**雇主同意**的凭据，单独留档 |

## 三、怎么签

见 [CLA §五](CLA.md)。两种形式都算：

- **A（轻量，推荐）**：PR 描述里勾选 `.github/pull_request_template.md` 的 CLA 那一项；
- **B（重）**：签独立文件，适合公司贡献或有人事变动的情形。

签完之后，在 §二 的表格里补一行：日期、姓名、形式（`PR #12` / `独立文件`）、标识。

## 四、什么时候这张表会变得重要

1. 你**第一次合并外部 PR** 的那一刻；
2. 你第一次**向企业发商业授权**——授权覆盖的代码里如果含别人的贡献而没签 CLA，
   那份授权就是无效的，属于根本性瑕疵；
3. 有人主张某段代码是他写的。

前两条之前，这张表只是备份；之后，它是证据。
